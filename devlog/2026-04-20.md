## 2026-04-20 学習ログ（react-hook-form の handleSubmit と自分で作る関数の違いを整理）

### 今日やったこと

今日は主に、`handleSubmit` という名前が2種類あるように見えて混乱していたところを整理した。

確認した内容は次の2つ。

```js
const handleSubmit = async (data) => {
  const updatedRecord = { ...record, ...data };
  await updateRecord(updatedRecord);
  setIsEditing(false);
  navigate(`/patient/${patient.id}/records`);
};

<form
  onSubmit={handleSubmit(async (data) => {
    await onSubmit(data);
    reset();
    setShowAddForm(false);
  })}
>
```

この2つを比べながら、

- 上は自分で定義した関数なのか
- 下の handleSubmit は react-hook-form のものなのか
- 無名関数と名前つき関数の違いは何か
- 分けて書くべきか、その場で書いてもよいのか

を整理した。

### 1. react-hook-form の handleSubmit と自分の関数は別物

同じ handleSubmit という名前でも、中身は同じではない。

react-hook-form の handleSubmit

これは useForm() から取り出すライブラリの関数。

役割は、

- フォームの入力値を集める
- schema でチェックする
- 問題なければ次の関数を実行する

つまり、
フォーム送信の入口。

自分で書く関数

たとえば次のようなもの。

```js
const handleSubmit = async (data) => {
  const updatedRecord = { ...record, ...data };
  await updateRecord(updatedRecord);
  setIsEditing(false);
  navigate(`/patient/${patient.id}/records`);
};
```

これはライブラリのものではなく、
自分で定義した普通の関数。

役割は、

- 受け取った data を使って更新データを作る
- updateRecord(updatedRecord) を呼ぶ
- 編集モードを終える
- 一覧画面へ戻る

つまり、
送信成功後に何をするかを書く関数。

### 2. 下の <form onSubmit={handleSubmit(...) }> の読み方

次のコードでは、

```jsx
<form
  onSubmit={handleSubmit(async (data) => {
    await onSubmit(data);
    reset();
    setShowAddForm(false);
  })}
>
```

外側の handleSubmit は
react-hook-form の handleSubmit。

一方、中の

```js
async (data) => {
  await onSubmit(data);
  reset();
  setShowAddForm(false);
};
```

は
自分でその場で書いた無名関数。

つまりこの形は、

handleSubmit
→ ライブラリの送信入口
async (data) => { ... }
→ 自分で書いた送信後の処理

という組み合わせ。

### 3. 無名関数と名前つき関数

ここも整理した。

無名関数

```js
async (data) => {
  await onSubmit(data);
  reset();
  setShowAddForm(false);
};
```

これは名前がついていない関数。
でも、自分で書いた関数であることに変わりはない。

名前つき関数

```js
const handleAddPatientSubmit = async (data) => {
  await onSubmit(data);
  reset();
  setShowAddForm(false);
};
```

このあと

```jsx
<form onSubmit={handleSubmit(handleAddPatientSubmit)}>
```

と書けば、

handleSubmit
→ react-hook-form のもの
handleAddPatientSubmit
→ 自分の送信後処理

と見分けやすくなる。

### 4. 分けなくても動くが、分けると読みやすい

無名関数をその場で書いても問題なく動く。

```jsx
<form
  onSubmit={handleSubmit(async (data) => {
    await onSubmit(data);
    reset();
    setShowAddForm(false);
  })}
>
```

ただし、処理が長くなると

- 保存
- reset
- close
- navigate
- error クリア

などが1か所に集まって、読みづらくなる。

そこで、次のように分けると見やすい。

```js
const handleAddPatientSubmit = async (data) => {
  await onSubmit(data);
  reset();
  setShowAddForm(false);
};
```

```jsx
<form onSubmit={handleSubmit(handleAddPatientSubmit)}>
```

つまり、
分けなくても動くが、理解しやすさのために分けることがある。

### 5. handleSubmit という名前を自分で使うと混乱しやすい

今日の学びとしてかなり大きかったのはここ。

react-hook-form にも handleSubmit があり、
自分でも `const handleSubmit = async (data) => { ... }` と書けてしまう。

すると、

- どっちがライブラリのものか
- どっちが自分の関数か

が見えにくくなる。

そのため、自分で作る関数には

- handleRecordSubmit
- handlePatientSubmit
- handleAddPatientSubmit

のように、役割がわかる名前をつける方が整理しやすい と理解した。

### 6. 「先に書いてある」と「先に動く」は別

これも今日の大事な理解だった。

たとえば、

```js
const handleAddPatientSubmit = async (data) => {
  await onSubmit(data);
  reset();
  setShowAddForm(false);
};
```

が useForm() より前に書いてあっても、
その中の reset() はその場ですぐ実行されるわけではない。

関数は、定義しただけでは動かない。
実際に呼ばれた時に初めて中の処理が動く。

つまり、

- 関数は先に定義される
- useForm() で reset などが用意される
- 送信ボタンが押された時に関数が実行される

という順番になる。

なので、
関数の中で reset() を使っていても、送信時にはもう使える状態だから大丈夫
ということを理解した。

### 7. 今日のまとめ

今日は、handleSubmit という名前が出てきた時に、

- これは react-hook-form のものか
- これは自分で作った関数か

を見分ける練習をした。

整理すると次の通り。

- useForm() から取り出す handleSubmit
  → ライブラリの送信入口
- const handleRecordSubmit = async (data) => { ... }
  → 自分で作る送信後の処理
- async (data) => { ... }
  → 自分で書いた無名関数
- 無名関数でも動く
- ただし、名前をつけて分けると読みやすい
- 「先に書いてある」と「先に実行される」は別

つまり、
フォーム送信では「入口」と「送信後の仕事」を分けて考えることが大事
と理解した。
