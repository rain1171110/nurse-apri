## 2026-04-29 学習ログ（Express APIサーバーの全体像とひな型）

### 学んだこと

`server/index.js` は、React から来た通信を受け取り、`data.json` を読んだり保存したりするための API サーバー。

全体の流れは次の通り。

```txt
React
  ↓ fetch
Express
  ↓ readData / writeData
data.json
```

### app.use(cors()) の理解

```js
app.use(cors());
```

React 側（例: `http://localhost:5173`）と Express 側（例: `http://localhost:3001`）はポートが違うため、ブラウザからは別サイト扱いになる。
そのため CORS 許可が必要。

### app.use(express.json()) の理解

```js
app.use(express.json());
```

React から送った JSON を Express 側で `req.body` として読めるようにする設定。

React 側の送信例:

```js
body: JSON.stringify(payload);
```

Express 側の受け取り例:

```js
const { patients, records } = req.body;
```

### GET /api/data の理解

```js
app.get("/api/data", (req, res) => {
  const data = readData();
  res.json(data);
});
```

React から「データをください」と呼ばれたときに `data.json` を読んで返す API。
GET は「読む」通信。

### PUT /api/data の理解

```js
app.put("/api/data", (req, res) => {
  const { patients, records } = req.body;
  const next = { patients, records };
  writeData(next);
  res.json(next);
});
```

React から送られた最新データを `data.json` に保存する API。
PUT は「更新・保存」通信。

### readData / writeData の理解

```js
const readData = () => {
  const raw = readFileSync(dataPath, "utf-8");
  return JSON.parse(raw);
};
```

`readData` は、`data.json` を読み込んで JSON 文字列を JavaScript オブジェクトに戻す。

```js
const writeData = (data) => {
  writeFileSync(dataPath, JSON.stringify(data, null, 2), "utf-8");
};
```

`writeData` は、JavaScript オブジェクトを JSON 文字列に変換して `data.json` に保存する。

- `JSON.parse()` は JSON 文字列 -> JavaScript データ
- `JSON.stringify()` は JavaScript データ -> JSON 文字列

### dataPath の理解

```js
const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);
const dataPath = path.join(__dirname, "data.json");
```

この 3 行は `server/data.json` の場所を正確に作るためのコード。
Node.js に JSON ファイルの場所を教えるために必要。

### エラーハンドリングの理解

```js
try {
  const data = readData();
  res.json(data);
} catch (error) {
  console.error("GET /api/data error:", error);
  res.status(500).json({ error: "Failed to read data" });
}
```

`try...catch` を使うと、`data.json` が壊れていてもサーバー全体が落ちにくくなる。

### データの形チェック

```js
if (!Array.isArray(patients) || !Array.isArray(records)) {
  return res.status(400).json({ error: "invalid payload" });
}
```

保存前に `patients` と `records` が配列か確認する。
変な形のデータを保存すると、React 側の `patients.map()` などが壊れるため。

### 今日の理解

Express サーバーは、React と `data.json` の間にいる「受付係」の役割。

- React は直接 `data.json` を触らない
- Express に「読んで」「保存して」を依頼する

### 今後の考え方

`server/index.js` は最初から全部自力で書けなくてもよい。
実務でも既存コード・ドキュメント・テンプレートを見ながら作ることが多い。

今はこのコードを「ローカル JSON 保存 API のひな型」として使う。

主に変更する場所:

- ポート番号
- JSON ファイル名
- API の URL
- データの形チェック
