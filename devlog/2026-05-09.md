## 今日やったこと

- Expressで作成した患者情報更新API `PUT /api/patients/:id` を復習した
- 1つずつ処理の役割を分解して、どこで「患者を探す」のかと「保存する」のかを整理した
- 特に `req.params.id` と `req.body` の使い分けを重点的に確認した

## 理解したこと

- `:id` はURLから受け取る値で、`req.params.id` で取り出せる
- `some()` は「対象患者が存在するか」の確認に使う。いなければ404を返す
- 更新データ作成時は `req.body` ではなくURLの `id` を優先するのが重要

```js
const updatedPatient = {
  ...req.body,
  id,
};
```

- オブジェクトは後ろの値が優先されるため、`body` に別IDが入っていてもURLの `id` で上書きできる
- `map()` で配列を作り直し、一致した1人だけ差し替える

```js
const next = {
  ...data,
  patients: data.patients.map((patient) =>
    patient.id === id ? updatedPatient : patient,
  ),
};
```

- `writeData(next)` は保存だけを担当する
- `res.json(updatedPatient)` はフロントに結果を返すだけを担当する

## 詰まったこと

- 「`writeData(next)` が患者を探して更新している」と最初は勘違いしていた
- 実際は、患者を探して差し替える処理は `map()` の時点で完了している
