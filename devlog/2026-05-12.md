## 全体の流れ

まず、患者情報の更新は次の順番で動くと整理した。

```text
PatientDetail.jsx
編集フォームで保存する
↓
await updatePatient(updated) を呼ぶ
↓
App.jsx の updatePatient が動く
↓
updatePatientApi(updated.id, updated) を呼ぶ
↓
patientApi.js から PUT /api/patients/:id を送る
↓
server/index.js の app.put("/api/patients/:id") が動く
↓
server/data.json が更新される
↓

↓
App.jsx で savedPatient として受け取る
↓
setAppData で React の state を更新する
↓
画面に反映される
```

## console.log でわかったこと

console.log は、データの通り道に目印を置くようなものだと理解した。

- どこまで処理が進んだかが見える
- 止まっている場所を見つけやすい
- バグの原因を1つずつ切り分けられる

つまり、console.log は「今どこにいるか」を教えてくれる地図みたいなもの。

## つまずいた点

### 1. console.logo のミス

今日出たエラーはこれだった。

```js
TypeError: console.logo is not a function
```

原因は、`console.log(...)` と書くべきところを `console.logo(...)` と書いていたことだった。

- `log` はある
- `logo` という関数はない

そのため、そこで処理が止まっていた。

### 2. some と find の違い

サーバー側でこのコードを確認した。

```js
const exists = data.patients.some((patient) => patient.id === id);
```

これは、「この id の患者が存在するか？」を調べるコード。

- `some()` は true / false を返す
- 存在チェックに向いている

一方で `find()` は、条件に合うデータそのものを返す。

```js
const foundPatient = data.patients.find((patient) => patient.id === id);
```

- `find()` は患者データを返す
- 見つからないと undefined になる

今回の目的は「いるかどうか」の確認なので、`some()` のほうが合っていると理解した。

つまり、`some = 存在チェック`、`find = データ取得`。

## PatientPage の役割

PatientDetail.jsx ではこう呼んでいる。

```js
await updatePatient(updated);
```

でも、PatientDetail が App.jsx に直接行っているわけではない。

流れはこうなっている。

```text
App.jsx
updatePatient を作る
↓
PatientPage に props で渡す
↓
PatientPage が Outlet context に入れる
↓
PatientDetail が useOutletContext で受け取る
↓
PatientDetail で await updatePatient(updated) を呼ぶ
```

つまり、PatientPage は App.jsx と子Route の橋渡し役になっている。

## updated と updatedPatient

今日の説明では `updatedPatient` という名前も出てきたが、実際のコードでは `updated` を使っている。

- `updated` = 編集後の患者データ
- `updatedPatient` = 同じ役割の別名

大事なのは名前よりも、`updatePatient(ここに入れたデータ)` の中身が App.jsx に渡ること。

## 今日の重要ポイント

App.jsx ではこのコードが大事だった。

```js
const savedPatient = await updatePatientApi(updated.id, updated);
```

ここでは2つの情報を渡している。

- `updated.id`
  - どの患者を更新するか
  - URL の `:id` に入る

- `updated`
  - どんな内容に更新するか
  - body でサーバーに送る

つまり、`updated.id` は宛先、`updated` は荷物の中身。

## 今日の理解

`updatePatientApi(updated.id, updated)` は、1つのデータを2つに分けて使っていると考えるとわかりやすい。

- 第1引数の `updated.id` は URL 用
- 第2引数の `updated` は送信するデータ用

だから、`updated` の中にも `id` は入っているけれど、今のコードでは `id` を分けて渡している。
