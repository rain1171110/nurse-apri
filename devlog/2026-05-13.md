# 2026-05-13 学習ログ（患者削除APIと一覧画面の整理）

## 今日やったこと

今日は、患者削除処理を実装した。

主な流れは以下。

削除ボタンを押す
↓
App.jsx の deletePatient(id) が呼ばれる
↓
deletePatientApi(id) が呼ばれる
↓
DELETE /api/patients/:id がサーバーに送られる
↓
server/data.json から患者データを削除する
↓
React の state からも患者データを削除する

---

## 扱ったコード

### 1. patientApi.js に削除APIを追加

```js
export const deletePatientApi = async (id) => {
  const response = await fetch(`${API_BASE}/patients/${id}`, {
    method: "DELETE",
  });

  if (!response.ok) {
    throw new Error(`API error:${response.status}`);
  }

  return response.json();
};
```

削除では患者データ全体は不要で、「どの患者を削除するか」を示す id だけを URL に入れて送る。

DELETE /api/patients/:id

### 2. server/index.js に DELETE ルートを作成

```js
app.delete("/api/patients/:id", (req, res) => {
  try {
    const data = readData();
    const { id } = req.params;

    const exists = data.patients.some(
      (patient) => String(patient.id) === String(id),
    );

    if (!exists) {
      return res.status(404).json({ error: "Patient not found" });
    }

    const next = {
      ...data,
      patients: data.patients.filter(
        (patient) => String(patient.id) !== String(id),
      ),
      records: data.records.filter(
        (record) => String(record.patientId) !== String(id),
      ),
    };

    writeData(next);

    res.json({ id });
  } catch (error) {
    console.error("DELETE /api/patients/:id error:", error);
    res.status(500).json({ error: "Failed to delete patient" });
  }
});
```

ポイントは filter で「削除したい id 以外を残す」こと。

```js
patients: data.patients.filter(
  (patient) => String(patient.id) !== String(id),
),
```

患者削除に合わせて、その患者に紐づく看護記録も同時に削除するようにした。

```js
records: data.records.filter(
  (record) => String(record.patientId) !== String(id),
),
```

### 3. App.jsx で state も更新

```js
const deletePatient = async (id) => {
  console.log("App deletePatient に来た id:", id);

  const deletedPatient = await deletePatientApi(id);

  setAppData((prev) => ({
    ...prev,
    patients: prev.patients.filter(
      (patient) => String(patient.id) !== String(deletedPatient.id),
    ),
    records: prev.records.filter(
      (record) => String(record.patientId) !== String(deletedPatient.id),
    ),
  }));
};
```

サーバー側だけ削除しても、React の state が変わらなければ画面は変わらない。
そのため、以下の両方が必要だった。

- server/data.json の削除
- React state の削除

## 学んだこと

### 1. 404エラーの切り分け

削除ボタンを押すと最初は以下が出た。

DELETE http://localhost:3001/api/patients/... 404 (Not Found)

まず onClick の書き方を確認。

```jsx
<DeleteButton onClick={() => onDelete(patient.id)} />
```

これは「クリックされたときに実行」される。

```jsx
<DeleteButton onClick={onDelete(patient.id)} />
```

こちらは「画面表示時にすぐ実行」されるのでNG。

### 2. 本当の原因

最終的な原因は、Express サーバーが古い状態のまま動いていたこと。

- server/index.js を変更
- でも古いサーバーが動いたまま
- DELETE がうまく動かず404
- サーバー再起動
- 新しいDELETE処理が反映
- 削除成功

学び:

- React 側は保存で反映されやすい
- Express / Node 側は再起動が必要なことがある

### 3. 一覧画面の責務整理

一時的に PatientList で PatientCard を使うと、一覧画面に以下が最初から表示された。

- 患者情報
- バイタルサイン一覧
- 看護記録
- 削除

理由は、PatientCard の中にそれらの UI が最初から含まれているため。

つまり、PatientList が「一覧のための最小表示」ではなく「患者メニューの表示」をしてしまった。

そのため、一覧画面はシンプルなカード表示に戻した。

```jsx
<div className="item-list">
  {patients.map((patient) => (
    <div
      className="card"
      key={patient.id}
      onClick={() => navigate(`/patient/${patient.id}`)}
      style={{ cursor: "pointer" }}
    >
      <div className="card-header">
        <h2 className="card-title" style={{ margin: 0 }}>
          {patient.room}号室 {patient.name}
        </h2>
      </div>
    </div>
  ))}
</div>
```

## 今日のポイント

- DELETE は id だけで削除できる
- 削除では map ではなく filter を使う
- 患者を削除するなら、関連 records も削除する
- Express / Node 側の変更はサーバー再起動が必要な場合がある
- PatientCard を一覧に使うと、中身がすべて表示される
- 一覧画面はシンプルにして、削除は詳細画面側に置くほうが安全

## つまずいた点

- 404 が出たとき、最初は onClick の書き方を疑った
- 実際の原因はサーバー再起動不足だった
- フロントとサーバーで「反映タイミング」が違うことを意識する必要がある

## 次回やること

- なぜ一覧画面がシンプルになったのかを、責務（役割）で説明できるようにする
- PatientList は一覧表示用、PatientCard は患者メニュー用という役割分担を明確にする

## まとめ

DeleteButton から API、サーバー削除、state 更新までの一連の流れをつなげて理解できた。
また、削除処理では「対象 id の指定」「関連データの同時削除」「フロント state 更新」の3点がそろって初めて画面に正しく反映されると分かった。
さらに、一覧画面と詳細画面で役割を分けることで、UIの安全性と見通しが上がることも学べた。
