# 2026-05-14 学習ログ（削除ボタンの役割分担と削除処理の流れ）

## 今日やったこと

今日は、患者削除処理について整理した。

特に、

- PatientList は一覧表示用
- PatientCard は患者メニュー用
- DeleteButton は削除ボタン用
- PatientMenu は削除後の画面遷移を決める場所
- App.jsx は実際にデータ削除を行う場所

という役割の違いを確認した。

---

## 一覧画面がシンプルになった理由

以前は PatientList の中で PatientCard を使っていたため、一覧画面に患者メニューまで表示されていた。

しかし、役割を整理すると、

- PatientList: 患者を選ぶための一覧画面
- PatientCard: 選んだ患者に対して操作するメニュー画面

となる。

そのため、一覧画面では患者名と部屋番号だけを表示し、クリックしたら患者ページへ移動する形にした。

- 一覧画面は「選ぶだけ」
- 操作は「患者ページに入ってから」

という形にしたことで、画面がシンプルになった。

## 削除ボタンの見た目が崩れた原因

削除ボタンだけ形が崩れていた原因は、ボタンの種類が混ざっていたことだった。

```jsx
<button className="btn-secondary">一覧に戻る</button>
```

これは自作 CSS のボタン。

一方で、

```jsx
<Button variant="contained" color="error">
  削除
</Button>
```

これは MUI のボタン。

HTML の button と MUI の Button では、CSS・余白・高さ・フォントが違うため、見た目が揃わなかった。

今回は他のボタンも自作 CSS で作っていたため、削除ボタンも MUI を使わずに、自作の button に統一した。

## 扱ったコード

### 1. DeleteButton.jsx

削除ボタンは DeleteButton コンポーネントに分けた。

```jsx
export default function DeleteButton({ onDelete, patient }) {
  const handleDelete = () => {
    const ok = window.confirm(`${patient.name}さんを削除しますか？`);

    if (!ok) return;

    onDelete();
  };

  return (
    <button type="button" className="btn-danger" onClick={handleDelete}>
      削除
    </button>
  );
}
```

ここでのポイントは、DeleteButton は実際の削除処理までは持たないこと。

DeleteButton の役割は、

- 削除ボタンを表示する
- 確認ダイアログを出す
- OK なら onDelete() を呼ぶ

まで。

### 2. PatientMenu.jsx

削除対象の患者 ID は PatientMenu 側で使う形にした。

```jsx
import { useOutletContext, useNavigate } from "react-router-dom";
import PatientCard from "./PatientCard";

export default function PatientMenu() {
  const navigate = useNavigate();
  const { patient, deletePatient } = useOutletContext();

  if (!patient) return <div>患者が見つかりません</div>;

  const handleDelete = async () => {
    await deletePatient(patient.id);
    navigate("/");
  };

  return (
    <div>
      <PatientCard patient={patient} onDelete={handleDelete} />
    </div>
  );
}
```

この形にしたことで、

- PatientMenu が patient.id を知っている
- DeleteButton は id を知らなくてよい
- DeleteButton は onDelete() を呼ぶだけ

になった。

## 削除後に一覧画面へ戻る理由

削除後に一覧へ戻る理由は、App.jsx の Route ではなく、PatientMenu.jsx にこれがあるから。

```js
navigate("/");
```

削除後の流れはこう。

DeleteButton を押す
↓
confirm が出る
↓
OK を押す
↓
onDelete() が呼ばれる
↓
PatientMenu の handleDelete が動く
↓
deletePatient(patient.id) が実行される
↓
削除成功後に navigate("/") で一覧画面へ戻る

## 削除処理の流れ

今日確認できた削除処理の全体像。

- DeleteButton
  - 確認ダイアログを出す
  - OK なら onDelete() を呼ぶ

- PatientMenu
  - deletePatient(patient.id) を呼ぶ
  - 削除後 navigate("/") で一覧へ戻る

- App.jsx
  - deletePatient(id) が実行される
  - deletePatientApi(id) を呼ぶ
  - サーバーから deletedPatient が返る
  - React の state から患者を消す

- server
  - DELETE /api/patients/:id
  - data.json から患者を削除する
  - { id: 削除した ID } を返す

## 今日の重要ポイント

今回の一番大事な学びは、削除処理を全部 1 か所に書くのではなく、役割ごとに分けること。

- DeleteButton: ボタンとしての処理
- PatientMenu: 削除後にどこへ移動するか
- App.jsx: React の state と API の削除処理
- server: 実際に data.json から削除する処理

この分け方にすると、コードの責任がわかりやすくなる。
