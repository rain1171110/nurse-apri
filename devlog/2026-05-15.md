# 2026-05-15 学習ログ（患者削除と看護記録削除の整理）

## 今日やったこと

今日は、看護記録システムで以下の削除処理を整理した。

- 患者を削除したときに、その患者の records も一緒に削除する
- 看護記録1件だけを削除する deleteRecordApi を作る
- server 側に DELETE /api/records/:id を追加する
- App.jsx に deleteRecord 関数を作る
- PatientPage から Outlet context で deleteRecord を子コンポーネントへ渡す

---

## 1. 患者削除では records も一緒に消す

患者を削除したときに、患者本人だけを削除すると、その患者に紐づく看護記録だけが残ってしまう。

これは、親の患者はいないのに、子の看護記録だけが残っている状態になるので不自然。

そのため、患者削除では以下の2つを同時に削除する。

- patients から patient.id が一致する患者を削除
- records から record.patientId が一致する記録を削除

```js
app.delete("/api/patients/:id", (req, res) => {
  try {
    const data = readData();
    const { id } = req.params;

    console.log("DELETE URLのid:", id);
    console.log(
      "data.json内の患者ID一覧:",
      data.patients.map((patient) => patient.id),
    );

    const exists = data.patients.some(
      (patient) => String(patient.id) === String(id),
    );

    if (!exists) {
      return res.status(404).json({ error: "Patient not found" });
    }

    const next = {
      ...data,
      patients: data.patients.filter(
        (patient) => String(patient.id) !== String(id),
      ),
      records: data.records.filter(
        (record) => String(record.patientId) !== String(id),
      ),
    };

    writeData(next);

    res.json({ id });
  } catch (error) {
    console.error("DELETE /api/patients/:id error:", error);
    res.status(500).json({ error: "Failed to delete patient" });
  }
});
```

## 2. patient.id / record.patientId / record.id の違い

今日一番大事だった理解。

- patient.id
  - 患者本人のID
- record.patientId
  - この記録がどの患者に紐づいているかを示すID
- record.id
  - 看護記録そのもののID

患者削除では、患者本人と、その患者に紐づく全記録を消す。

- 患者削除
  - patient.id で患者本人を削除
  - record.patientId でその患者の記録を全部削除

看護記録削除では、記録1件だけを消す。

- 記録削除
  - record.id で記録1件だけ削除

つまり、

- 患者を削除するとき → record.patientId を見る
- 記録を削除するとき → record.id を見る

ここを理解できた。

## 3. deleteRecordApi を作成

api.js に看護記録削除用の関数を追加した。

最初は /patients/${id} になっていたが、記録削除なので /records/${id} に修正した。

```js
export const deleteRecordApi = async (id) => {
  const response = await fetch(`${API_BASE}/records/${id}`, {
    method: "DELETE",
  });

  if (!response.ok) {
    throw new Error(`API error:${response.status}`);
  }

  return response.json();
};
```

この関数の流れ。

- record.id を受け取る
- DELETE /api/records/:id にリクエストを送る
- server 側で records から1件削除する
- サーバーから返ってきた JSON を返す

## 4. server/index.js に DELETE /api/records/:id を追加

看護記録1件を削除する API を作成した。

最初は record.patientId と比較してしまったが、記録1件を削除する場合は record.id を使う必要があると理解した。

```js
app.delete("/api/records/:id", (req, res) => {
  try {
    const data = readData();
    const { id } = req.params;

    const exists = data.records.some(
      (record) => String(record.id) === String(id),
    );

    if (!exists) {
      return res.status(404).json({ error: "Record not found" });
    }

    const next = {
      ...data,
      records: data.records.filter(
        (record) => String(record.id) !== String(id),
      ),
    };

    writeData(next);

    res.json({ id });
  } catch (error) {
    console.error("DELETE /api/records/:id error:", error);
    res.status(500).json({ error: "Failed to delete record" });
  }
});
```

この処理の流れ。

- DELETE /api/records/:id が呼ばれる
- data.json を読む
- URL の id を取得する
- records の中にその id の記録があるか確認
- なければ 404
- あれば records からその1件だけ削除
- data.json に保存
- フロントへ { id } を返す

## 5. App.jsx に deleteRecord を作成

App.jsx に、React の state からも看護記録を削除する処理を追加した。

```js
const deleteRecord = async (id) => {
  console.log("App deleteRecord に来た id:", id);

  const deletedRecord = await deleteRecordApi(id);

  console.log("サーバーから返ってきた deletedRecord:", deletedRecord);

  setAppData((prev) => ({
    ...prev,
    records: prev.records.filter(
      (record) => String(record.id) !== String(deletedRecord.id),
    ),
  }));

  return deletedRecord;
};
```

この流れ。

- App.jsx の deleteRecord に record.id が来る
- deleteRecordApi(id) を呼ぶ
- DELETE /api/records/:id が実行される
- server が data.json の records から1件削除する
- server が { id } を返す
- App.jsx が deletedRecord.id を使って state からも削除する

ここでも大事なのは、record.id を見ること。

record.patientId を使うと、その患者の記録をまとめて消す方向になってしまう。

## 6. return deletedRecord について

deleteRecord の最後に、

```js
return deletedRecord;
```

を書いた。

これは、呼び出し元で削除結果を使いたい場合に便利。

```js
const result = await deleteRecord(record.id);
console.log(result);
```

のように、削除された記録IDを受け取ることができる。

ただし、呼び出し元で使わない場合は、なくても動く。

## 7. PatientPage から deleteRecord を Outlet context に渡す

PatientPage.jsx で deleteRecord を props として受け取り、Outlet context に渡した。

```jsx
export default function PatientPage({
  patients,
  records,
  updatePatient,
  addRecord,
  updateRecord,
  deleteRecord,
  deletePatient,
}) {
  const { id } = useParams();
  const patient = patients.find((p) => String(p.id) === id);
  const patientRecords =
    records.filter((r) => String(r.patientId) === id) ?? [];

  if (!patient) return <div>患者が見つかりません</div>;

  const usedRoomsForEdit = extractUsedRoomNumbers(patients, patient.id);

  return (
    <Outlet
      context={{
        patient,
        patientRecords,
        updatePatient,
        addRecord,
        updateRecord,
        deleteRecord,
        deletePatient,
        usedRoomsForEdit,
      }}
    />
  );
}
```

これで子コンポーネント側では、

```js
const { deleteRecord } = useOutletContext();
```

として deleteRecord を使えるようになる。

## 8. filter() は見つからないと空配列を返す

最後に確認したこと。

```js
const patientRecords = records.filter((r) => String(r.patientId) === id) ?? [];
```

ここで、患者に記録がない場合どうなるか確認した。

結論。

filter() は一致するものがない場合、undefined ではなく [] を返す。

つまり、記録がない患者でも、[] になるので問題ない。

そのため、以下だけでもOK。

```js
const patientRecords = records.filter((r) => String(r.patientId) === id);
```

ただし、records 自体が undefined の場合は、

```js
records.filter(...)
```

でエラーになる。

今のアプリでは records は最初から配列として管理しているので問題ない。

## 今日つまずいたところ

### 1. patientId と id の使い分け

最初は deleteRecord でも record.patientId を使ってしまった。

しかし、看護記録1件を削除する場合は、record.id を見る必要がある。

整理すると、

- 患者削除 → record.patientId
- 記録削除 → record.id

### 2. DeleteButton / PatientCard / PatientMenu の props の流れ

削除ボタン周りで、以下のエラーが出た。

- Cannot read properties of undefined (reading 'name')
- onDelete is not a function

原因は、patient が渡っていないのに patient.name を読もうとしていたこと。

また、DeleteButton に onDelete が正しく渡っていなかったこと。

最終的に、

- PatientMenu
- PatientCard
- DeleteButton

という流れで onDelete を渡す必要があると理解した。
