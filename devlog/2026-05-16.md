## 1. DeleteButton の props の流れを理解した

最初に、削除ボタンで onDelete is not a function というエラーが出た。

原因は、DeleteButton が onDelete という props を受け取る作りなのに、呼び出し側で別の名前を渡していたことだった。

```jsx
export default function DeleteButton({ onDelete }) {
  const handleDelete = () => {
    const ok = window.confirm("削除しますか？");

    if (!ok) return;

    onDelete();
  };

  return (
    <button type="button" className="btn-danger" onClick={handleDelete}>
      削除
    </button>
  );
}
```

DeleteButton は、自分では何を削除するか知らない。

役割はこれだけ。

- 削除ボタンを押す
- confirm を出す
- OKなら親から受け取った onDelete() を実行する

つまり、実際に患者を削除するのか、看護記録を削除するのかは、親コンポーネント側で決める。

## 2. 患者削除の流れを整理した

患者削除では、PatientMenu.jsx の中で handleDelete を作った。

```js
const handleDelete = async () => {
  await deletePatient(patient.id);
  navigate("/");
};
```

この関数は、削除ボタンを押したときの一連の流れをまとめている。

- deletePatient(patient.id)：患者データを削除する本体処理
- navigate("/")：削除後に患者一覧へ戻る

つまり handleDelete は、削除処理そのものというより、削除ボタンを押したあとにやる流れをまとめた関数。

## 3. props 名を具体的にする重要性を学んだ

最初はこうなっていた。

```jsx
<PatientCard patient={patient} onDelete={handleDelete} />
```

ただし、PatientCard 側で props 名を onDeletePatient に変えた場合、呼び出し側も合わせる必要がある。

修正後：

```jsx
<PatientCard patient={patient} onDeletePatient={handleDelete} />
```

PatientCard.jsx 側ではこう受け取る。

```jsx
export default function PatientCard({ patient, onDeletePatient }) {
  return (
    <DeleteButton
      onDelete={onDeletePatient}
      message="この患者を削除しますか？"
    />
  );
}
```

今回理解したこと。

- 左側の onDelete は DeleteButton に渡す props 名
- 右側の onDeletePatient は PatientCard が受け取った関数

名前が似ていると混乱しやすいので、患者削除なら onDeletePatient、記録削除なら handleDeleteRecord のように、具体的な名前にすると読みやすくなる。

## 4. NursingRecordList.jsx の役割を整理した

NursingRecordList.jsx は、看護記録の一覧表示と追加を担当している。

できていることは以下。

- 看護記録一覧を表示する

この役割分担で進めることにした。

## 5. NursingRecordForm.jsx の役割を整理した

## 7. POST /api/records を追加した

看護記録を新規作成する API を追加した。

```js
app.post("/api/records", (req, res) => {
  try {
    const data = readData();

    const newRecord = {
      ...req.body,
      id: crypto.randomUUID(),
    };

    const next = {
      ...data,
      records: [...data.records, newRecord],
    };

    writeData(next);
    res.status(201).json(newRecord);
  } catch (error) {
    console.error("POST/api/records error", error);
    res.status(500).json({ error: "Failed to create records" });
  }
});
```

ここで学んだこと。

- 新規作成時は、フロントから id を送らない
- サーバー側で crypto.randomUUID() を使って id を作る
- data.json の records に追加する
- 作成された newRecord をフロントへ返す

最初は newPatient という変数名にしていたが、看護記録なので newRecord に修正した。

## 8. PUT /api/records/:id を追加した

看護記録を更新する API を追加した。

```js
app.put("/api/records/:id", (req, res) => {
  try {
    const data = readData();
    const { id } = req.params;

    const exists = data.records.some(
      (record) => String(record.id) === String(id),
    );

    if (!exists) {
      return res.status(404).json({ error: "Record not found" });
    }

    const recordToSave = {
      ...req.body,
      id,
    };

    const next = {
      ...data,
      records: data.records.map((record) =>
        String(record.id) === String(id) ? recordToSave : record,
      ),
    };

    writeData(next);

    res.json(recordToSave);
  } catch (error) {
    console.error("PUT /api/records/:id error:", error);
    res.status(500).json({ error: "Failed to update record" });
  }
});
```

ここで大事なのはこれ。

```js
const recordToSave = {
  ...req.body,
  id,
};
```

フロントから送られてきた req.body の内容を使うが、id は URL の id を優先する。

- PUT /api/records/:id
- URL の id を正として扱う
- req.body の id に上書きされないようにする

これは患者更新のときと同じ考え方。

## 9. DELETE /api/records/:id を確認した

看護記録削除 API も確認した。

```js
app.delete("/api/records/:id", (req, res) => {
  try {
    const data = readData();
    const { id } = req.params;

    const exists = data.records.some(
      (record) => String(record.id) === String(id),
    );

    if (!exists) {
      return res.status(404).json({ error: "Record not found" });
    }

    const next = {
      ...data,
      records: data.records.filter(
        (record) => String(record.id) !== String(id),
      ),
    };

    writeData(next);

    res.json({ id });
  } catch (error) {
    console.error("DELETE /api/records/:id error:", error);
    res.status(500).json({ error: "Failed to delete record" });
  }
});
```

削除の流れ。

- URL から id を受け取る
- records にその id の記録があるか確認する
- なければ 404
- あれば filter でその記録だけ除外する
- data.json に保存する
- 削除した id を返す

## 10. api/patientApi.js に records 用 API 関数を追加した

フロント側の API ファイルに、看護記録用の API 関数を追加した。

```js
export const createRecordApi = async (record) => {
  const response = await fetch(`${API_BASE}/records`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(record),
  });

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  return response.json();
};

export const updateRecordApi = async (id, record) => {
  const response = await fetch(`${API_BASE}/records/${id}`, {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(record),
  });

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  return response.json();
};

export const deleteRecordApi = async (id) => {
  const response = await fetch(`${API_BASE}/records/${id}`, {
    method: "DELETE",
  });

  if (!response.ok) {
    throw new Error(`API error:${response.status}`);
  }

  return response.json();
};
```

ここで理解したこと。

- createRecordApi(record)
  - POST /api/records
  - 新規作成なので id は不要
- updateRecordApi(id, record)
  - PUT /api/records/:id
  - どの記録を更新するか必要なので id が必要
- deleteRecordApi(id)
  - DELETE /api/records/:id
  - どの記録を削除するか必要なので id が必要

最初は createRecordApi(id, record) にしていたが、新規作成時はサーバー側で id を作るため、id は不要だと理解した。

## 今日理解した重要ポイント

1. Create では id を送らない
2. Update / Delete では id が必要
3. handleDelete は「削除ボタンを押した後の流れ」をまとめた関数
4. DeleteButton は削除処理の中身を知らず、onDelete() を呼ぶだけ
5. props 名を揃えないと onDelete is not a function になる

```js
const addRecord = async (record, patientId) => {
  const recordToAdd = {
    ...record,
    patientId,
  };

  const savedRecord = await createRecordApi(recordToAdd);

  setAppData((prev) => ({
    ...prev,
    records: [...prev.records, savedRecord],
  }));
};

const updateRecord = async (record) => {
  const savedRecord = await updateRecordApi(record.id, record);

  setAppData((prev) => ({
    ...prev,
    records: prev.records.map((r) =>
      r.id === savedRecord.id ? savedRecord : r,
    ),
  }));
};

const deleteRecord = async (id) => {
  await deleteRecordApi(id);

  setAppData((prev) => ({
    ...prev,
    records: prev.records.filter((record) => record.id !== id),
  }));
};
```
