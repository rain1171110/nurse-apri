# 2026-05-17 学習ログ（看護記録CRUDを専用APIに接続した）

## 今日やったこと

今日は、看護記録の追加・編集・削除処理を、`onSaveData` による全体保存から、看護記録専用 API を使う形に整理した。

- 追加 → `createRecordApi`
- 編集 → `updateRecordApi`
- 削除 → `deleteRecordApi`

これにより、`App.jsx` の `addRecord` / `updateRecord` / `deleteRecord` が、それぞれ専用 API を呼び出す形になった。

---

## 1. 以前の updateRecord との違い

以前は、看護記録を1件更新するために `onSaveData` で `patients` と `records` 全体を保存していた。

```js
const updateRecord = async (updatedRecord) => {
  const nextRecords = appData.records.map((r) =>
    r.id === updatedRecord.id ? updatedRecord : r,
  );

  await onSaveData({
    patients: appData.patients,
    records: nextRecords,
  });
};
```

記録1件を変更するだけなのに、`patients` と `records` を全部送っていた。

### なぜ専用 API に変えたのか

理由は3つ。

1. データが増えたときに無駄が少ない
2. API の役割が分かりやすい
3. 他のデータを間違って上書きしにくい

記録が何万件もある場合、1件だけ変更したいのに `records` 全部を送るのは無駄が大きい。
また、記録を変更したいだけなのに `patients` も一緒に送ると、古い情報で上書きしてしまう可能性がある。

## 2. addRecord の整理

`addRecord` では、まず `recordToAdd` を作ってから `createRecordApi` を1回だけ呼ぶ。

```js
const addRecord = async (record, patientId) => {
  const recordToAdd = {
    ...record,
    patientId,
    id: crypto.randomUUID(),
  };

  try {
    setApiError("");

    const savedRecord = await createRecordApi(recordToAdd);

    setAppData((prev) => ({
      ...prev,
      records: [...prev.records, savedRecord],
    }));

    return savedRecord;
  } catch (error) {
    console.error("看護記録の追加に失敗しました", error);
    setApiError("看護記録の追加に失敗しました");
  }
};
```

大事なポイント。

- `createRecordApi` は1回だけ呼ぶ（2回呼ぶと同じ記録が2件追加されてしまう）
- `createRecordApi` の返り値は AppData 全体ではなく、追加された看護記録1件
- なので `setAppData(responseAppData)` とは書かず、`records` に1件追加する形にする

## 3. updateRecord の整理

```js
const updateRecord = async (record) => {
  try {
    setApiError("");

    const updatedRecord = await updateRecordApi(record.id, record);

    setAppData((prev) => ({
      ...prev,
      records: prev.records.map((r) =>
        String(r.id) === String(updatedRecord.id) ? updatedRecord : r,
      ),
    }));

    return updatedRecord;
  } catch (error) {
    console.error("看護記録修正に失敗しました", error);
    setApiError("看護記録修正に失敗しました");
  }
};
```

`updateRecordApi(record.id, record)` の意味。

- `record.id` = どの看護記録を更新するか
- `record` = どんな内容に更新するか

その後、`records` の中から同じ `id` の記録だけを `updatedRecord` に差し替える。

```js
records: prev.records.map((r) =>
  String(r.id) === String(updatedRecord.id) ? updatedRecord : r,
),
```

流れはこう。

1. `records` を1件ずつ見る
2. `id` が `updatedRecord.id` と同じなら `updatedRecord` に差し替える
3. 違う記録はそのまま残す

## 4. deleteRecord の整理

```js
const deleteRecord = async (id) => {
  try {
    setApiError("");

    const deletedRecord = await deleteRecordApi(id);

    setAppData((prev) => ({
      ...prev,
      records: prev.records.filter(
        (record) => String(record.id) !== String(deletedRecord.id),
      ),
    }));

    return deletedRecord;
  } catch (error) {
    console.error("看護記録削除に失敗しました", error);
    setApiError("看護記録削除に失敗しました");
  }
};
```

`filter` の意味。

```js
records: prev.records.filter(
  (record) => String(record.id) !== String(deletedRecord.id),
),
```

流れはこう。

1. `records` を1件ずつ見る
2. `deletedRecord.id` と違うものだけ残す
3. 同じ `id` の記録は削除される

注意：この書き方はサーバー側から `deletedRecord.id` が返ってくることが前提。  
サーバーが `{ id: 削除したID }` を返しているなら OK。

## 今日のポイント

### 1. onSaveData と専用 API の違い

| 方法                                                      | 処理の範囲                  |
| --------------------------------------------------------- | --------------------------- |
| `onSaveData`                                              | `data.json` 全体を保存する  |
| `createRecordApi` / `updateRecordApi` / `deleteRecordApi` | 看護記録1件に対して処理する |

以前は、記録1件を変更するために全体保存していた。  
今は、記録1件だけを API で処理する形にした。

### 2. API の返り値の形を意識する

`onSaveData` の返り値は `{ patients: [...], records: [...] }` という全体データ。

しかし `createRecordApi` の返り値は `{ id: "...", patientId: "...", content: "..." }` という記録1件。

なので `setAppData(responseAppData)` や `isValidAppData` は使わない。

### 3. try...catch の中で API は1回だけ呼ぶ

間違えやすい書き方。

```js
// ❌ これはAPIを2回呼んでしまう
await updateRecordApi(record.id, record);

try {
  const savedRecord = await updateRecordApi(savedRecord); // savedRecordはまだない！
}
```

正しくは、`try` の中で1回だけ呼ぶ。

```js
// ✅ これが正しい
try {
  const updatedRecord = await updateRecordApi(record.id, record);
}
```

### 4. 命名の整理

| 名前              | 役割                                                 |
| ----------------- | ---------------------------------------------------- |
| `addRecord`       | App.jsx の中で画面側の「記録追加処理」を担当する関数 |
| `recordToAdd`     | これから追加する記録データ                           |
| `createRecordApi` | サーバーに「新規作成して」と依頼する API 関数        |

`createRecordApi` は CRUD の Create に合わせた名前なので `create` のままでよい。  
App.jsx 側の関数名は `addRecord` のままでよい。

```
↓

App.jsx の setAppData で React state 更新
↓

```

## つまずいた点

- `createRecordApi` を try の外と中で2回呼んでしまいそうになった
  → try の中で1回だけ呼ぶのが正しい
- `savedRecord` を作る前に使ってしまうコードを書いてしまった
  → 変数は使う前に宣言する
- API の返り値が全体データだと思い込んで `setAppData(responseAppData)` と書いてしまいそうになった
  → 専用 API の返り値は1件分のデータなので、`records` に追加・差し替え・除外する形にする

## まとめ

今日は、`onSaveData` による全体保存から、看護記録専用 API（`createRecordApi` / `updateRecordApi` / `deleteRecordApi`）を使う形に切り替えた。  
API の返り値は1件分のデータなので、`setAppData` で `records` だけを更新するのがポイント。  
`try...catch` の中で API を1回だけ呼ぶことと、変数を使う前に宣言することも意識できた。  
つまり、「1件の変更には1件分の API を使い、返ってきた1件で state を更新する」が今日の核心。
