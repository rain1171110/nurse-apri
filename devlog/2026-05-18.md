## 2. 患者追加処理を専用APIに切り替えた

以前は、患者追加時に onSaveData を使って、patients と records をまとめて保存していた。

以前の形:

```js
const addPatientSubmit = async (data) => {
  const patientToAdd = { ...data, id: crypto.randomUUID() };
  const nextPatients = [...patients, patientToAdd];
  await onSaveData({ patients: nextPatients, records });
};
```

今日は、患者追加専用の addPatient を作成し、createPatientApi を呼ぶ形に変更した。

```js
const addPatient = async (patient) => {
  try {
    setApiError("");

    const savedPatient = await createPatientApi(patient);

    setAppData((prev) => ({
      ...prev,
      patients: [...prev.patients, savedPatient],
    }));

    return savedPatient;
  } catch (error) {
    console.error("患者追加に失敗しました", error);
    setApiError("患者追加に失敗しました");
  }
};
```

PatientList 側では、フォーム入力から患者1人分のデータを作り、addPatient に渡す形にした。

```js
const addPatientSubmit = async (data) => {
  const patientToAdd = { ...data, id: crypto.randomUUID() };
  await addPatient(patientToAdd);
};
```

ポイント:

- addPatient({ patientToAdd }) ではなく addPatient(patientToAdd) にする
- 前者は patientToAdd というキーを持つ別オブジェクトになる
- 後者は患者データそのものを渡せる

## 3. createPatientApi のURLを確認した

患者追加用の API 関数を作った。

```js
export const createPatientApi = async (patient) => {
  const response = await fetch(`${API_BASE}/patients`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(patient),
  });

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  return response.json();
};
```

注意点:

- URL は単数形の /patient ではなく複数形の /patients
- 正: POST /api/patients
- 誤: POST /api/patient

## 4. saveAppData を使わない方針にした

以前の saveAppData は、全体データをまとめて保存する関数だった。

```js
export const saveAppData = async (payload) => {
  const response = await fetch(`${API_BASE}/data`, {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  });

  if (!response.ok) {
    throw new Error(`API error:${response.status}`);
  }

  return response.json();
};
```

これは PUT /api/data で patients と records をまとめて保存する処理。

今後の方針:

- 残す: fetchAppData（初回読み込み用）
- 使わない: saveAppData（全体保存方式をやめたため）

## 5. APIをCRUD操作ごとに分割した意味

以前は PUT /api/data で、患者情報と看護記録をまとめて保存していた。

現在は、役割ごとに API を分けた。

### 患者API

| メソッド | URL               | 内容     |
| -------- | ----------------- | -------- |
| POST     | /api/patients     | 患者追加 |
| PUT      | /api/patients/:id | 患者更新 |
| DELETE   | /api/patients/:id | 患者削除 |

### 看護記録API

| メソッド | URL              | 内容         |
| -------- | ---------------- | ------------ |
| POST     | /api/records     | 看護記録追加 |
| PUT      | /api/records/:id | 看護記録更新 |
| DELETE   | /api/records/:id | 看護記録削除 |

つまり、患者と看護記録をそれぞれ CRUD 操作用の API に分けた。

## 6. App.jsx の役割整理

App.jsx では、API 通信と React state 更新を担当する。

全体の流れ:

```txt
画面操作
↓
App.jsx
↓
api/patientApi.js
↓
server/index.js
↓
server/data.json
↓
React state 更新
↓
画面に反映
```

患者追加の流れ:

```txt

↓

↓

↓

↓

↓

↓

↓

```

```txt
↓

↓

↓

↓

```
