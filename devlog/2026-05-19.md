# 2026-05-19 学習ログ：看護記録管理アプリのデプロイ

## 今日やったこと

看護記録管理アプリを、フロントエンドとバックエンドに分けてデプロイした。

- バックエンド：Render
- フロントエンド：Vercel
- API接続：Vercel側の環境変数 `VITE_API_BASE` を使用

最終的に、Vercelで公開したReactアプリから、Render上のExpress APIにアクセスし、患者一覧を表示できるところまで確認できた。

---

## 1. APIファイルの整理

もともと `api.js` にまとめていたAPI通信処理を、役割ごとに分割した。

```txt
src/api/
├─ appDataApi.js
├─ patientApi.js
└─ recordApi.js
```

- appDataApi.js
  - アプリ全体の初期データ取得を担当
  - fetchAppData()
- patientApi.js
  - 患者情報の追加・更新・削除を担当
  - createPatientApi()
  - updatePatientApi()
  - deletePatientApi()
- recordApi.js
  - 看護記録の追加・更新・削除を担当
  - createRecordApi()
  - updateRecordApi()
  - deleteRecordApi()

この分割により、患者APIと看護記録APIの役割がわかりやすくなった。

## 2. RenderでExpress APIをデプロイ

バックエンドのExpress APIをRenderにデプロイした。

Renderでは、APIサーバーとして動かすために Web Service を選択した。

### Renderの設定

- Language: Node
- Branch: main
- Build Command: npm install
- Start Command: npm run api
- Instance Type: Free

package.json では以下のように設定している。

```json
"scripts": {
  "dev": "vite",
  "api": "node server/index.js"
}
```

そのため、Renderの Start Command は `npm run api` でよい。

---

## 3. Render用にPORT設定を修正

最初はサーバーのポートを固定で書いていた。

```js
const PORT = 3001;
```

しかし、RenderではRender側がポート番号を指定するため、以下のように修正した。

```js
const PORT = process.env.PORT || 3001;
```

これにより、

- Render上では process.env.PORT
- ローカルでは 3001

を使えるようになった。

## 7. 環境変数 VITE_API_BASE を設定

Vercel上のReactアプリからRenderのAPIを呼ぶため、VercelのEnvironment Variablesに以下を追加した。

- Name: VITE_API_BASE
- Value: https://RenderのURL/api

ここで大事なのは、最後を /api までにすること。

コード側では以下のように呼んでいる。

```js
fetch(`${API_BASE}/data`);
```

そのため、VITE_API_BASE に /api/data まで入れてしまうと、URLが重複してしまう。

- 正しい例: https://xxxxx.onrender.com/api
- 最終的にアクセスされるURL: https://xxxxx.onrender.com/api/data

---

## 8. 環境変数変更後にRedeploy

Vercelでは環境変数を追加しただけでは、既存のデプロイには反映されない。

そのため、Environment Variablesを設定したあとに、最新のデプロイをRedeployした。

```txt
Deployments
↓
最新デプロイの「...」
↓
Redeploy
↓
Use existing Build Cache はチェックしない
↓
Redeploy
```

Viteでは環境変数がビルド時に埋め込まれるため、環境変数を変更したら再ビルドが必要になることを学んだ。

## 9. 発生したエラー

最初はVercelで画面を開いたときに、以下のような表示が出た。

- APIから読み込みできませんでした

原因として確認したことは以下。

- Render APIが直接開けるか
- Express側にCORS設定があるか
- Vercelの VITE_API_BASE が正しいか
- 環境変数設定後にRedeployしているか

Express側には以下の設定があり、CORSは問題なかった。

```js
import cors from "cors";

app.use(cors());
```

最終的には、Vercel側の環境変数を設定し、Redeployすることで解決した。

## 今日理解したこと

- ReactアプリとExpress APIは、デプロイ先を分ける必要がある
- フロントエンドはVercel、バックエンドはRenderで公開できる
- Renderでは process.env.PORT を使う必要がある
- Vercelでは環境変数 VITE_API_BASE を使ってAPIのURLを切り替える
- Viteの環境変数は VITE\_ から始める必要がある
- 環境変数を変更したらRedeployが必要
- CORS設定がないと、別ドメインのフロントエンドからAPIを呼べない
- デプロイ後は、ローカルとは違ってURLや環境変数の設定が重要になる
- JSON file保存は学習用としては使えるが、本番運用ではDB連携が必要になる
