## 1. ProjectStatus の理解

```ts
enum ProjectStatus {
  Active,
  Finished,
}
```

`ProjectStatus` は、プロジェクトの状態を表すためのもの。

* `Active`：実行中
* `Finished`：完了

今後、active リストと finished リストにプロジェクトを分けるために、各プロジェクトに `status` を持たせる。

---

## 2. Project クラスの理解

```ts
class Project {
  constructor(
    public id: string,
    public title: string,
    public description: string,
    public manday: number,
    public status: ProjectStatus,
  ) {}
}
```

この `Project` クラスは、プロジェクトデータの形を決めている。

つまり、1つのプロジェクトは以下の情報を持つ。

```ts
id: string;
title: string;
description: string;
manday: number;
status: ProjectStatus;
```

以前は `projects: any[]` のようにしていたため、配列の中に何でも入れられる状態だった。

```ts
private projects: any[] = [];
```

これを以下のように変更することで、`projects` には `Project` 型のデータだけを入れると明確にできる。

```ts
private projects: Project[] = [];
```

これにより、TypeScript が型チェックしてくれるようになる。

---

## 3. new Project(...) の理解

```ts
const newProject = new Project(
  Math.random().toString(),
  title,
  description,
  manday,
  ProjectStatus.Active,
);
```

ここで `Project` クラスをインスタンス化している。

つまり、`new Project(...)` によって、以下のようなデータが作られる。

```ts
Project {
  id: "0.123456789",
  title: "入力されたタイトル",
  description: "入力された説明",
  manday: 5,
  status: ProjectStatus.Active
}
```

この `newProject` を `projects` 配列に追加する。

```ts
this.projects.push(newProject);
```

## 4. addProject の引数の型について

```ts
addProject(title: string, description: string, manday: number) {
  const newProject = new Project(
    Math.random().toString(),
    title,
    description,
    manday,
    ProjectStatus.Active,
  );
}
```

`addProject()` の引数にも型を書く理由を確認した。

```ts
addProject(title: string, description: string, manday: number)
```

これは、`addProject` に入ってくる値の型をチェックするため。

一方で、`new Project(...)` の型は、`Project` インスタンスを作るときの型チェック。

整理すると以下のようになる。

```txt
addProject の型
→ 関数に入ってくる値の型チェック

Project constructor の型
→ Project インスタンスを作るときの型チェック
```

役割が違うため、どちらも必要。

## 5. Listener 型の理解

```ts
type Listener = (items: Project[]) => void;
```

`Listener` は、関数の型を表している。

意味は以下の通り。

```txt
Project[] を受け取って、何も返さない関数
```

たとえば、以下のような関数が `Listener` 型になる。

```ts
(projects: Project[]) => {
  this.assignedProjects = projects;
  this.renderProjects();
}
```

この関数は、`Project[]` を受け取って、`assignedProjects` に代入し、画面を更新している。戻り値はないので `void`。

---

## 6. listeners を any[] から Listener[] に変更

変更前は以下のように書いていた。

```ts
private listeners: any[] = [];
```

これは、`listeners` に何でも入れられる状態。

しかし、実際に `listeners` に入れたいのは、`Project[]` を受け取って画面を更新する関数だけ。

そのため、以下のように変更した。

```ts
type Listener = (items: Project[]) => void;

private listeners: Listener[] = [];
```

これにより、`listeners` には `Listener` 型の関数だけを入れると明確にできる。

---

## 7. addListener の型

```ts
addListener(listenerFn: Listener) {
  this.listeners.push(listenerFn);
}
```

`addListener` に渡せるのは `Listener` 型の関数だけ。

そのため、以下はOK。

```ts
projectState.addListener((projects: Project[]) => {
  this.assignedProjects = projects;
  this.renderProjects();
});
```

しかし、以下のようなものは `Listener` 型ではないため、TypeScript が止めてくれる。

```ts
projectState.addListener("hello");
```

```ts
projectState.addListener((num: number) => {
  console.log(num);
});
```

---

## 8. ProjectState と ProjectList の連携

現在の流れは以下の通り。

```txt
ProjectInput
  ↓
submitHandler()
  ↓
projectState.addProject(title, desc, manday)
  ↓
ProjectState の projects に new Project を追加
  ↓
listeners に入っている関数を全部実行
  ↓
ProjectList が projects を受け取る
  ↓
assignedProjects に保存
  ↓
renderProjects() で画面表示
```

コードでは、まず `ProjectInput` から以下が呼ばれる。

```ts
projectState.addProject(title, desc, manday);
```

`ProjectState` 側で本体データに保存する。

```ts
this.projects.push(newProject);
```

そのあと、登録されている listener 関数をすべて実行する。

```ts
for (const listenerFn of this.listeners) {
  listenerFn(this.projects.slice());
}
```

`ProjectList` 側では、以下の関数を listener として登録している。

```ts
projectState.addListener((projects: Project[]) => {
  this.assignedProjects = projects;
  this.renderProjects();
});
```

これにより、`ProjectState` の本体データが変わると、`ProjectList` に通知され、画面が更新される。

---

## 9. this.projects.slice() の理解

```ts
listenerFn(this.projects.slice());
```

`slice()` は配列のコピーを作る。

つまり、`ProjectState` が持っている本体データ `projects` をそのまま渡すのではなく、コピーを渡している。

```txt
this.projects
→ 本体データ

this.projects.slice()
→ コピーされた配列
```

本体データを外部から直接変更されにくくするために、コピーを渡している。

## 10. active / finished の表示分け

現在のコードでは、active リストも finished リストも同じ `projects` を受け取っているため、両方に同じプロジェクトが表示される。

今後は、`status` を使って表示するプロジェクトを分ける。

```ts
projectState.addListener((projects: Project[]) => {
  const relevantProjects = projects.filter((prj) => {
    if (this.type === "active") {
      return prj.status === ProjectStatus.Active;
    }
    return prj.status === ProjectStatus.Finished;
  });

  this.assignedProjects = relevantProjects;
  this.renderProjects();
});
```

これにより、以下のように表示を分けられる。

```txt
active の ProjectList
→ status が Active のものだけ表示

finished の ProjectList
→ status が Finished のものだけ表示
```

## 11. renderProjects の重複表示対策

現在の `renderProjects()` は、表示済みの `<li>` を消さずに追加しているため、プロジェクトを追加するたびに表示が重複する可能性がある。

修正するには、`for` の前に以下を入れる。

```ts
listEl.innerHTML = "";
```

修正版。

```ts
private renderProjects() {
  const listEl = document.getElementById(
    `${this.type}-projects-list`,
  )! as HTMLUListElement;

  listEl.innerHTML = "";

  for (const prjItem of this.assignedProjects) {
    const listItem = document.createElement("li");
    listItem.textContent = prjItem.title;
    listEl.appendChild(listItem);
  }
}
```

これで、毎回リストを空にしてから、最新の `assignedProjects` を表示し直せる。
