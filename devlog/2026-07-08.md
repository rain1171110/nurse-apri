## appDataApi.ts のTypeScript化

`fetchAppData` の戻り値に `Promise<AppData>` を付けた。

```ts
import type { AppData } from "../types";

const API_BASE =
  import.meta.env.VITE_API_BASE ?? "http://localhost:3001/api";

export const fetchAppData = async (): Promise<AppData> => {
  const response = await fetch(`${API_BASE}/data`);

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  const data: AppData = await response.json();
  return data;
};
```

### 理解したこと

```ts
export const fetchAppData = async (): Promise<AppData> => {
```

これは、

「この関数は非同期関数で、最終的に `AppData` 型のデータを返す」

という意味。

`async` 関数は必ず `Promise` を返すため、戻り値の型は `AppData` ではなく `Promise<AppData>` になる。

```ts
const response = await fetch(`${API_BASE}/data`);
```

ここではAPI通信をしている。

```ts
const data: AppData = await response.json();
```

ここで、レスポンスの中からJSONデータ本体を取り出している。

## patientApi.ts のTypeScript化

`patientApi.ts` をTypeScript化した。

```ts
import type { Patient } from "../types";

const API_BASE =
  import.meta.env.VITE_API_BASE ?? "http://localhost:3001/api";

export const createPatientApi = async (
  patient: Omit<Patient, "id">,
): Promise<Patient> => {
  const response = await fetch(`${API_BASE}/patients`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(patient),
  });

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  const data: Patient = await response.json();
  return data;
};

export const updatePatientApi = async (
  id: string,
  patient: Omit<Patient, "id">,
): Promise<Patient> => {
  const response = await fetch(`${API_BASE}/patients/${id}`, {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(patient),
  });

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  const data: Patient = await response.json();
  return data;
};

export const deletePatientApi = async (
  id: string,
): Promise<{ id: string }> => {
  const response = await fetch(`${API_BASE}/patients/${id}`, {
    method: "DELETE",
  });

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  const data: { id: string } = await response.json();
  return data;
};
```

## Omit<Patient, "id"> について

今日一番重要だったのはこれ。

```ts
patient: Omit<Patient, "id">
```

これは、新しく `patient` という型を作っているわけではない。

すでにある `Patient` 型をもとにして、`id` だけを除いた型として使っている。

元の `Patient` 型はこれ。

```ts
export type Patient = {
  id: string;
  name: string;
  room: number;
  age: number;
  disease: string;
  history: string;
  progress: string;
};
```

`Omit<Patient, "id">` は、これと同じ意味になる。

```ts
{
  name: string;
  room: number;
  age: number;
  disease: string;
  history: string;
  progress: string;
}
```

新規作成時は、まだ `id` がない。

そのため、`createPatientApi` に渡す患者データは `id` なしでよい。

しかし、APIから返ってくる患者データにはサーバー側で作成された `id` が付く。

そのため、戻り値は以下になる。

```ts
Promise<Patient>
```

つまり、

```txt
入ってくるデータ：idなし
返ってくるデータ：idあり
```

ということ。

## <> と as の違い

今日、`Omit<Patient, "id">` の `<>` は `as` ではだめなのかを確認した。

結論として、`<>` と `as` は役割が違う。

```ts
Omit<Patient, "id">
```

これは、`Omit` という型の機能に、`Patient` と `"id"` を渡している。

つまり、型を作るための書き方。

一方で、

```ts
const input = document.getElementById("name") as HTMLInputElement;
```

これは、すでにある値を `HTMLInputElement` として扱うための書き方。

整理すると、

```txt
<> → 型に材料を渡す
as → 値をこの型として扱う
```

今回の `Omit<Patient, "id">` は、`Patient` 型を加工しているため、`<>` を使う。

## createPatientApi の流れ

```txt
idなしの患者データを受け取る
↓
POST /patients に送る
↓

↓

↓
そのPatientをreturnする
```

## updatePatientApi の流れ

```txt
idと更新内容を受け取る
↓
PUT /patients/:id に送る
↓
サーバーがその患者データを更新する
↓
更新後のPatientが返ってくる
↓
そのPatientをreturnする
```

---

## deletePatientApi の流れ

```txt
削除したいidを受け取る
↓
DELETE /patients/:id に送る
↓
サーバーがその患者を削除する
↓
{ id: 削除したID } が返ってくる
↓
それをreturnする
```

## 今日の理解まとめ

今日のポイントは以下。

```txt

Promise<Patient>
```
