## 1. `RecordInput` の役割

`RecordInput` は、`recordSchema.safeParse()` に渡す前の入力データ型です。

```ts
type RecordInput = z.input<typeof recordSchema>;
```

`RecordInput` は、次のテストケース型で使われています。

```ts
type ValidRecordValidationCase = {
  id: string;
  label: string;
  input: RecordInput;
  expectValid: true;
};

type InvalidRecordValidationCase = {
  id: string;
  label: string;
  input: RecordInput;
  expectValid: false;
  expectErrorPath: string;
  expectErrorMessage?: string;
};
```

このため、各テストケースの `input` は自動的に `RecordInput` 型になります。

流れは次のとおりです。

```text
RecordInput
↓
RecordValidationCase の input
↓
testCase.input
↓
recordSchema.safeParse(testCase.input)
```

`safeParse()` の行に直接 `RecordInput` と書かれていなくても、`testCase.input` にすでに型が付いています。

---

## 2. `z.input<typeof recordSchema>` の意味

```ts
type RecordInput = z.input<typeof recordSchema>;
```

これは、Zodによる変換前の入力型です。

`optionalNumber()` は、入力として文字列・数値・`undefined` を受け取れます。

```ts
z
  .union([z.string(), z.number()])
  .optional()
```

そのため、バイタルには次のような値を渡せます。

```ts
vitals: {
  T: "36.5",
}
```

```ts
vitals: {
  T: 36.5,
}
```

```ts
vitals: {}
```

フォーム入力では文字列になることが多いため、テストケースでは次のように文字列を使っています。

```ts
T: "36.5"
```

## 3. バリデーション結果の判定

バリデーションテストでは、次の3項目を判定しています。

### 成功・失敗が予定どおりか

```ts
const isExpectedResult =
  result.success === testCase.expectValid;
```

たとえば、失敗を期待していて実際にも失敗した場合は、次の比較になります。

```ts
false === false
```

結果は `true` です。

この `true` は、バリデーション成功という意味ではなく、予定どおりの結果だったという意味です。

---

### エラーが発生した場所が予定どおりか

```ts
const isExpectedErrorPath =
  testCase.expectValid ||
  firstPath === testCase.expectErrorPath;
```

正常ケースではエラー場所を確認する必要がないため、`testCase.expectValid` が `true` なら自動的に `true` になります。

異常ケースでは、実際のエラーパスと期待するエラーパスを比較します。

```ts
firstPath === testCase.expectErrorPath
```

例：

```ts
"vitals.T" === "vitals.T"
```

---

### エラーメッセージが予定どおりか

```ts
const isExpectedErrorMessage =
  testCase.expectValid ||
  testCase.expectErrorMessage === undefined ||
  firstMessage === testCase.expectErrorMessage;
```

正常ケースでは確認をスキップします。

異常ケースでも、`expectErrorMessage` を設定していない場合は確認をスキップします。

メッセージが設定されている場合のみ、実際のメッセージと比較します。

---

## 4. 最終的なテスト結果

3つの判定がすべて `true` の場合だけ、`ok` が `true` になります。

```ts
ok:
  isExpectedResult &&
  isExpectedErrorPath &&
  isExpectedErrorMessage,
```

つまり、次のすべてが正しい必要があります。

```text
成功・失敗が予定どおり
かつ
エラー場所が予定どおり
かつ
エラーメッセージが予定どおり
```

## 5. 最初のエラーを取得する処理

Zodのエラー一覧から、最初のエラーだけを取得しています。

```ts
const firstIssue = result.success
  ? undefined
  : result.error.issues[0];
```

エラーパスを文字列に変換します。

```ts
const firstPath = (firstIssue?.path ?? []).join(".");
```

たとえば、次の配列は、

```ts
["vitals", "T"]
```

次の文字列になります。

```text
vitals.T
```

エラーメッセージも取得します。

```ts
const firstMessage = firstIssue?.message ?? "";
```

正常ケースでは `firstIssue` が `undefined` になるため、エラーパスとエラーメッセージは空文字になります。

## 6. Patient用の実行関数

```ts
export const runPatientValidationCases =
  (): PatientValidationResult[] => {
    return createPatientValidationCases().map((testCase) => {
      const schema = makePatientSchemaPartial(testCase.usedRooms);
      const result = schema.safeParse(testCase.input);

      const firstIssue = result.success
        ? undefined
        : result.error.issues[0];

      const firstPath = (firstIssue?.path ?? []).join(".");
      const firstMessage = firstIssue?.message ?? "";

      const isExpectedResult =
        result.success === testCase.expectValid;

      const isExpectedErrorPath =
        testCase.expectValid ||
        firstPath === testCase.expectErrorPath;

      const isExpectedErrorMessage =
        testCase.expectValid ||
        testCase.expectErrorMessage === undefined ||
        firstMessage === testCase.expectErrorMessage;

      return {
        id: testCase.id,
        label: testCase.label,
        expected: testCase.expectValid
          ? "valid"
          : "invalid",
        actual: result.success
          ? "valid"
          : "invalid",
        ok:
          isExpectedResult &&
          isExpectedErrorPath &&
          isExpectedErrorMessage,
        firstErrorPath: firstPath,
        firstErrorMessage: firstMessage,
      };
    });
  };
```

## 8. バイタル未入力の正常ケース

バイタル項目はすべて任意なので、空のオブジェクトでも成功します。

```ts
{
  id: "record-without-vitals",
  label: "バイタル未入力でも正常",
  input: {
    date: "2026-07-10",
    author: "岡﨑",
    content: "変化なし",
    vitals: {},
  },
  expectValid: true,
},
```

現在のSchemaでは、`vitals` オブジェクト自体は必須です。

```ts
vitals: z.object({
  T: optionalNumber(
    35,
    42,
    "体温は35以上",
    "体温は42以下",
  ),
  P: optionalNumber(
    0,
    200,
    "脈拍は0以上",
    "脈拍は200以下",
  ),
  R: optionalNumber(
    0,
    40,
    "呼吸は0以上",
    "呼吸は40以下",
  ),
  SBP: optionalNumber(
    0,
    250,
    "収縮期は0以上",
    "収縮期は250以下",
  ),
  DBP: optionalNumber(
    0,
    150,
    "拡張期は0以上",
    "拡張期は150以下",
  ),
  SPO2: optionalNumber(
    0,
    100,
    "SPO2は0以上",
    "SPO2は100以下",
  ),
}),
```

そのため、これは有効です。

```ts
vitals: {}
```

しかし、次のように `vitals` 自体を省略すると型エラーになります。

```ts
input: {
  date: "2026-07-10",
  author: "岡﨑",
  content: "変化なし",
}
```

今回発生したエラーは、`vitals: {}` の書き忘れが原因でした。

## 9. ブラウザコンソールから実行する

開発環境のときだけ、実行関数を `window` に登録しています。

```ts
if (
  import.meta.env?.DEV &&
  typeof window !== "undefined"
) {
  const devWindow = window as typeof window & {
    runPatientValidationCases:
      typeof runPatientValidationCases;
    runRecordValidationCases:
      typeof runRecordValidationCases;
  };

  devWindow.runPatientValidationCases =
    runPatientValidationCases;

  devWindow.runRecordValidationCases =
    runRecordValidationCases;
}
```

ブラウザコンソールでは、次のように実行できます。

```ts
runPatientValidationCases();
```

```ts
runRecordValidationCases();
```

表形式で確認する場合は、`console.table()` を使います。

```ts
console.table(runPatientValidationCases());
```

```ts
console.table(runRecordValidationCases());
```

## 今日理解できたこと

* `RecordInput` は `recordSchema` が受け取る入力型
* `RecordInput` はテストケースの `input` プロパティで使われている
* `safeParse()` に渡す時点で、`testCase.input` には型が付いている
* `isExpectedResult` は成功・失敗が予定どおりかを確認する
* `isExpectedErrorPath` はエラー場所が予定どおりかを確認する
* `isExpectedErrorMessage` はエラーメッセージが予定どおりかを確認する
* 正常ケースではエラーパスとメッセージの確認をスキップする
* `vitals` の各項目は省略できる
* 現在のSchemaでは `vitals` オブジェクト自体は必要
* バイタル未入力の場合は `vitals: {}` と書く
* Patient / Record のテスト関数をブラウザから実行できるようになった
