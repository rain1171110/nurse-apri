## 2. `recordSchema.test.ts` の作成

記録用のテストケースを、正常系と異常系に分けて実行するようにした。

```ts
import { createRecordValidationCases, recordSchema } from "./schema";
import { describe, expect, it } from "vitest";

const cases = createRecordValidationCases();

const validCases = cases.filter((c) => c.expectValid);
const invalidCases = cases.filter((c) => !c.expectValid);

describe("Record Schema Validation", () => {
  validCases.forEach((c) => {
    it(`should validate successfully for case: ${c.label}`, () => {
      const result = recordSchema.safeParse(c.input);

      expect(result.success).toBe(true);
    });
  });
});

describe("Record Schema Validation - Invalid Cases", () => {
  invalidCases.forEach((c) => {
    it(`should fail validation for case: ${c.label}`, () => {
      const result = recordSchema.safeParse(c.input);

      expect(result.success).toBe(false);

      if (!result.success) {
        const firstIssue = result.error.issues[0];
        const firstErrorPath = firstIssue?.path.join(".") ?? "";

        expect(firstErrorPath).toBe(c.expectErrorPath);

        if (c.expectErrorMessage) {
          expect(firstIssue?.message).toBe(c.expectErrorMessage);
        }
      }
    });
  });
});
```

### 理解したこと

`recordSchema` はスキーマを作る関数ではなく、すでに作成済みのZodスキーマである。

そのため、次のように関数として呼び出さない。

```ts
const schema = recordSchema();
```

直接 `safeParse()` を使用する。

```ts
const result = recordSchema.safeParse(c.input);
```

検証に失敗した場合は、次のように `success` を使って型を絞り込む。

```ts
if (!result.success) {
  console.log(result.error);
}
```

これにより、TypeScriptが「この中では失敗結果なので `error` が存在する」と判断できる。

## 4. `RecordInput` と `RecordOutput` を定義

Zodの検証前と検証後で型を分けた。

```ts
export type RecordInput = z.input<typeof recordSchema>;
export type RecordOutput = z.output<typeof recordSchema>;
```

### `RecordInput`

フォームへ入力される段階の型。

バイタルには文字列を入力できる。

```ts
const input: RecordInput = {
  date: "2026-07-13",
  author: "岡﨑",
  content: "変化なし",
  vitals: {
    T: "36.5",
    P: "80",
  },
};
```

### `RecordOutput`

Zodの検証と `transform()` が終わった後の型。

文字列だったバイタルが数値へ変換される。

```ts
const output: RecordOutput = {
  date: "2026-07-13",
  author: "岡﨑",
  content: "変化なし",
  vitals: {
    T: 36.5,
    P: 80,
  },
};
```

整理すると次のようになる。

```text
RecordInput
フォーム入力前・入力中
"36.5" のような文字列を含む

RecordOutput
Zodで検証・変換した後
36.5 のような数値になる
```

## 6. `handleSubmit(onSubmit)` の理解

フォームでは次のコードを使用している。

```tsx
<form onSubmit={handleSubmit(onSubmit)}>
```

`handleSubmit` は自分で作った関数ではない。

`useForm()` が返すReact Hook Formの関数である。

```ts
const {
  handleSubmit,
} = useForm();
```

`handleSubmit` はフォーム送信時に、主に次の処理を担当する。

```text
1. ブラウザの通常送信を止める
2. フォームの値を集める
3. Zodでバリデーションする
4. エラーならerrorsへ入れる
5. 成功なら検証済みデータをonSubmitへ渡す
```

仕組みを簡略化すると、次のようなイメージになる。

```ts
const handleSubmit = (successFunction) => {
  return async (event) => {
    event.preventDefault();

    const inputData = フォームの入力値;
    const result = recordSchema.safeParse(inputData);

    if (!result.success) {
      return;
    }

    await successFunction(result.data);
  };
};
```

実際のReact Hook Form内部はもっと複雑だが、基本的な理解はこれでよい。

## 7. `onSubmit` の正体

親コンポーネントでは、次のように関数を渡している。

```tsx
<NursingRecordForm
  initialValues={formData}
  onSubmit={handleAddRecordSubmit}
  showDate
  onErrorsChange={onErrorsChange}
/>
```

そのため、子コンポーネントでは次の関係になる。

```ts
onSubmit === handleAddRecordSubmit
```

つまり、

```ts
handleSubmit(onSubmit)
```

は実質的に次と同じである。

```ts
handleSubmit(handleAddRecordSubmit)
```

検証が成功すると、React Hook Formが次のように関数を実行する。

```ts
handleAddRecordSubmit(result.data);
```

全体の流れは次のとおり。

```text
親でhandleAddRecordSubmitを作る
↓
onSubmitというprops名で子に渡す
↓
子がhandleSubmit(onSubmit)へ渡す
↓
React Hook Formがフォームを検証する
↓
成功したらhandleAddRecordSubmit(data)を実行する
```

## 9. 関数型 `FormatValue`

最初は次のようなオブジェクト型を書いてしまった。

```ts
type FormatValue = {
  value: string;
  unit?: string;
  empty: string;
};
```

これは次のようなオブジェクトの型を表す。

```ts
const data: FormatValue = {
  value: "36.5",
  unit: "℃",
  empty: "--",
};
```

今回作りたかったのは、オブジェクト型ではなく関数型だった。

```ts
type FormatValue = (
  value: string | number | null | undefined,
  unit?: string,
  empty?: string,
) => string;
```

実装は次のとおり。

```ts
export const formatValue: FormatValue = (
  value,
  unit = "",
  empty = "--",
) => (value !== "" && value != null ? `${value}${unit}` : empty);
```

使用例。

```ts
formatValue(36.5, "℃");
// "36.5℃"

formatValue(80, "回");
// "80回"

formatValue("", "%");
// "--"
```

今回理解した重要点は、`type` はオブジェクト型だけでなく、関数型にも名前を付けられるということ。

```ts
type ObjectType = {
  value: string;
};

type FunctionType = (value: string) => string;
```

## 11. `formatBpText`

血圧の上と下が両方入力されている場合だけ表示する仕様にした。

```ts
export const formatBpText = (
  sbp: string | number | null | undefined,
  dbp: string | number | null | undefined,
): string => {
  if (sbp && dbp) {
    return `${sbp}/${dbp}`;
  }

  return "--";
};
```

使用例。

```ts
formatBpText(120, 70);
// "120/70"

formatBpText(120, "");
// "--"

formatBpText(undefined, 70);
// "--"
```

最初は次のように書いていた。

```ts
export const formatBpText = (
  sbp: string | number | null | undefined,
  dbp: string | number | null | undefined,
): string => (sbp && dbp ? `${sbp}/${dbp}` : sbp || dbp || "--");
```

しかし、後半の処理では `number` をそのまま返す可能性がある。

```ts
sbp || dbp || "--"
```

そのため、戻り値を `string` と宣言すると型エラーになった。

```text
Type 'string | number' is not assignable to type 'string'.
```

今回は片方だけの血圧は表示せず、両方そろった場合だけ表示する仕様に変更した。

## 12. `formatDate`

JavaScriptの `Date` と、MUI DatePickerの `Dayjs` の両方を受け取れるようにした。

```ts
export const formatDate = (
  date: string | number | Date | Dayjs | null | undefined,
): string => {
  return date ? dayjs(date).format("YYYY-MM-DD") : "";
};
```

これにより、次の両方に対応できる。

```ts
formatDate(new Date());
```

```tsx
onChange={(newValue) => field.onChange(formatDate(newValue))}
```

## 13. `extractUsedRoomNumbers`

```ts

```

しかし、処理内で `.filter()` や `.map()` を使っているため、実際には患者オブジェクトの配列である。

```ts
export const extractUsedRoomNumbers = (
  patients: Patient[],
  excludePatientId: string | null = null,
): number[] => {
  return patients
    .filter((patient) => patient.id !== excludePatientId)
    .map((patient) => patient.room)
    .filter((room) => Number.isFinite(room));

```



```ts
): number[]
```

使用中の部屋番号の配列を返す。

戻り値の例。


## 今日の理解

- `recordSchema` の正常系・異常系テストを書ける
- `safeParse()` の失敗結果は `if (!result.success)` で絞り込める
- `z.input` は検証前、`z.output` は変換後の型
- `handleSubmit` はフォーム値の収集と検証を担当する
- `handleSubmit(onSubmit)` は検証成功後に `onSubmit(data)` を呼ぶ
- 子の `onSubmit` には親の `handleAddRecordSubmit` が入っている
- `type` ではオブジェクト型だけでなく関数型も定義できる
- 配列に `.filter()` や `.map()` を使う場合、引数は配列型にする
- 表示用関数は戻り値を `string` に統一すると扱いやすい
- `.tsx` はJSXを含むファイル、`.ts` はJSXを含まないファイルに使う
