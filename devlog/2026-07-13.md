## 1. NursingRecordListのprops型

`NursingRecordList` は、親コンポーネントからバリデーションエラーを受け取る関数をpropsとして受け取る。

```tsx
import type { FieldErrors } from "react-hook-form";
import type { RecordInput } from "./schema";

type NursingRecordListProps = {
  onErrorsChange?: (errors: FieldErrors<RecordInput>) => void;
};
```

### 型の意味

```ts
onErrorsChange?: (errors: FieldErrors<RecordInput>) => void;
```

* `onErrorsChange?`

  * `?` が付いているため省略可能
* `errors`

  * `RecordInput` に対応するReact Hook Formのエラー
* `void`

  * 関数は意味のある値を返さない

## 2. NursingRecordForm側の型も統一

`NursingRecordList` と `NursingRecordForm` で、`onErrorsChange` の型を同じにする必要があった。

```tsx
import type { FieldErrors } from "react-hook-form";
import type { RecordInput, RecordOutput } from "./schema";

type NursingRecordFormProps = {
  initialValues: RecordInput;
  onSubmit: (data: RecordOutput) => void | Promise<void>;
  showDate?: boolean;
  onErrorsChange?: (errors: FieldErrors<RecordInput>) => void;
};
```

最初はフォーム側が以下の型になっていた。

```ts
onErrorsChange?: (errors: unknown) => void;
```

しかし、`NursingRecordList` 側では以下の型を使っていた。

```ts
onErrorsChange?: (errors: FieldErrors<RecordInput>) => void;
```

型が一致していなかったため、`TS2322` エラーが発生した。

両方を次の型に統一して解決した。

```ts
(errors: FieldErrors<RecordInput>) => void
```

## 3. createEmptyRecordによる型推論

`createEmptyRecord` の戻り値に `RecordInput` を指定した。

```ts
export const createEmptyRecord = (): RecordInput => ({
  date: "",
  vitals: {
    T: "",
    P: "",
    R: "",
    SBP: "",
    DBP: "",
    SPO2: "",
  },
  content: "",
  author: "",
});
```

そのため、`useState` 側で改めて型を書く必要はない。

```tsx
const [formData, setFormData] = useState(createEmptyRecord());
```

TypeScriptは、`createEmptyRecord()` の戻り値から次のように推論する。

```ts
formData: RecordInput
```

実質的には以下と同じ意味になる。

```tsx
const [formData, setFormData] =
  useState<RecordInput>(createEmptyRecord());
```

今回は型推論を利用して、短い書き方を採用した。

## 4. RecordInputとRecordOutputの違い

フォームの初期値には `RecordInput` を使う。

```tsx
const [formData, setFormData] = useState(createEmptyRecord());
```

フォーム送信後のデータには `RecordOutput` を使う。

```tsx
const handleAddRecordSubmit = async (
  data: RecordOutput,
): Promise<void> => {
  await addRecord(data, patient.id);

  setIsAdding(false);
  setFormData(createEmptyRecord());
};
```

### データの流れ

```text
createEmptyRecord()
        ↓
RecordInput
        ↓
NursingRecordForm
        ↓
Zodで検証・変換
        ↓
RecordOutput
        ↓
handleAddRecordSubmit
        ↓
addRecord
```

`RecordInput` では、バイタル値に文字列を含められる。

```ts
T?: string | number;
```

`RecordOutput` では、Zodによる変換後の値になる。

```ts
T?: number;
```

## 5. useOutletContextの型付け

`useOutletContext()` は、型を指定しないと中身の型が分からない。

そのため、Context用の型を作成した。

```tsx
import type { NursingRecord, Patient } from "./types";
import type { RecordOutput } from "./schema";

type NursingRecordOutletContext = {
  patient: Patient | undefined | null;
  patientRecords: NursingRecord[];
  addRecord: (
    data: RecordOutput,
    patientId: string,
  ) => Promise<void>;
};
```

使用時にジェネリックとして型を渡す。

```tsx
const { patient, patientRecords, addRecord } =
  useOutletContext<NursingRecordOutletContext>();
```

これにより、TypeScriptは以下を理解できる。

```ts
patientRecords: NursingRecord[]
```

```ts
addRecord: (
  data: RecordOutput,
  patientId: string,
) => Promise<void>
```

## 6. patientがnullまたはundefinedの可能性

以下のコードでエラーが発生した。

```tsx
await addRecord(data, patient.id);
```

エラー内容は以下だった。

```text
TS18049: 'patient' is possibly 'null' or 'undefined'.
```

`patient` の型が次のようになっているためである。

```ts
patient: Patient | undefined | null;
```

そのため、`handleAddRecordSubmit` より前に存在確認を行った。

```tsx
if (!patient) {
  return <div>患者が見つかりません</div>;
}
```

修正後は、存在チェックより下で `patient` が `Patient` 型に絞り込まれる。

```tsx
if (!patient) {
  return <div>患者が見つかりません</div>;
}

const handleAddRecordSubmit = async (
  data: RecordOutput,
): Promise<void> => {
  await addRecord(data, patient.id);

  setIsAdding(false);
  setFormData(createEmptyRecord());
};
```

存在チェックより下では、以下を安全に利用できる。

```tsx
patient.id
patient.room
patient.name
```

## 7. NursingRecordListの完成形

```tsx
import { useState } from "react";
import { useNavigate, useOutletContext } from "react-router-dom";
import type { FieldErrors } from "react-hook-form";

import { createEmptyRecord, formatDate } from "./Utils";
import NursingRecordForm from "./NursingRecordForm";

import type { NursingRecord, Patient } from "./types";
import type { RecordInput, RecordOutput } from "./schema";

type NursingRecordListProps = {
  onErrorsChange?: (errors: FieldErrors<RecordInput>) => void;
};

type NursingRecordOutletContext = {
  patient: Patient | undefined | null;
  patientRecords: NursingRecord[];
  addRecord: (
    data: RecordOutput,
    patientId: string,
  ) => Promise<void>;
};

export default function NursingRecordList({
  onErrorsChange,
}: NursingRecordListProps) {
  const navigate = useNavigate();

  const { patient, patientRecords, addRecord } =
    useOutletContext<NursingRecordOutletContext>();

  const [isAdding, setIsAdding] = useState(false);
  const [formData, setFormData] = useState(createEmptyRecord());

  if (!patient) {
    return <div>患者が見つかりません</div>;
  }

  const handleAddRecordSubmit = async (
    data: RecordOutput,
  ): Promise<void> => {
    await addRecord(data, patient.id);

    setIsAdding(false);
    setFormData(createEmptyRecord());
  };

  return (
    <div className="container-md">
      <div className="section-header">
        <h1 className="section-title">
          {patient.room}号室 {patient.name} さん
        </h1>

        {!isAdding && (
          <div className="section-actions">
            <button
              type="button"
              className="btn-primary"
              onClick={() => {
                setFormData({
                  ...createEmptyRecord(),
                  date: formatDate(new Date()),
                });

                setIsAdding(true);
              }}
            >
              記録を追加
            </button>
          </div>
        )}
      </div>

      {!isAdding && (
        <>
          <p className="text-secondary">看護記録一覧</p>

          <div className="item-list">
            {patientRecords.map((record) => (
              <div
                className="card"
                key={record.id}
                onClick={() =>
                  navigate(
                    `/patient/${patient.id}/records/${record.id}`,
                  )
                }
                style={{ cursor: "pointer" }}
              >
                <div className="card-header">
                  <h3
                    className="card-title"
                    style={{ margin: 0 }}
                  >
                    {record.date} {record.author}
                  </h3>
                </div>
              </div>
            ))}
          </div>
        </>
      )}

      {isAdding && (
        <div className="card">
          <div className="card-header">
            <h3 className="card-title">記録を追加</h3>
          </div>

          <NursingRecordForm
            initialValues={formData}
            onSubmit={handleAddRecordSubmit}
            showDate
            onErrorsChange={onErrorsChange}
          />

          <div className="card-footer">
            <button
              type="button"
              className="btn-secondary"
              onClick={() => {
                setIsAdding(false);
                setFormData(createEmptyRecord());
              }}
            >
              キャンセル
            </button>
          </div>
        </div>
      )}

      {!isAdding && (
        <div className="form-actions">
          <button
            type="button"
            className="btn-secondary"
            onClick={() => navigate(`/patient/${patient.id}`)}
          >
            メニューに戻る
          </button>

          <button
            type="button"
            className="btn-secondary"
            onClick={() => navigate("/")}
          >
            患者一覧へ戻る
          </button>
        </div>
      )}
    </div>
  );
}
```

## 8. App.tsxで最初に直す型

`App.tsx` では、型エラーが連鎖しないように、上流のStateから型を付ける。

### appData

修正前：

```tsx
const [appData, setAppData] = useState({
  patients: [],
  records: [],
});
```

修正後：

```tsx
const [appData, setAppData] = useState<AppData>({
  patients: [],
  records: [],
});
```

空配列だけでは、TypeScriptが配列の中身を正しく推論できない可能性がある。

`AppData` を指定することで、以下の型になる。

```ts
patients: Patient[]
records: NursingRecord[]
```

## 9. timerRefの型

修正前：

```tsx
const timerRef = useRef(null);
```

修正後：

```tsx
const timerRef =
  useRef<ReturnType<typeof setTimeout> | null>(null);
```

`timerRef.current` には、最初は `null` が入り、その後 `setTimeout()` の戻り値が入る。

```tsx
timerRef.current = setTimeout(() => {
  setDisplayErrors({});
}, 10000);
```

そのため、`null` とタイマーIDの両方を許可する型にする。

## 10. addRecordの型

フォームから受け取る値は、Zod変換後の `RecordOutput`。

```tsx
const addRecord = async (
  record: RecordOutput,
  patientId: string,
): Promise<void> => {
  const recordToAdd: NursingRecord = {
    ...record,
    patientId,
    id: crypto.randomUUID(),
  };

  try {
    setApiError("");

    const savedRecord = await createRecordApi(recordToAdd);

    setAppData((prev) => ({
      ...prev,
      records: [...prev.records, savedRecord],
    }));
  } catch (error) {
    console.error("看護記録追加に失敗しました", error);
    setApiError("看護記録追加に失敗しました");
  }
};
```

`Promise<void>` を指定する場合、値は返さない。

そのため、以下は削除する。

```ts
return savedRecord;
```

戻り値として保存後の記録を使いたい場合は、戻り値型を変える必要がある。

```ts
Promise<NursingRecord | undefined>
```

今回は呼び出し側で戻り値を使っていないため、`Promise<void>` に統一する。

## 11. addPatientの型

新しい患者を登録する段階では、まだ `id` がない。

そのため、引数には `Omit<Patient, "id">` を使う。

```tsx
const addPatient = async (
  patient: Omit<Patient, "id">,
): Promise<Patient | undefined> => {
  try {
    setApiError("");

    const savedPatient = await createPatientApi(patient);

    setAppData((prev) => ({
      ...prev,
      patients: [...prev.patients, savedPatient],
    }));

    return savedPatient;
  } catch (error) {
    console.error("患者追加に失敗しました", error);
    setApiError("患者追加に失敗しました");

    return undefined;
  }
};
```

### Omitの意味

```ts
Omit<Patient, "id">
```

`Patient` 型から `id` だけを除いた型。

```ts
type Patient = {
  id: string;
  name: string;
  room: number;
  age: number;
  disease: string;
  history: string;
  progress: string;
};
```

新規登録時に受け取るデータは次の形になる。

```ts
{
  name: string;
  room: number;
  age: number;
  disease: string;
  history: string;
  progress: string;
}
```

## 12. updatePatientの型

患者更新時は、どの患者を更新するか判断するために `id` が必要。

そのため、引数には `Patient` を使う。

```tsx
const updatePatient = async (
  patientToUpdate: Patient,
): Promise<Patient | undefined> => {
  try {
    setApiError("");

    const { id, ...patientData } = patientToUpdate;

    const updatedPatient = await updatePatientApi(
      id,
      patientData,
    );

    setAppData((prev) => ({
      ...prev,
      patients: prev.patients.map((patient) =>
        patient.id === updatedPatient.id
          ? updatedPatient
          : patient,
      ),
    }));

    return updatedPatient;
  } catch (error) {
    console.error("患者情報更新に失敗しました", error);
    setApiError("患者情報更新に失敗しました");

    return undefined;
  }
};
```

## 13. idと更新データを分ける理由

`updatePatientApi` は次の型になっている。

```ts
export const updatePatientApi = async (
  id: string,
  patient: Omit<Patient, "id">,
): Promise<Patient> => {
  const response = await fetch(
    `${API_BASE}/patients/${id}`,
    {
      method: "PUT",
      headers: {
        "Content-Type": "application/json",
      },
      body: JSON.stringify(patient),
    },
  );

  const data: Patient = await response.json();

  return data;
};
```

第1引数には `id` が必要。

```ts
id: string
```

第2引数には、`id` を含まない患者データが必要。

```ts
patient: Omit<Patient, "id">
```

そのため、更新前の患者オブジェクトを分割する。

```ts
const { id, ...patientData } = patientToUpdate;
```

例えば、元のデータが以下の場合、

```ts
const patientToUpdate = {
  id: "patient-1",
  name: "田中",
  room: 101,
  age: 70,
  disease: "肺炎",
  history: "",
  progress: "",
};
```

分割後は次のようになる。

```ts
id;
// "patient-1"
```

```ts
patientData;
// {
//   name: "田中",
//   room: 101,
//   age: 70,
//   disease: "肺炎",
//   history: "",
//   progress: ""
// }
```

APIへ渡すときは次の形になる。

```ts
const updatedPatient = await updatePatientApi(
  id,
  patientData,
);
```

### URLとbodyの役割

```text
URLのid
→ どの患者を更新するか

bodyのpatientData
→ 患者情報を何に変更するか
```

実際のリクエストは以下のイメージになる。

```ts
fetch(`/patients/${id}`, {
  method: "PUT",
  body: JSON.stringify(patientData),
});
```

## 今日理解した重要ポイント

### 新規登録

新規登録時は、まだ `id` がない。

```ts
patient: Omit<Patient, "id">
```

### 更新

更新時は、対象を特定するために `id` が必要。

```ts
patientToUpdate: Patient
```

### APIへ渡すとき

`id` はURLへ渡し、残りのデータはリクエストボディへ渡す。

```ts
const { id, ...patientData } = patientToUpdate;

await updatePatientApi(id, patientData);
```
