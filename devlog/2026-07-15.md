# 学習ログ：App.tsx の TypeScript化④

## 今日の学習内容

今日は、`App.tsx` の患者更新処理と患者削除処理について学習した。

特に、次の内容を確認した。

* 更新する患者の `id` と更新データを分ける理由
* URLとリクエストボディの役割の違い
* 関数の引数の型と戻り値の型の違い
* `deletePatient` で発生した `TS2740` エラーの原因
* APIの実際の戻り値に合わせて型を書く必要性

---

## 1. `updatePatient` の処理

現在の患者更新処理は次の形になっている。

```ts
const updatePatient = async (
  patientToUpdate: Patient,
): Promise<Patient | undefined> => {
  try {
    setApiError("");

    const { id, ...patientData } = patientToUpdate;

    const updatedPatient = await updatePatientApi(id, patientData);

    setAppData((prev) => ({
      ...prev,
      patients: prev.patients.map((patient) =>
        String(patient.id) === String(updatedPatient.id)
          ? updatedPatient
          : patient,
      ),
    }));

    return updatedPatient;
  } catch (error) {
    console.error("患者情報更新に失敗しました", error);
    setApiError("患者情報更新に失敗しました");
  }
};
```

---

## 2. `id` と更新データを分ける

次のコードで、患者データから `id` と、それ以外のデータを分けている。

```ts
const { id, ...patientData } = patientToUpdate;
```

たとえば、`patientToUpdate` が次のデータだったとする。

```ts
const patientToUpdate = {
  id: "3",
  name: "山田太郎",
  room: 203,
  age: 70,
  disease: "肺炎",
  history: "高血圧",
  progress: "経過良好",
};
```

分割代入後は次のようになる。

```ts
const id = "3";
```

```ts
const patientData = {
  name: "山田太郎",
  room: 203,
  age: 70,
  disease: "肺炎",
  history: "高血圧",
  progress: "経過良好",
};
```

---

## 3. URLとbodyの役割

患者更新APIでは、`id` と患者データを別々に渡している。

```ts
const updatedPatient = await updatePatientApi(id, patientData);
```

API関数は次のような形になっている。

```ts
export const updatePatientApi = async (
  id: string,
  patient: Omit<Patient, "id">,
): Promise<Patient> => {
  const response = await fetch(`${API_BASE}/patients/${id}`, {
    method: "PUT",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(patient),
  });

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  const data: Patient = await response.json();
  return data;
};
```

### URLの `id`

```ts
`${API_BASE}/patients/${id}`
```

たとえば `id` が `"3"` の場合、送信先は次のようになる。

```txt
/api/patients/3
```

これはサーバーに対して、

```txt
IDが3の患者を更新する
```

と伝えている。

つまり、`id` は次の役割を持つ。

```txt
誰を更新するか
```

### bodyの `patientData`

```ts
body: JSON.stringify(patient)
```

bodyには次のような更新内容が入る。

```json
{
  "name": "山田太郎",
  "room": 203,
  "age": 70,
  "disease": "肺炎",
  "history": "高血圧",
  "progress": "経過良好"
}
```

これはサーバーに対して、

```txt
どのような内容に更新するか
```

を伝えている。

### 今日の重要ポイント

```txt
id
→ 誰を更新するか

patientData
→ 何に更新するか
```

## 4. 患者削除処理

患者削除処理は次の形になっている。

```ts
const deletePatient = async (id: string) => {
  try {
    setApiError("");

    const deletedPatient = await deletePatientApi(id);

    setAppData((prev) => ({
      ...prev,

      patients: prev.patients.filter(
        (patient) => String(patient.id) !== String(deletedPatient.id),
      ),

      records: prev.records.filter(
        (record) => String(record.patientId) !== String(deletedPatient.id),
      ),
    }));

    return deletedPatient;
  } catch (error) {
    console.error("患者削除に失敗しました", error);
    setApiError("患者削除に失敗しました");
  }
};
```

---

## 5. `filter()` で患者を削除する

次の処理では、削除された患者以外を新しい配列に残している。

```ts
patients: prev.patients.filter(
  (patient) => String(patient.id) !== String(deletedPatient.id),
),
```

`filter()` は、条件が `true` のデータだけを残す。

```ts
String(patient.id) !== String(deletedPatient.id)
```

つまり、

```txt
削除した患者とIDが違う患者だけ残す
```

という意味になる。

---

## 6. 患者に紐づく記録も削除する

次の処理では、削除された患者の看護記録を除外している。

```ts
records: prev.records.filter(
  (record) => String(record.patientId) !== String(deletedPatient.id),
),
```

看護記録には、どの患者の記録なのかを示す `patientId` が入っている。

```ts
const record = {
  id: "record-1",
  patientId: "3",
  author: "岡﨑",
  content: "食事摂取良好",
};
```

患者ID `"3"` が削除された場合、`patientId` が `"3"` の記録も配列から除外する。

処理の流れは次のようになる。

```txt
患者を削除する
↓
patientsから患者本人を除外する
↓
recordsからその患者の記録も除外する
```

## 7. 引数の型と戻り値の型

次の関数を確認した。

```ts
const deletePatient = async (
  id: string,
): Promise<Patient | undefined> => {
```

### `id: string`

```ts
id: string
```

これは、関数が受け取る引数の型である。

```txt
deletePatientは文字列型のidを受け取る
```

という意味になる。

### `Promise<Patient | undefined>`

```ts
Promise<Patient | undefined>
```

これは、関数が返す値の型である。

```txt
成功時はPatientを返す
失敗時はundefinedを返す
```

という宣言になる。

### 重要な違い

```txt
id: string
→ 関数に入ってくる値の型

Promise<Patient | undefined>
→ 関数から出ていく値の型
```

## 8. 発生したTypeScriptエラー

次の戻り値型を追加したところ、エラーが発生した。

```ts
const deletePatient = async (
  id: string,
): Promise<Patient | undefined> => {
```

エラー内容は次のとおり。

```txt
TS2740:
Type '{ id: string; }' is missing the following properties from type 'Patient':
name, room, age, disease, and 2 more.
```

エラーが発生した場所は次のコード。

```ts
return deletedPatient;
```

---

## 9. エラーが発生した理由

`deletePatientApi(id)` が返すデータは、完全な `Patient` 型ではなく、次の形だった。

```ts
{
  id: string;
}
```

たとえば次のようなデータになる。

```ts
{
  id: "3";
}
```

しかし、関数の戻り値では次のように宣言していた。

```ts
Promise<Patient | undefined>
```

`Patient` 型には、`id` 以外にもすべてのプロパティが必要になる。

```ts
export type Patient = {
  id: string;
  name: string;
  room: number;
  age: number;
  disease: string;
  history: string;
  progress: string;
};
```

実際に返している値は、

```ts
{
  id: string;
}
```

宣言した戻り値は、

```ts
Patient
```

だった。

そのためTypeScriptは、

```txt
idしかないデータをPatientとして返すことはできない
```

と判断してエラーを出した。

## 10. 実際の戻り値に合わせる場合

削除APIが `{ id: string }` を返す設計なら、戻り値の型も合わせる。

```ts
const deletePatient = async (
  id: string,
): Promise<{ id: string } | undefined> => {
  try {
    setApiError("");

    const deletedPatient = await deletePatientApi(id);

    setAppData((prev) => ({
      ...prev,

      patients: prev.patients.filter(
        (patient) => String(patient.id) !== String(deletedPatient.id),
      ),

      records: prev.records.filter(
        (record) => String(record.patientId) !== String(deletedPatient.id),
      ),
    }));

    return deletedPatient;
  } catch (error) {
    console.error("患者削除に失敗しました", error);
    setApiError("患者削除に失敗しました");
  }
};
```

戻り値の型は次のようになる。

```ts
Promise<{ id: string } | undefined>
```

## 11. 戻り値を使わない場合

削除した患者データを呼び出し元で使用しない場合は、`return deletedPatient` を削除して、戻り値を `void` にする方法もある。

```ts
const deletePatient = async (id: string): Promise<void> => {
  try {
    setApiError("");

    const deletedPatient = await deletePatientApi(id);

    setAppData((prev) => ({
      ...prev,

      patients: prev.patients.filter(
        (patient) => String(patient.id) !== String(deletedPatient.id),
      ),

      records: prev.records.filter(
        (record) => String(record.patientId) !== String(deletedPatient.id),
      ),
    }));
  } catch (error) {
    console.error("患者削除に失敗しました", error);
    setApiError("患者削除に失敗しました");
  }
};
```

この場合の意味は次のとおり。

```txt
非同期処理は行うが、呼び出し元には値を返さない
```

## 今日理解したこと

### 更新処理

```txt
URLのid
→ 誰を更新するか

bodyのpatientData
→ 何に更新するか
```

### 関数の型

```txt
引数の型
→ 関数が受け取る値

戻り値の型
→ 関数が返す値
```

### TypeScriptの戻り値

```txt
戻り値の型は、自分が返したい型ではなく、
実際に関数が返しているデータの型に合わせる
```

### 今回のエラー原因

```txt
実際の戻り値
{ id: string }

宣言した戻り値
Patient

この2つが一致していなかったためTS2740が発生した
```
