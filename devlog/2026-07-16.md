## 1. `appData`とは

`appData`は、アプリで使用する患者データと看護記録データをまとめて保存しているReactのstate。

```tsx
const [appData, setAppData] = useState<AppData>({
  patients: [],
  records: [],
});
```

`AppData`型は、患者配列と看護記録配列を持っている。

```ts
export type AppData = {
  patients: Patient[];
  records: NursingRecord[];
};
```

それぞれの役割は以下の通り。

```tsx
appData.patients;
```

患者データの配列。

```tsx
appData.records;
```

看護記録データの配列。

データの流れは以下。

```text
data.json
↓
APIで読み込む
↓
appDataに保存する
↓
ReactがappDataの変更を検知する
↓
画面を再表示する
```

Reactが直接`data.json`を操作しているわけではない。

- `data.json`：データの保存場所
- API：データを読み込み・追加・更新・削除する窓口
- `appData`：React側で現在使用しているデータ
- React：`appData`をもとに画面を表示する

## 2. 患者削除処理

患者削除処理を以下のように修正した。

```tsx
const deletePatient = async (id: string): Promise<void> => {
  try {
    setApiError("");

    const deletedPatient = await deletePatientApi(id);

    setAppData((prev) => ({
      ...prev,

      patients: prev.patients.filter(
        (patient) => String(patient.id) !== String(deletedPatient.id),
      ),

      records: prev.records.filter(
        (record) => String(record.patientId) !== String(deletedPatient.id),
      ),
    }));
  } catch (error) {
    console.error("患者削除に失敗しました", error);
    setApiError("患者削除に失敗しました");
  }
};
```

### 処理の流れ

```text
deletePatient(id)
↓
deletePatientApi(id)でサーバー側の患者を削除
↓
削除された患者データをdeletedPatientで受け取る
↓
deletedPatient.idを使ってappData.patientsから患者を除外
↓
同じpatientIdを持つ看護記録もappData.recordsから除外
↓
Reactが画面を更新する
```

### `Promise<void>`の意味

```tsx
const deletePatient = async (
  id: string,
): Promise<void> => {
```

`Promise<void>`は、非同期処理は行うが、呼び出し元には値を返さないという意味。

関数内では以下の値を使用している。

```tsx
const deletedPatient = await deletePatientApi(id);
```

ただし、最後に以下を書いていない。

```tsx
return deletedPatient;
```

そのため、呼び出し元には削除した患者データを返していない。

```tsx
await deletePatient(id);
```

削除処理の完了を待つだけの呼び出し方になる。

## 3. 値を返す場合と返さない場合

### 値を返さない場合

```tsx
const deletePatient = async (id: string): Promise<void> => {
  await deletePatientApi(id);
};
```

呼び出し元では、処理が終わるのを待つだけ。

```tsx
await deletePatient(id);
```

### 値を返す場合

```tsx
const deletePatient = async (id: string): Promise<Patient | undefined> => {
  try {
    const deletedPatient = await deletePatientApi(id);

    return deletedPatient;
  } catch (error) {
    console.error(error);
  }
};
```

呼び出し元で、削除した患者データを受け取れる。

```tsx
const deletedPatient = await deletePatient(id);

console.log(deletedPatient?.name);
```

削除したデータを返すと、以下のような処理に利用できる。

```tsx
alert(`${deletedPatient.name}さんを削除しました`);
```

また、一時的な復元機能などにも利用できる。

ただし、本格的な復元機能では、完全削除ではなく`deletedAt`などを使用する論理削除が必要になる。

## 4. 看護記録追加処理

看護記録追加処理を以下の形に修正した。

```tsx
const addRecord = async (
  record: RecordOutput,
  patientId: string,
): Promise<void> => {
  const recordToAdd: Omit<NursingRecord, "id"> = {
    ...record,
    patientId,
  };

  try {
    setApiError("");

    const savedRecord = await createRecordApi(recordToAdd);

    setAppData((prev) => ({
      ...prev,
      records: [...prev.records, savedRecord],
    }));
  } catch (error) {
    console.error("看護記録追加に失敗しました", error);
    setApiError("看護記録追加に失敗しました");
  }
};
```

### `record`の内容

`record`には、フォームから送られてきた記録内容が入っている。

```ts
record: RecordOutput;
```

例：

```ts
{
  date: "2026-07-16",
  author: "岡﨑",
  content: "食事摂取良好",
  vitals: {
    T: 36.5,
    P: 80,
    R: 18,
    SBP: 120,
    DBP: 70,
    SPO2: 98
  }
}
```

この時点では、どの患者の記録なのかを示す`patientId`がない。

そこで、以下の処理で`patientId`を追加する。

```tsx
const recordToAdd: Omit<NursingRecord, "id"> = {
  ...record,
  patientId,
};
```

### `Omit<NursingRecord, "id">`

```ts
Omit<NursingRecord, "id">;
```

これは、`NursingRecord`型から`id`だけを除いた型。

看護記録の`id`はAPI側で作成されるため、追加前のデータには含めない。

### 保存後の処理

```tsx
const savedRecord = await createRecordApi(recordToAdd);
```

APIから、`id`付きの保存済み記録を受け取る。

その後、Reactのstateへ追加する。

```tsx
setAppData((prev) => ({
  ...prev,
  records: [...prev.records, savedRecord],
}));
```

これは、以前の記録一覧を残しつつ、最後に新しい記録を追加している。

## 5. 看護記録更新処理

```tsx
const updateRecord = async (
  recordToUpdate: NursingRecord,
): Promise<NursingRecord | undefined> => {
  try {
    setApiError("");

    const { id, ...recordData } = recordToUpdate;

    const updatedRecord = await updateRecordApi(id, recordData);

    setAppData((prev) => ({
      ...prev,

      records: prev.records.map((record) =>
        String(record.id) === String(updatedRecord.id) ? updatedRecord : record,
      ),
    }));

    return updatedRecord;
  } catch (error) {
    console.error("看護記録修正に失敗しました", error);
    setApiError("看護記録修正に失敗しました");
  }
};
```

### `id`と更新内容を分ける

```tsx
const { id, ...recordData } = recordToUpdate;
```

この処理で、看護記録の`id`と、それ以外の更新内容を分けている。

```ts
id;
```

どの看護記録を更新するかを示す。

```ts
recordData;
```

どのような内容に更新するかを示す。

APIには以下のように渡す。

```tsx
const updatedRecord = await updateRecordApi(id, recordData);
```

役割分担は以下。

```text
id
→ 誰を更新するか

recordData
→ 何に更新するか
```

## 6. `map()`による記録の置き換え

```tsx
records: prev.records.map((record) =>
  String(record.id) === String(updatedRecord.id)
    ? updatedRecord
    : record,
),
```

現在の看護記録を1件ずつ確認している。

```text
IDが一致する記録
→ updatedRecordに置き換える

IDが一致しない記録
→ 元のrecordをそのまま残す
```

例：

```ts
[
  {
    id: "1",
    content: "変更前",
  },
  {
    id: "2",
    content: "別の記録",
  },
];
```

APIから以下の記録が返ってきた場合、

```ts
{
  id: "1",
  content: "変更後",
}
```

更新後は以下になる。

```ts
[
  {
    id: "1",
    content: "変更後",
  },
  {
    id: "2",
    content: "別の記録",
  },
];
```

## 7. `handleRecordSubmit`と`updateRecord`の関係

`NursingRecordItem`には以下の処理がある。

```tsx
const handleRecordSubmit = async (formValues) => {

    ...record,
    ...formValues,
  };

  await updateRecord(recordToUpdate);

  setIsEditing(false);
```

この処理の中で、`App.tsx`の`updateRecord`関数を呼び出している。

```tsx
await updateRecord(recordToUpdate);
```

処理の流れは以下。

```text

↓

↓

↓

↓
APIで記録を更新する
↓

↓
編集状態を終了する
↓
記録一覧へ移動する
```

## 8. 同じ名前でも別の変数

以下の2つの`recordToUpdate`は別の変数。

### 呼び出し側

```tsx
const handleRecordSubmit = async (formValues) => {
  const recordToUpdate = {
    ...record,
    ...formValues,
  };

  await updateRecord(recordToUpdate);
};
```

これは、`handleRecordSubmit`内で作った変数。

### 受け取り側

```tsx
const updateRecord = async (
  recordToUpdate: NursingRecord,
): Promise<NursingRecord | undefined> => {
```

これは、`updateRecord`関数が受け取る引数。

別の変数だが、呼び出し側で作ったデータが、受け取り側の引数へ渡される。

```text
handleRecordSubmit側のrecordToUpdate
↓
updateRecord(recordToUpdate)で渡す
↓
updateRecord側の引数recordToUpdateに入る
```

単純な例では以下と同じ。

```ts
const message = "こんにちは";

showMessage(message);

function showMessage(text: string) {
  console.log(text);
}
```

`message`と`text`は別の変数だが、`message`の中身が`text`へ渡される。

## 9. APIから返った値が呼び出し元へ戻る流れ

`updateRecordApi`では、APIへPUTリクエストを送信している。

```ts
export const updateRecordApi = async (
  id: string,
  record: Omit<NursingRecord, "id">,
): Promise<NursingRecord> => {
  const response = await fetch(`${API_BASE}/records/${id}`, {
    method: "PUT",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(record),
  });

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  const data: NursingRecord = await response.json();

  return data;
};
```

ここで返しているのは、`fetch`処理そのものではない。

```ts
const data: NursingRecord = await response.json();

return data;
```

APIが返したJSONを`NursingRecord`データとして返している。

その値を、`App.tsx`側で受け取る。

```tsx
const updatedRecord = await updateRecordApi(id, recordData);
```

さらに、以下で呼び出し元へ返している。

```tsx
return updatedRecord;
```

値の流れは以下。

```text
APIが更新後のJSONを返す
↓
updateRecordApiがresponse.json()で受け取る
↓
updateRecordApiがreturn dataする
↓
App.tsxのupdateRecordがupdatedRecordで受け取る
↓
App.tsxのupdateRecordがreturn updatedRecordする
↓
NursingRecordItem側で受け取れる
```

コードでは以下の流れになる。

```ts
const data = await response.json();

return data;
```

↓

```tsx
const updatedRecord = await updateRecordApi(id, recordData);

return updatedRecord;
```

↓

```tsx
const result = await updateRecord(recordToUpdate);
```

最終的に、`result`にはAPIから返ってきた更新済みの看護記録が入る。

## 10. 現在は戻り値を受け取っていない

現在の`handleRecordSubmit`は以下。

```tsx
await updateRecord(recordToUpdate);
```

これは、更新処理が終わるのを待っているだけ。

`updateRecord`から返された`updatedRecord`を変数に保存していない。

戻り値を使用する場合は、以下のように書く。

```tsx
const updatedRecord = await updateRecord(recordToUpdate);
```

この場合、`App.tsx`の以下の値を受け取れる。

```tsx
return updatedRecord;
```

更新成功・失敗を判定する場合は以下のように使える。

```tsx
const handleRecordSubmit = async (formValues: RecordOutput): Promise<void> => {
  const recordToUpdate: NursingRecord = {
    ...record,
    ...formValues,
  };

  const updatedRecord = await updateRecord(recordToUpdate);

  if (!updatedRecord) {
    return;
  }

  setIsEditing(false);
  navigate(`/patient/${patient.id}/records`);
};
```

更新に成功した場合、

```text
updatedRecordに看護記録が入る
↓
編集を終了する
↓
一覧画面へ移動する
```

更新に失敗した場合、

```text
updatedRecordがundefinedになる
↓
if文で処理を終了する
↓
編集画面に残る
```

## 今日の重要ポイント

### `await`と`return`は役割が違う

```tsx
await updateRecord(recordToUpdate);
```

`await`は、非同期処理が終わるのを待つ。

```tsx
return updatedRecord;
```

`return`は、呼び出し元へ値を返す。

### 値は返すだけでは使われない

```tsx
return updatedRecord;
```

と書いても、呼び出し元で受け取らなければ、その値は使われない。

```tsx
const result = await updateRecord(recordToUpdate);
```

このように変数で受け取って初めて、返された値を利用できる。

### 同じ変数名でも別の変数

関数の外側で作った変数と、関数の引数は別の変数。

ただし、関数を呼び出すことでデータが渡される。

```text
渡す側の変数
↓
関数を呼び出す
↓
受け取る側の引数
```
