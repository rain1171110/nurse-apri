## 1. `updateRecord` の戻り値

`App.tsx` の `updateRecord` は、更新成功時にAPIから返ってきた看護記録を返す。

```ts
const updateRecord = async (
  recordToUpdate: NursingRecord,
): Promise<NursingRecord | undefined> => {
  try {
    setApiError("");

    const { id, ...recordData } = recordToUpdate;

    const updatedRecord = await updateRecordApi(id, recordData);

    setAppData((prev) => ({
      ...prev,
      records: prev.records.map((record) =>
        String(record.id) === String(updatedRecord.id)
          ? updatedRecord
          : record,
      ),
    }));

    return updatedRecord;
  } catch (error) {
    console.error("看護記録修正に失敗しました", error);
    setApiError("看護記録修正に失敗しました");

    return undefined;
  }
};
```

成功時は次の値を返す。

```ts
return updatedRecord;
```

失敗時は更新後のデータが存在しないため、次を返す。

```ts
return undefined;
```

戻り値の型は以下になる。

```ts
Promise<NursingRecord | undefined>
```

つまり、

```text
成功時：NursingRecord
失敗時：undefined
```

という設計になっている。

## 2. `NursingRecordItem` で更新結果を受け取る

`App.tsx` の `updateRecord` が返した値は、呼び出し側で受け取ることができる。

```ts
const updatedRecord = await updateRecord(recordToUpdate);
```

更新に失敗した場合は `undefined` が返るため、次のように処理を止める。

```ts
if (!updatedRecord) {
  return;
}
```

成功時のみ、編集モードを終了して一覧画面へ戻る。

```ts
console.log("更新成功", updatedRecord);

setIsEditing(false);
navigate(`/patient/${patient.id}/records`);
```

以下の書き方は、変数名と関数名が同じになるため使用しない。

```ts
const updateRecord = await updateRecord(recordToUpdate);
```

更新結果を受け取る変数は、`updatedRecord` にする。

```ts
const updatedRecord = await updateRecord(recordToUpdate);
```

## 3. `deleteRecord` の成功・失敗を返す

削除後に画面遷移するかどうかを判断するため、`deleteRecord` の戻り値を `boolean` に変更した。

```ts
const deleteRecord = async (id: string): Promise<boolean> => {
  try {
    setApiError("");

    const deletedRecord = await deleteRecordApi(id);

    setAppData((prev) => ({
      ...prev,
      records: prev.records.filter(
        (record) => String(record.id) !== String(deletedRecord.id),
      ),
    }));

    return true;
  } catch (error) {
    console.error("看護記録削除に失敗しました", error);
    setApiError("看護記録削除に失敗しました");

    return false;
  }
};
```

戻り値は以下の意味になる。

```text
削除成功：true
削除失敗：false
```

呼び出し側では、削除成功時だけ画面遷移する。

```ts
const handleDelete = async (): Promise<void> => {
  const isDeleted = await deleteRecord(record.id);

  if (!isDeleted) {
    return;
  }

  navigate(`/patient/${patient.id}/records`);
};
```

## 4. `PatientList` の TypeScript 化

`PatientList` の props 型を作成した。

```ts
type PatientListProps = {
  patients: Patient[];
  isLoading: boolean;
  apiError: string;
  onErrorsChange: React.Dispatch<React.SetStateAction<{}>>;
  addPatient: (
    patient: Omit<Patient, "id">,
  ) => Promise<Patient | undefined>;
};
```

### `onErrorsChange`

```ts
onErrorsChange: React.Dispatch<React.SetStateAction<{}>>;
```

これは、`useState` が返す更新関数の型。

`App.tsx` では次の `setGlobalErrors` を渡している。

```ts
const [globalErrors, setGlobalErrors] = useState({});
```

```tsx
<PatientList onErrorsChange={setGlobalErrors} />
```

つまり、`PatientList` の `onErrorsChange` の正体は `setGlobalErrors`。

---

### `addPatient`

```ts
addPatient: (
  patient: Omit<Patient, "id">,
) => Promise<Patient | undefined>;
```

これは、親コンポーネントで定義した `addPatient` と同じ関数型。

```ts
const addPatient = async (
  patient: Omit<Patient, "id">,
): Promise<Patient | undefined> => {
```

`Omit<Patient, "id">` は、`Patient` 型から `id` を除いた型。

患者追加前はまだ `id` がないため、`id` なしの患者データをAPIへ送る。

成功すると、APIから `id` 付きの `Patient` が返る。

失敗すると、`undefined` が返る。

## 5. `addPatientSubmit` の型

フォームから受け取る患者データは文字列ではなく、患者情報のオブジェクト。

そのため、以下のように型を付けた。

```ts
const addPatientSubmit = async (
  data: Omit<Patient, "id">,
): Promise<void> => {
  const savedPatient = await addPatient(data);

  if (!savedPatient) {
    return;
  }

  setShowAddForm(false);
};
```

追加に失敗した場合はフォームを閉じず、成功時だけフォームを閉じる。

## 7. `NursingRecordItem` の TypeScript 化

`NursingRecordItem` の props 型を作成した。

```ts
type NursingRecordItemProps = {
  onErrorsChange: React.Dispatch<React.SetStateAction<{}>>;
};
```

さらに、`PatientPage` の Outlet Context から受け取る値の型を作成した。

```ts
type NursingRecordItemContext = {
  patient: Patient | undefined | null;
  patientRecords: NursingRecord[];
  updateRecord: (
    recordToUpdate: NursingRecord,
  ) => Promise<NursingRecord | undefined>;
  deleteRecord: (id: string) => Promise<boolean>;
};
```

`useOutletContext` に型を渡した。

```ts
const { patient, patientRecords, updateRecord, deleteRecord } =
  useOutletContext<NursingRecordItemContext>();
```

これによりTypeScriptは、それぞれの値を以下の型として認識できる。

```text
patient
→ Patient | undefined | null

patientRecords
→ NursingRecord[]

updateRecord
→ NursingRecordを受け取り、
  NursingRecordまたはundefinedを返す非同期関数

deleteRecord
→ idを受け取り、
  booleanを返す非同期関数
```

## 今日理解したポイント

* `return updatedRecord` は、更新後のデータを呼び出し元へ返している
* `await updateRecord(...)` の戻り値は変数で受け取れる
* 更新失敗時は `undefined` を使って処理を止められる
* 削除処理は `boolean` を返すことで成功・失敗を判断できる
* `React.Dispatch<React.SetStateAction<{}>>` は `useState` の更新関数の型
* propsで受け取る関数は、親で定義した関数と同じ引数型・戻り値型にする
* `useOutletContext` には Context 全体の型を指定できる
* 使用していないpropsは渡さない
