## 1. Patient型の修正

実際の`server/data.json`では、年齢・病名・既往歴・経過が存在しない患者もいる。

そのため、これらを任意プロパティに変更した。

```ts
export type Patient = {
  id: string;
  name: string;
  room: number;
  age?: number;
  disease?: string;
  history?: string;
  progress?: string;
};
```

`?`が付いたプロパティは、存在しなくてもよい。

```ts
age?: number;
```

これは次の型と同じような意味になる。

```ts
age: number | undefined;
```

## 2. NursingRecord型の修正

Zodの`recordSchema`では日付が必須になっている。

そのため、`NursingRecord`でも`date`を必須にした。

```ts
export type NursingRecord = {
  id: string;
  patientId: string;
  date: string;
  author: string;
  content?: string;
  vitals: VitalSigns;
};
```

変更前は任意プロパティだった。

```ts
date?: string;
```

変更後は必須になった。

```ts
date: string;
```

## 4. deletePatientの戻り値

患者削除に成功したかどうかを呼び出し側で判断できるように、戻り値を`boolean`に変更した。

```ts
const deletePatient = async (
  id: string,
): Promise<boolean> => {
  try {
    setApiError("");

    const deletedPatient = await deletePatientApi(id);

    setAppData((prev) => ({
      ...prev,
      patients: prev.patients.filter(
        (patient) =>
          String(patient.id) !== String(deletedPatient.id),
      ),
      records: prev.records.filter(
        (record) =>
          String(record.patientId) !==
          String(deletedPatient.id),
      ),
    }));

    return true;
  } catch (error) {
    console.error("患者削除に失敗しました", error);
    setApiError("患者削除に失敗しました");

    return false;
  }
};
```

戻り値の意味は次のとおり。

```text
削除成功：true
削除失敗：false
```

## 5. addRecordの戻り値

看護記録追加に成功した場合は、APIから返ってきた看護記録を返す。

失敗した場合は`undefined`を返す。

```ts
const addRecord = async (
  record: RecordOutput,
  patientId: string,
): Promise<NursingRecord | undefined> => {
  const recordToAdd: Omit<NursingRecord, "id"> = {
    ...record,
    patientId,
  };

  try {
    setApiError("");

    const savedRecord = await createRecordApi(recordToAdd);

    setAppData((prev) => ({
      ...prev,
      records: [...prev.records, savedRecord],
    }));

    return savedRecord;
  } catch (error) {
    console.error("看護記録追加に失敗しました", error);
    setApiError("看護記録追加に失敗しました");

    return undefined;
  }
};
```

戻り値は次のようになる。

```text
追加成功：NursingRecord
追加失敗：undefined
```

## 6. 看護記録追加成功時だけフォームを閉じる

`addRecord`の戻り値を` savedRecord`で受け取る。

```ts
const handleAddRecordSubmit = async (
  data: RecordOutput,
): Promise<void> => {
  const savedRecord = await addRecord(data, patient.id);

  if (!savedRecord) {
    return;
  }

  setIsAdding(false);
  setFormData(createEmptyRecord());
};
```

失敗時は`undefined`が返るため、処理を終了する。

```ts
if (!savedRecord) {
  return;
}
```

これにより、追加失敗時にフォームが勝手に閉じなくなった。

## 7. 看護記録更新処理の型付け

フォームから受け取る値に`RecordOutput`型を指定した。

```ts
const handleRecordSubmit = async (
  formValues: RecordOutput,
): Promise<void> => {
  const recordToUpdate: NursingRecord = {
    ...record,
    ...formValues,
  };

  const updatedRecord = await updateRecord(
    recordToUpdate,
  );

  if (!updatedRecord) {
    return;
  }

  console.log("更新成功", updatedRecord);

  setIsEditing(false);
  navigate(`/patient/${patient.id}/records`);
};
```

元の`record`には、次の値が含まれている。

```text
id
patientId
現在の看護記録
```

`formValues`には、バリデーション後のフォームデータが含まれている。

```text
date
author
content
vitals
```

次の処理では、元の看護記録に編集後のフォームデータを上書きしている。

```ts
const recordToUpdate: NursingRecord = {
  ...record,
  ...formValues,
};
```

`formValues`には`id`と`patientId`がないため、それらは元の`record`から残る。

## 8. PatientPagePropsの作成

`PatientPage`は、Appから次のデータを受け取る。

```text
patients：患者全員
records：看護記録全部
各種CRUD関数
```

現在作成している型は以下。

```ts
type PatientPageProps = {
  patients: Patient[];
  records: NursingRecord[];
} & Pick<
  PatientOutletContext,
  | "updatePatient"
  | "addRecord"
  | "updateRecord"
  | "deleteRecord"
  | "deletePatient"
>;
```

### PatientPagePropsとPatientOutletContextの違い

`PatientPageProps`は、Appから`PatientPage`へ渡すデータの型。

```text
App
↓ props
PatientPage
```

`PatientOutletContext`は、`PatientPage`から子ルートへ渡すデータの型。

```text
PatientPage
↓ Outlet Context
PatientDetailなどの子コンポーネント
```

## 9. Pickと&について

次の部分は今日初めて確認した。

```ts
& Pick<
  PatientOutletContext,
  | "updatePatient"
  | "addRecord"
  | "updateRecord"
  | "deleteRecord"
  | "deletePatient"
>
```

### Pick

`Pick`は、既存の型から指定したプロパティだけを取り出す。

```ts
type User = {
  id: string;
  name: string;
  age: number;
};

type UserProfile = Pick<User, "name" | "age">;
```

作られる型は次と同じ。

```ts
type UserProfile = {
  name: string;
  age: number;
};
```

### &

型で使う`&`は、複数の型を合体させる。

```ts
type A = {
  name: string;
};

type B = {
  age: number;
};

type C = A & B;
```

`C`は次の型になる。

```ts
type C = {
  name: string;
  age: number;
};
```

## 今日理解できたポイント

- 実際のデータに存在しない項目は任意プロパティにできる
- Zodで必須の項目は、ドメイン型でも必須にそろえる
- 型としてだけ使用するimportには`import type`を使う
- 追加・更新成功時は、APIから返ったデータを返せる
- 失敗時に`undefined`や`false`を返すと、呼び出し側で処理を止められる
- `RecordOutput`はZodによる変換後の型
- 更新時は、元データにフォームデータを上書きできる
- `PatientPageProps`と`PatientOutletContext`は役割が異なる
