## 1. PropsとOutlet Contextの違い

今回のアプリでは、データが次の順番で渡される。

```text
App
 ↓ Props
PatientPage
 ↓ patientやpatientRecordsを作成
Outlet Context
 ↓
NursingRecordListなどの子ルート
```

### Props

Propsは、親コンポーネントから直接呼び出した子コンポーネントへ値を渡すために使用する。

```tsx
<PatientPage
  patients={appData.patients}
  records={appData.records}
  updatePatient={updatePatient}
  addRecord={addRecord}
  updateRecord={updateRecord}
  deleteRecord={deleteRecord}
  deletePatient={deletePatient}
/>
```

### Outlet Context

`Outlet Context`は、`PatientPage`から`Outlet`内に表示される子ルートへ値を渡すために使用する。

```tsx
return <Outlet context={outletContext} />;
```

子ルートでは`useOutletContext()`を使って受け取る。

```tsx
const { patient, patientRecords, addRecord } =
  useOutletContext<NursingRecordListOutletContext>();
```

## 2. Outletの役割

`Outlet`は、現在のURLに対応する子ルートを表示する場所である。

```tsx
<Route
  path="/patient/:id"
  element={
    <PatientPage
      patients={appData.patients}
      records={appData.records}
      updatePatient={updatePatient}
      addRecord={addRecord}
      updateRecord={updateRecord}
      deleteRecord={deleteRecord}
      deletePatient={deletePatient}
    />
  }
>
  <Route index element={<PatientMenu />} />
  <Route
    path="detail"
    element={<PatientDetail onErrorsChange={setGlobalErrors} />}
  />
  <Route path="vitals" element={<PatientVitals />} />
  <Route
    path="records"
    element={<NursingRecordList onErrorsChange={setGlobalErrors} />}
  />
  <Route
    path="records/:recordId"
    element={<NursingRecordItem onErrorsChange={setGlobalErrors} />}
  />
</Route>
```

URLによって、`PatientPage`の`Outlet`に表示されるコンポーネントが変わる。

| URL | Outletに表示されるコンポーネント |
|---|---|
| `/patient/1` | `PatientMenu` |
| `/patient/1/detail` | `PatientDetail` |
| `/patient/1/vitals` | `PatientVitals` |
| `/patient/1/records` | `NursingRecordList` |
| `/patient/1/records/10` | `NursingRecordItem` |

## 3. PatientPagePropsのPick

```tsx
type PatientPageProps = {
  patients: Patient[];
  records: NursingRecord[];
} & Pick<
  PatientOutletContext,
  | "updatePatient"
  | "updateRecord"
  | "deleteRecord"
  | "deletePatient"
  | "addRecord"
>;
```

`PatientPage`独自のPropsは、直接型を書いている。

```tsx
{
  patients: Patient[];
  records: NursingRecord[];
}
```

各関数の型は、`PatientOutletContext`から`Pick`で取り出している。

```tsx
Pick<
  PatientOutletContext,
  | "updatePatient"
  | "updateRecord"
  | "deleteRecord"
  | "deletePatient"
  | "addRecord"
>
```

`&`によって、2つの型を合体させている。

## 4. PatientPageで患者と記録を取得する

```tsx
const { id } = useParams();

const patient = patients.find(
  (p) => String(p.id) === id,
);

const patientRecords = records.filter(
  (r) => String(r.patientId) === id,
);
```

### `find()`

`find()`は、条件に一致する1つの要素を取得する。

```tsx
const patient = patients.find(
  (p) => String(p.id) === id,
);
```

見つからなかった場合は`undefined`を返すため、確認が必要になる。

```tsx
if (!patient) {
  return <div>患者が見つかりません</div>;
}
```

### `filter()`

`filter()`は、条件に一致する複数の要素を配列で取得する。

```tsx
const patientRecords = records.filter(
  (r) => String(r.patientId) === id,
);
```

記録が見つからない場合でも、`undefined`ではなく空配列を返す。

```tsx
[]
```

そのため、次の確認は不要である。

```tsx
if (!patientRecords) {
  return <div>患者記録が見つかりません</div>;
}
```

記録が0件か確認する場合は、配列の長さを使用する。

```tsx
if (patientRecords.length === 0) {
  // 記録が0件の場合
}
```

### 今回の使い分け

```text
患者を1人取得する    → find()
患者の記録を複数取得 → filter()
```

## 5. PatientOutletContextを作る

患者の存在を確認したあと、子ルートへ渡すContextを作成する。

```tsx
if (!patient) {
  return <div>患者が見つかりません</div>;
}

const usedRoomsForEdit = extractUsedRoomNumbers(
  patients,
  patient.id,
);

const outletContext: PatientOutletContext = {
  patient,
  patientRecords,
  updatePatient,
  addRecord,
  updateRecord,
  deleteRecord,
  deletePatient,
  usedRoomsForEdit,
};

return <Outlet context={outletContext} />;
```

`PatientPage`内で作成した値は次の3つ。

```tsx
patient
patientRecords
usedRoomsForEdit
```

`App`からPropsで受け取った関数は次の5つ。

```tsx
updatePatient
addRecord
updateRecord
deleteRecord
deletePatient
```

これらを合体させて、完全な`PatientOutletContext`を作っている。

## 6. PatientOutletContextの型

```tsx
export type PatientOutletContext = {
  patient: Patient;
  patientRecords: NursingRecord[];
  updatePatient: (
    patient: Patient,
  ) => Promise<Patient | undefined>;
  addRecord: (
    data: RecordOutput,
    patientId: string,
  ) => Promise<NursingRecord | undefined>;
  updateRecord: (
    record: NursingRecord,
  ) => Promise<NursingRecord | undefined>;
  deleteRecord: (
    id: string,
  ) => Promise<boolean>;
  deletePatient: (
    id: string,
  ) => Promise<boolean>;
  usedRoomsForEdit: number[];
};
```

`deleteRecord`は、成功時に`true`、失敗時に`false`を返すため、戻り値型は`Promise<boolean>`になる。

```tsx
const deleteRecord = async (
  id: string,
): Promise<boolean> => {
  try {
    setApiError("");

    const deletedRecord = await deleteRecordApi(id);

    setAppData((prev) => ({
      ...prev,
      records: prev.records.filter(
        (record) =>
          String(record.id) !== String(deletedRecord.id),
      ),
    }));

    return true;
  } catch (error) {
    console.error("看護記録削除に失敗しました", error);
    setApiError("看護記録削除に失敗しました");

    return false;
  }
};
```

## 7. NursingRecordList専用のOutlet Context型

最初は、使用する型を直接書いていた。

```tsx
type NursingRecordListOutletContext = {
  patient: Patient | undefined | null;
  patientRecords: NursingRecord[];
  addRecord: (
    data: RecordOutput,
    patientId: string,
  ) => Promise<NursingRecord | undefined>;
};
```

今回は、共通の`PatientOutletContext`から必要なプロパティを`Pick`する方法に変更した。

```tsx
type NursingRecordListOutletContext = Pick<
  PatientOutletContext,
  "patient" | "patientRecords" | "addRecord"
>;
```

受け取る場所は次のとおり。

```tsx
const { patient, patientRecords, addRecord } =
  useOutletContext<NursingRecordListOutletContext>();
```

これにより、`PatientOutletContext`と子コンポーネントの型をそろえやすくなる。

## 8. 今日の重要ポイント

- Propsは、親から直接呼び出した子コンポーネントへ値を渡す。
- Outlet Contextは、親ルートからOutlet内の子ルートへ値を渡す。
- `Outlet`には、URLに対応する子ルートのコンポーネントが表示される。
- `find()`は1件を取得し、見つからない場合は`undefined`を返す。
- `filter()`は複数件を配列で取得し、見つからない場合は`[]`を返す。
- `Pick`を使うと、既存の型から必要なプロパティだけを選択できる。
- 関数の型は、実際の戻り値と一致させる。
- `deleteRecord`は`true`または`false`を返すため、`Promise<boolean>`になる。
