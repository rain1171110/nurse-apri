## 1. NursingRecordListのContext型

`NursingRecordList`が使用する3項目だけを取り出しました。

```tsx
type NursingRecordListOutletContext = Pick<
  PatientOutletContext,
  "patient" | "patientRecords" | "addRecord"
>;
```

Contextを受け取る処理です。

```tsx
const { patient, patientRecords, addRecord } =
  useOutletContext<NursingRecordListOutletContext>();
```

`Pick`を使うことで、このコンポーネントが何を使用しているのか分かりやすくなります。

## 3. PatientDetailのContext型

`PatientDetail`が使用する3項目だけを取り出しました。

```tsx
type PatientDetailOutletContext = Pick<
  PatientOutletContext,
  "patient" | "updatePatient" | "usedRoomsForEdit"
>;
```

Contextを受け取ります。

```tsx
const { patient, updatePatient, usedRoomsForEdit } =
  useOutletContext<PatientDetailOutletContext>();
```

### 発生したエラー

`useOutletContext`の末尾に`()`がなかったため、次のエラーが発生しました。

```text
Property 'patient' does not exist on type
'() => PatientDetailOutletContext'
```

間違ったコードです。

```tsx
useOutletContext<PatientDetailOutletContext>
```

これは関数を実行せず、「関数そのもの」を表しています。

正しいコードです。

```tsx
useOutletContext<PatientDetailOutletContext>()
```

`()`を付けることで関数が実行され、Contextのオブジェクトが返ります。

## 4. 患者フォーム用の型を追加

以前の`PatientDetail`では、看護記録用の型を使用していました。

```tsx
RecordInput
RecordOutput
```

しかし、`PatientDetail`は患者情報フォームなので、患者用の型を追加しました。

```tsx
export type PatientInput = z.input<
  ReturnType<typeof makePatientSchemaPartial>
>;

export type PatientOutput = z.output<
  ReturnType<typeof makePatientSchemaPartial>
>;
```

### PatientInput

Zodによる検証・変換前の型です。

フォームの数値入力欄では、文字列が入る可能性があります。

```tsx
{
  name: "山田太郎",
  room: "101",
  age: "70"
}
```

### PatientOutput

Zodによる検証・変換後の型です。

```tsx
{
  name: "山田太郎",
  room: 101,
  age: 70
}
```

使い分けは次のとおりです。

```text
患者情報フォーム → PatientInput / PatientOutput
看護記録フォーム → RecordInput / RecordOutput
```

## 5. ReturnTypeが必要な理由

`makePatientSchemaPartial`は、Zodスキーマそのものではなく、Zodスキーマを返す関数です。

```tsx
export const makePatientSchemaPartial = (
  usedRooms: number[],
) => {
  return z.object({
    // 患者用スキーマ
  });
};
```

`typeof`だけでは、関数そのものの型になります。

```tsx
typeof makePatientSchemaPartial
```

イメージすると次の型です。

```tsx
(usedRooms: number[]) => 患者用のZodスキーマ
```

関数が返すZodスキーマの型を取得するため、`ReturnType`を使います。

```tsx
ReturnType<typeof makePatientSchemaPartial>
```

流れは次のとおりです。

```text
makePatientSchemaPartial
        ↓ typeof
関数の型
        ↓ ReturnType
関数が返すZodスキーマの型
        ↓ z.input / z.output
PatientInput / PatientOutput
```

スキーマが変数の場合は、`typeof`だけで取得できます。

```tsx
export const recordSchema = z.object({
  // 看護記録スキーマ
});

export type RecordInput = z.input<typeof recordSchema>;
export type RecordOutput = z.output<typeof recordSchema>;
```

今回の使い分けです。

```tsx
// スキーマが入った変数
z.input<typeof recordSchema>;

// スキーマを返す関数
z.input<ReturnType<typeof makePatientSchemaPartial>>;
```

すべての関数に`ReturnType`が必要という意味ではありません。

今回は関数そのものではなく、「関数が返すZodスキーマの型」が必要なため使用しています。

## 6. roomを必須の数値に変更

`Patient`型では、`room`が必須の数値です。

```tsx
export type Patient = {
  id: string;
  name: string;
  room: number;
};
```

患者スキーマでも空欄を許可しないように変更しました。

```tsx
room: optionalNumber(
  1,
  999,
  "部屋番号は1以上",
  "部屋番号は999以下",
)
  .refine((value) => value !== undefined, {
    message: "部屋番号は必須です",
  })
  .transform((value) => value as number),
```

これにより、検証後の`PatientOutput`では`room`が`number`になります。

## 7. PatientDetailのフォーム型

Propsのエラー型を患者用に変更しました。

```tsx
type PatientDetailProps = {
  onErrorsChange?: (
    errors: FieldErrors<PatientInput>,
  ) => void;
};
```

`useForm`には、入力前と変換後の型を指定しました。

```tsx
const {
  control,
  handleSubmit,
  formState: { errors },
  reset,
  clearErrors,
} = useForm<PatientInput, unknown, PatientOutput>({
  resolver: zodResolver(
    makePatientSchemaPartial(usedRoomsForEdit),
  ),
  mode: "onSubmit",
  reValidateMode: "onSubmit",
  defaultValues,
});
```

型引数の役割です。

```tsx
useForm<
  PatientInput,  // フォーム入力時
  unknown,       // 外部Contextは使用しない
  PatientOutput  // Zodによる検証・変換後
>
```

## 8. 患者更新処理

Zodによる検証・変換後の`PatientOutput`を受け取ります。

```tsx
const handlePatientSubmit = async (
  data: PatientOutput,
): Promise<void> => {
  const patientToUpdate = {
    ...patient,
    ...data,
  };

  const updatedPatient = await updatePatient(patientToUpdate);

  if (!updatedPatient) {
    return;
  }

  reset(data);
  clearErrors();
  onErrorsChange?.({});
  setIsEditing(false);
};
```

### patientToUpdateを使う理由

`updatePatient`では、どの患者を更新するか判断するために`id`が必要です。

```tsx
const patientToUpdate = {
  ...patient,
  ...data,
};

await updatePatient(patientToUpdate);
```

`patientToUpdate`には`id`が含まれます。

```tsx
{
  id: "1",
  name: "山田太郎",
  room: 101,
  age: 70
}
```

### resetにdataを使う理由

`reset()`は、フォームの値を設定し直す処理です。

フォームには`id`の入力欄がないため、フォーム項目だけを持つ`data`を渡します。

```tsx
reset(data);
```

使い分けは次のとおりです。

```tsx
// 患者IDが必要
updatePatient(patientToUpdate);

// 患者IDが不要
reset(data);
```

## 今日のまとめ

- `Pick`でContextから必要な項目だけを選択した
- `useOutletContext`の実行には末尾の`()`が必要
- 患者フォームには`PatientInput`と`PatientOutput`を使う
- 看護記録フォームには`RecordInput`と`RecordOutput`を使う
- スキーマを返す関数の戻り値型は`ReturnType`で取得する
- `updatePatient`には患者IDを含む`patientToUpdate`を渡す
- `reset`にはフォーム項目だけを持つ`data`を渡す
- 更新に失敗した場合はフォームを閉じない
