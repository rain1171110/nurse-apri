## 1. `defaultValues`と`reset()`の違い

`defaultValues`は、React Hook Formでフォームが最初に作成されたときの初期値として使われる。

```tsx
const defaultValues = useMemo(
  () => ({
    name: patient?.name ?? "",
    room: patient?.room ?? "",
    age: patient?.age ?? "",
    disease: patient?.disease ?? "",
    history: patient?.history ?? "",
    progress: patient?.progress ?? "",
  }),
  [patient],
);
```

しかし、別の患者を選択して`patient`が変わっても、`defaultValues`だけでは入力欄は自動更新されない。

そのため、`defaultValues`が変わったときに`reset()`を実行する。

```tsx
useEffect(() => {
  reset(defaultValues);
}, [defaultValues, reset]);
```

処理の流れは次のとおり。

```text
patientが変わる
↓
useMemoがdefaultValuesを作り直す
↓
defaultValuesが変わる
↓
useEffectが実行される
↓
reset(defaultValues)でフォームを更新する
```

## 2. 患者情報を更新するときに`patient`と`data`を結合する理由

```tsx
const patientToUpdate = { ...patient, ...data };
```

- `patient`には患者の`id`と変更前の情報が入っている
- `data`にはフォーム入力後の情報が入っている
- `data`には患者の`id`が含まれていない

そのため、患者を判別するための`id`を残しながら、フォームの値で患者情報を上書きする。

```tsx
const handlePatientSubmit = async (
  data: PatientOutput,
): Promise<void> => {
  const patientToUpdate = { ...patient, ...data };

  const updatedPatient = await updatePatient(patientToUpdate);

  if (!updatedPatient) {
    return;
  }

  reset(data);
  clearErrors();
  onErrorsChange?.({});
  setIsEditing(false);
};
```

後ろに書いた`...data`が、`patient`の同じプロパティを上書きする。

## 4. `DeleteButton`の型付け

`DeleteButton`は削除処理の内容や患者IDを知らず、親から渡された削除関数を実行する。

```tsx
type DeleteButtonProps = {
  onDelete: () => Promise<void>;
};

export default function DeleteButton({
  onDelete,
}: DeleteButtonProps) {
  const handleDelete = async (): Promise<void> => {
    const ok = window.confirm("この患者を削除しますか？");

    if (!ok) return;

    await onDelete();
  };

  return (
    <button
      type="button"
      className="btn-danger"
      onClick={handleDelete}
    >
      削除
    </button>
  );
}
```

削除関数の受け渡しは次の流れになる。

```text
親コンポーネント
↓
PatientCardのonDeletePatient
↓
DeleteButtonのonDelete
↓
onDelete()を実行
```

## 7. 患者追加成功時だけフォームを閉じる

以前のコードでは、患者追加に失敗しても子コンポーネント側でフォームを閉じる可能性があった。

```tsx
await onSubmit(data);
reset();
setShowAddForm(false);
```

親コンポーネント内で`return`しても、Promiseの処理が完了すると子側は次の処理へ進んでしまう。

そこで、親から保存結果を返し、子で成功したか確認するように変更した。

### `PatientList.tsx`

```tsx
const addPatientSubmit = async (
  data: Omit<Patient, "id">,
): Promise<Patient | undefined> => {
  const savedPatient = await addPatient(data);

  if (!savedPatient) {
    return undefined;
  }

  return savedPatient;
};
```

### `AddPatientForm.tsx`

```tsx
const handleAddPatientSubmit = async (
  data: PatientOutput,
): Promise<void> => {
  const savedPatient = await onSubmit(data);

  if (!savedPatient) {
    return;
  }

  reset();
  setShowAddForm(false);
};
```

これにより、次の動作になる。

```text
患者追加に成功
↓
savedPatientが返る
↓
フォームをリセットする
↓
フォームを閉じる
```

```text
患者追加に失敗
↓
undefinedが返る
↓
returnする
↓
入力内容を残してフォームを開いたままにする
```

---

## 8. 今日理解したこと

- `defaultValues`はフォーム作成時の初期値として使われる
- 患者変更後の値は`reset(defaultValues)`でフォームへ反映する
- `useEffect`の中で`reset()`を呼び出す順番を理解した
- `data`には患者IDがないため、`patient`と結合する必要がある
- `Patient[]`は患者オブジェクトの配列を表す
- stateの更新関数には`Dispatch<SetStateAction<boolean>>`を使用する
- propsで渡す非同期関数は`() => Promise<void>`などで表現する
- 親コンポーネントから保存結果を返すことで、子が成功・失敗を判定できる
- API処理に失敗した場合は、フォームを閉じず入力内容を残す設計にできる

## 2. `deletePatient`の戻り値

`PatientMenu.tsx`では、削除結果を確認してから患者一覧へ移動している。

```tsx
const isDeleted = await deletePatient(patient.id);

if (!isDeleted) {
  return;
}

navigate("/");
```

そのため、`deletePatient`の戻り値を`Promise<void>`にすると、`isDeleted`は`undefined`になる。

削除に成功したかどうかを呼び出し元へ伝えるため、戻り値を`Promise<boolean>`にした。

```tsx
const deletePatient = async (
  id: string,
): Promise<boolean> => {
  try {
    setApiError("");

    const deletedPatient = await deletePatientApi(id);

    setAppData((prev) => ({
      ...prev,
      patients: prev.patients.filter(
        (patient) =>
          String(patient.id) !==
          String(deletedPatient.id),
      ),
      records: prev.records.filter(
        (record) =>
          String(record.patientId) !==
          String(deletedPatient.id),
      ),
    }));

    return true;
  } catch (error) {
    console.error(
      "患者削除に失敗しました",
      error,
    );

    setApiError("患者削除に失敗しました");

    return false;
  }
};
```

戻り値の役割は次のとおり。

```tsx
return true;
```

削除成功を表す。

```tsx
return false;
```

削除失敗を表す。

## 3. 削除された患者のIDを使ってstateを更新する

APIから返ってきた削除済み患者のIDを使用して、患者一覧から対象患者を除外する。

```tsx
patients: prev.patients.filter(
  (patient) =>
    String(patient.id) !==
    String(deletedPatient.id),
),
```

同じ患者に紐づいた看護記録も削除する。

```tsx
records: prev.records.filter(
  (record) =>
    String(record.patientId) !==
    String(deletedPatient.id),
),
```

`filter()`は、条件が`true`になったデータを新しい配列へ残す。

そのため、削除された患者IDと一致しないデータだけを残している。

## 5. `PatientMenuContext`で必要な型だけを取得する

`PatientMenu.tsx`で使用するOutlet Contextは次の2つだけである。

- `patient`
- `deletePatient`

そのため、`Pick`を使用して必要な型だけを取り出した。

```tsx
type PatientMenuContext = Pick<
  PatientOutletContext,
  "patient" | "deletePatient"
>;
```

`PatientOutletContext`全体を指定することもできるが、`Pick`を使うと、このコンポーネントが何を使用しているのか分かりやすくなる。

## 6. 完成した`PatientMenu.tsx`

```tsx
import {
  useOutletContext,
  useNavigate,
} from "react-router-dom";
import PatientCard from "./PatientCard";
import type { PatientOutletContext } from "./types";

type PatientMenuContext = Pick<
  PatientOutletContext,
  "patient" | "deletePatient"
>;

export default function PatientMenu() {
  const navigate = useNavigate();

  const { patient, deletePatient } =
    useOutletContext<PatientMenuContext>();

  if (!patient) {
    return <div>患者が見つかりません</div>;
  }

  const handleDelete = async (): Promise<void> => {
    const isDeleted = await deletePatient(patient.id);

    if (!isDeleted) {
      return;
    }

    navigate("/");
  };

  return (
    <div>
      <PatientCard
        patient={patient}
        onDeletePatient={handleDelete}
      />
    </div>
  );
}
```

## 7. `handleDelete`の戻り値が`Promise<void>`になる理由

`deletePatient`は削除結果を返す。

```tsx
deletePatient: (
  id: string,
) => Promise<boolean>;
```

一方、`handleDelete`は結果を受け取って画面遷移に使用するが、自分自身は値を返さない。

```tsx
const handleDelete =
  async (): Promise<void> => {
```

つまり、それぞれの役割は異なる。

```text
deletePatient
→ 削除結果としてbooleanを返す

handleDelete
→ 結果を使って画面遷移する
→ 自分自身は何も返さない
```

## 8. 患者削除処理全体のつながり

```text
App.tsx
deletePatient(id)を定義
↓ propsとして渡す

PatientPage
deletePatientを受け取る
↓ Outlet contextとして渡す

PatientMenu
deletePatientを受け取る
↓

PatientCard

↓

DeleteButton

↓

↓

```

## 9. 今日理解したこと

- Routeの`deletePatient={deletePatient}`は関数の実行ではなく、関数の受け渡しである
- propsの左側は受け取り先の名前、右側は渡す値や関数である
- `PatientPage`から子ルートへはOutlet Contextを使って関数を渡せる
- `PatientMenu`では`useOutletContext()`を使って関数を受け取る
- `Pick`を使うと必要なContext型だけを取り出せる
- 削除結果を使用する場合は`Promise<void>`ではなく`Promise<boolean>`が必要になる
- 削除成功時は`true`、失敗時は`false`を返す
- `handleDelete`は削除結果を使用するが、自分自身は値を返さないため`Promise<void>`になる
- 削除成功時だけ患者一覧へ移動する仕組みを理解した
