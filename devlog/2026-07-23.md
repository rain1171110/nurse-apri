## 1. `main.jsx`のTypeScript化

`main.jsx`を`main.tsx`へ変更した。

TypeScriptでは、`document.getElementById()`の戻り値が次の型になる。

```ts
HTMLElement | null
```

今回は`index.html`に`id="root"`の要素が必ず存在するため、`!`を付けて「`null`ではない」とTypeScriptへ伝えた。

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { BrowserRouter as Router } from "react-router-dom";
import "./index.css";
import "./App.css";
import App from "./App";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <Router>
      <App />
    </Router>
  </StrictMode>,
);
```

## 2. `PatientVitals`のTypeScript化

`PatientVitals`では、`PatientOutletContext`から使用する値だけを`Pick`で取り出した。

```tsx
type PatientVitalsOutletContext = Pick<
  PatientOutletContext,
  "patient" | "patientRecords"
>;
```

Outlet Contextに型を指定した。

```tsx
const { patient, patientRecords } =
  useOutletContext<PatientVitalsOutletContext>();
```

これにより、`patientRecords.map()`内の`r`は、自動的に`NursingRecord`型として推論される。

```tsx
patientRecords.map((r) => {
  const { T, P, R, SBP, DBP, SPO2 } = r.vitals ?? {};
});
```

`T`や`P`なども、次の型として自動推論される。

```ts
number | undefined
```

## 9. Prismaのデータモデル作成

患者、看護記録、バイタルサインの3つのモデルを作成した。

```prisma
generator client {
  provider = "prisma-client"
  output   = "../server/generated/prisma"
}

datasource db {
  provider = "postgresql"
}

model Patient {
  id       String          @id @default(uuid())
  name     String
  room     Int             @unique
  age      Int?
  disease  String?
  history  String?
  progress String?
  records  NursingRecord[]
}

model NursingRecord {
  id        String      @id @default(uuid())
  patientId String
  date      String
  author    String
  content   String?
  patient   Patient     @relation(fields: [patientId], references: [id], onDelete: Cascade)
  vitals    VitalSigns?
}

model VitalSigns {
  id       String        @id @default(uuid())
  recordId String        @unique
  T        Float?
  P        Int?
  R        Int?
  SBP      Int?
  DBP      Int?
  SPO2     Int?
  record   NursingRecord @relation(fields: [recordId], references: [id], onDelete: Cascade)
}
```

モデルの関係：

```text
Patient 1人
  └─ NursingRecord 複数
       └─ VitalSigns 1件
```

`onDelete: Cascade`により、患者を削除したときに、その患者の看護記録も削除できる設計にした。

データモデルの文法を確認した。

```bash
npx prisma validate
```

結果：

```text
The schema at prisma\schema.prisma is valid
```

## 13. Prisma接続ファイルの作成

`server/db.ts`を作成した。

```ts
import "dotenv/config";
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "./generated/prisma/client.js";

const connectionString = process.env.DATABASE_URL;

if (!connectionString) {
  throw new Error("DATABASE_URL is not defined");
}

const adapter = new PrismaPg({
  connectionString,
});

export const prisma = new PrismaClient({
  adapter,
});
```

処理の流れ：

```text
.envからDATABASE_URLを取得
↓
PrismaPgでPostgreSQLへの接続を作成
↓
PrismaClientへ接続を渡す
↓
他のファイルから利用できるようにexport
```

`DATABASE_URL`が設定されていない場合は、分かりやすいエラーを発生させる。

```ts
if (!connectionString) {
  throw new Error("DATABASE_URL is not defined");
}
```

## 今日理解したこと

- `document.getElementById()`は`null`を返す可能性がある
- `!`を使うと、値が`null`ではないことをTypeScriptへ伝えられる
- `Pick`を使うと、コンポーネントが使用する値を明示できる
- ViteのビルドとTypeScriptの型チェックは同じものではない
- PrismaはJavaScriptからデータベースを操作しやすくするORM
- Prisma Schemaでテーブルとリレーションを定義できる
- `@unique`を使うと、データベース側でも重複を防止できる
- `onDelete: Cascade`で関連データを連鎖削除できる
- `.env`の接続情報はGitHubへ公開してはいけない
- `prisma db push`は現在の設計をDBへ直接反映する
- `prisma generate`はデータベース操作用のClientを生成する
- `npm audit fix --force`は安易に使用しない
- フロントエンドとバックエンドでTypeScript設定を分けられる
