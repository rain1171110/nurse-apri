## Prismaが生成した型

`server/generated/prisma/client.ts`は自分で作成したファイルではなく、Prismaが自動生成したファイル。

次のコマンドを実行すると生成される。

```bash
npx prisma generate
```

`server/index.ts`では、Prismaが生成した型を読み込んだ。

```ts
import type {
  NursingRecord,
  Patient,
} from "./generated/prisma/client.js";
```

実際のファイルは`client.ts`だが、NodeNext形式では、実行時に生成されるJavaScriptを想定して`.js`と書く。

`generated`フォルダ内のファイルは、基本的に直接編集しない。

## AppData型の作成

患者配列と看護記録配列を持つオブジェクトを表すため、サーバー側に`AppData`型を作成した。

```ts
type AppData = {
  patients: Patient[];
  records: NursingRecord[];
};
```

フロントエンドの`src/types.ts`にも`AppData`型はある。

しかし、サーバーから`src/types.ts`を読み込むと、`src/schema.ts`などのフロントエンド用ファイルまでサーバーの設定で型チェックされてしまった。

そのため、現在はサーバー側に一時的な`AppData`型を作成した。

Prismaへ完全移行すると、`data.json`、`readData()`、`writeData()`、この`AppData`型も将来的には不要になる。

## readDataとwriteDataへの型付け

変更前は、`data`の型が決まっていなかった。

```ts
const readData = () => {
  const raw = readFileSync(dataPath, "utf-8");
  return JSON.parse(raw);
};

const writeData = (data) => {
  writeFileSync(dataPath, JSON.stringify(data, null, 2), "utf-8");
};
```

次のように型を付けた。

```ts
const readData = (): AppData => {
  const raw = readFileSync(dataPath, "utf-8");
  return JSON.parse(raw) as AppData;
};

const writeData = (data: AppData): void => {
  writeFileSync(dataPath, JSON.stringify(data, null, 2), "utf-8");
};
```

### 型の意味

```ts
const readData = (): AppData => {
```

`readData()`が`AppData`型のデータを返すという意味。

```ts
const writeData = (data: AppData): void => {
```

次の意味になる。

- 引数`data`は`AppData`型
- 戻り値はないため`void`

---

## 型推論について

`readData()`の戻り値を`AppData`型にしたことで、その先の型をTypeScriptが自動的に判断できるようになった。

```ts
const data = readData();
```

この時点で`data`は`AppData`型になる。

そのため、次の`patient`は自動的に`Patient`型になる。

```ts
data.patients.map((patient) => {
  // patientはPatient型
});
```

次の`record`も自動的に`NursingRecord`型になる。

```ts
data.records.filter((record) => {
  // recordはNursingRecord型
});
```

そのため、コールバックごとに次の型を書く必要はない。

```ts
(patient: Patient)
(record: NursingRecord)
```

型の流れは次のようになる。

```text
readData(): AppData
        ↓
data: AppData
        ↓
data.patients: Patient[]
        ↓
patient: Patient
```

## GET /api/patientsをPrismaへ変更

変更前は、`data.json`から患者一覧を取得していた。

```ts
app.get("/api/patients", (req, res) => {
  try {
    const data = readData();
    res.json(data.patients);
  } catch (error) {
    console.error("GET /api/patients error:", error);
    res.status(500).json({ error: "Failed to read patients" });
  }
});
```

Prismaを使う形に変更した。

```ts
app.get("/api/patients", async (req, res) => {
  try {
    const patients = await prisma.patient.findMany();

    res.json(patients);
  } catch (error) {
    console.error("GET /api/patients error:", error);
    res.status(500).json({ error: "Failed to read patients" });
  }
});
```

### asyncとawaitが必要な理由

データベースへのアクセスには時間がかかるため、`findMany()`はPromiseを返す。

```ts
const patients = prisma.patient.findMany();
```

この場合、`patients`は患者配列ではなくPromiseになる。

`await`を付けることで、データベースから結果が返るまで待ち、患者配列を取得できる。

```ts
const patients = await prisma.patient.findMany();
```

`await`を使用するため、Expressのコールバックにも`async`を付ける。

```ts
app.get("/api/patients", async (req, res) => {
```

## GET /api/dataをPrismaへ変更

最初は次のように考えた。

```ts
const AppData = await prisma.AppData.findMany();
```

しかし、`AppData`はTypeScriptの型であり、Prismaのモデルではない。

Prismaで操作できるのは、`schema.prisma`に定義したモデル。

```prisma
model Patient {
  // 患者データ
}

model NursingRecord {
  // 看護記録データ
}
```

そのため、患者と看護記録をそれぞれ取得する。

```ts
app.get("/api/data", async (req, res) => {
  try {
    const patients = await prisma.patient.findMany();
    const records = await prisma.nursingRecord.findMany();

    const data: AppData = {
      patients,
      records,
    };

    res.json(data);
  } catch (error) {
    console.error("GET /api/data error:", error);
    res.status(500).json({ error: "Failed to read data" });
  }
});
```

---

## patientsとrecordsをdataにまとめる理由

`res.json()`へ、次のように2つの値を別々に渡すことはできない。

```ts
res.json(patients, records);
```

そのため、患者と看護記録を1つのオブジェクトにまとめる。

```ts
const data: AppData = {
  patients,
  records,
};

res.json(data);
```

APIから返されるJSONは次の形になる。

```json
{
  "patients": [],
  "records": []
}
```

定数を作らず、直接オブジェクトを渡すこともできる。

```ts
res.json({
  patients,
  records,
});
```

今回は`AppData`型どおりの形になっているか確認するため、`data`定数を作成した。

```ts
const data: AppData = {
  patients,
  records,
};
```

例えば`records`を書き忘れると、TypeScriptがエラーで教えてくれる。

## 今日の理解

- `client.ts`は自分で作成したものではなく、Prismaが自動生成したファイル
- `generated`フォルダ内は基本的に直接編集しない
- `AppData`はデータベースのモデルではなく、API全体のデータ形式を表す型
- Prismaでは`schema.prisma`に定義したモデルを操作する
- `prisma.patient.findMany()`で患者一覧を取得できる
- `prisma.nursingRecord.findMany()`で看護記録一覧を取得できる
- データベース処理ではPromiseが返るため、`async`と`await`が必要
- `res.json()`で複数のデータを返す場合は、1つのオブジェクトにまとめる
- 関数の戻り値に型を付けると、その先の変数にも型が自動的に伝わる

対象コードはこちら。

```ts
app.post("/api/patients", async (req, res) => {
  try {
    const newPatient = await prisma.patient.create({
      data: req.body,
    });

    res.status(201).json(newPatient);
  } catch (error) {
    console.error("POST /api/patients error:", error);
    res.status(500).json({ error: "Failed to create patient" });
  }
});
```

変更前に使用していた次の処理は、Prismaへ移行すると不要になる。

```ts
const data = readData();

const newPatient = {
  ...req.body,
  id: crypto.randomUUID(),
};

const next = {
  ...data,
  patients: [...data.patients, newPatient],
};

writeData(next);
```

`schema.prisma`に次の設定があるため、患者IDはPrisma・PostgreSQL側で自動生成される。

```prisma
id String @id @default(uuid())
```
