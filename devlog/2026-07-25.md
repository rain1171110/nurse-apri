## 3. 患者追加処理をPrismaへ変更

### 変更後のコード

```ts
app.post("/api/patients", async (req, res) => {
  try {
    const newPatient = await prisma.patient.create({
      data: req.body,
    });

    res.status(201).json(newPatient);
  } catch (error) {
    console.error("POST /api/patients error:", error);
    res.status(500).json({ error: "Failed to create patient" });
  }
});
```

### 処理内容

```ts
prisma.patient.create({
  data: req.body,
});
```

- `prisma.patient`：Patientテーブルを指定する
- `create()`：新しい患者を1件保存する
- `data: req.body`：フロントから届いた患者情報を保存する
- `await`：データベースへの保存完了を待つ
- `newPatient`：保存後の患者データを受け取る

患者IDは、Prisma Schemaの設定によって自動生成される。

```prisma
id String @id @default(uuid())
```

そのため、以前使用していた次の処理は不要になった。

```ts
id: crypto.randomUUID()
```

## 4. `req.body`とは

`req.body`は、フロントエンドから送信されたデータである。

フロントエンドでは、次のようにデータを送っている。

```ts
const response = await fetch(`${API_BASE}/records`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify(record),
});
```

バックエンドでは、次の設定によってJSONをJavaScriptオブジェクトとして受け取る。

```ts
app.use(express.json());
```

データの流れ：

```text
フロントエンドのrecord
        ↓
JSON.stringify(record)
        ↓
HTTPリクエストのbody
        ↓
app.use(express.json())
        ↓
バックエンドのreq.body
```

## 5. 看護記録追加処理をPrismaへ変更

`NursingRecord`と`VitalSigns`は別テーブルなので、受信したデータを分けて保存する。

### 変更後のコード

```ts
app.post("/api/records", async (req, res) => {
  try {
    const { vitals, ...recordData } = req.body;

    const newRecord = await prisma.nursingRecord.create({
      data: {
        ...recordData,
        vitals: {
          create: vitals,
        },
      },
      include: {
        vitals: true,
      },
    });

    res.status(201).json(newRecord);
  } catch (error) {
    console.error("POST /api/records error:", error);
    res.status(500).json({ error: "Failed to create record" });
  }
});
```

### 分割代入

```ts
const { vitals, ...recordData } = req.body;
```

例えば、`req.body`が次のデータだった場合、

```ts
{
  patientId: "患者ID",
  date: "2026-07-25",
  author: "岡崎",
  content: "状態安定",
  vitals: {
    T: 36.5,
    P: 70,
    R: 16,
    SBP: 120,
    DBP: 70,
    SPO2: 98
  }
}
```

`vitals`にはバイタル情報が入る。

```ts
const vitals = {
  T: 36.5,
  P: 70,
  R: 16,
  SBP: 120,
  DBP: 70,
  SPO2: 98,
};
```

`recordData`には、`vitals`を除いた残りの情報が入る。

```ts
const recordData = {
  patientId: "患者ID",
  date: "2026-07-25",
  author: "岡崎",
  content: "状態安定",
};
```

役割：

```text
recordData → NursingRecordテーブル
vitals     → VitalSignsテーブル
```

### 関連データの同時作成

```ts
vitals: {
  create: vitals,
},
```

これによって、看護記録と関連付けながらVitalSignsを作成する。

### バイタルを含めて返す

```ts
include: {
  vitals: true,
},
```

これによって、保存後の看護記録と一緒にバイタル情報も返される。

## 6. 看護記録取得時にバイタルも取得

`GET /api/data`でも、看護記録に関連するバイタルを取得するように変更した。

```ts
app.get("/api/data", async (req, res) => {
  try {
    const patients = await prisma.patient.findMany();

    const records = await prisma.nursingRecord.findMany({
      include: {
        vitals: true,
      },
    });

    const data = {
      patients,
      records,
    };

    res.json(data);
  } catch (error) {
    console.error("GET /api/data error:", error);
    res.status(500).json({ error: "Failed to read data" });
  }
});
```

### `include`なし

```ts
const records = await prisma.nursingRecord.findMany();
```

NursingRecordテーブル本体の情報だけを取得する。

### `include`あり

```ts
const records = await prisma.nursingRecord.findMany({
  include: {
    vitals: true,
  },
});
```

NursingRecord本体と、関連するVitalSignsを一緒に取得する。

## 7. Prismaによる型推論

次の`: AppData`は、必ずしも書く必要はない。

```ts
const data: AppData = {
  patients,
  records,
};
```

今回は次のように書ける。

```ts
const data = {
  patients,
  records,
};
```

TypeScriptとPrismaが、`patients`と`records`から`data`の型を自動推論してくれる。

```ts
const records = await prisma.nursingRecord.findMany({
  include: {
    vitals: true,
  },
});
```

この場合、Prismaは`include`の内容も確認し、`records`に`vitals`が含まれる型を推論する。

重要なのは、`include`がなくても型推論は行われることである。

```text
includeなし
→ vitalsを含まない型を推論

includeあり
→ vitalsを含む型を推論
```

## 8. 以前の患者が表示されなくなった理由

以前の患者情報は`data.json`に保存されていた。

現在の取得処理は、PostgreSQLから患者を取得している。

```ts
const patients = await prisma.patient.findMany();
```

そのため、`data.json`に保存されている以前の患者は画面に表示されなくなった。

```text
以前：data.jsonから取得
現在：PostgreSQLから取得
```

以前の患者データが削除されたわけではなく、`data.json`には残っている。必要であれば、後からseed処理を作成してPostgreSQLへ移行できる。

## 今日理解したこと

- `req.body`はフロントエンドから送信されたデータ
- `express.json()`がJSONをJavaScriptオブジェクトへ変換する

- `include`で関連するバイタルも取得できる
- Prismaは`include`の内容を反映して型推論する
- PrismaのローカルDB、API、フロントの3つを起動する必要がある
