## 1. Prismaエラーを判定する方法

`catch (error)`の`error`は、TypeScriptでは中身が不明な`unknown`として扱われる。

そのため、`error.code`を使う前に安全確認が必要になる。

```ts
if (
  typeof error === "object" &&
  error !== null &&
  "code" in error &&
  error.code === "P2025"
) {
  // P2025の場合の処理
}
```

それぞれの意味は次のとおり。

```ts
typeof error === "object"
// errorがオブジェクトか確認

error !== null
// nullではないことを確認

"code" in error
// errorの中にcodeプロパティがあるか確認

error.code === "P2025"
// codeの値がP2025か確認
```

`"code"`は文字列だが、ここでは`code`というプロパティ名を指定している。

## 2. PrismaエラーをHTTPエラーへ変換する理由

Prismaのエラーコードは、バックエンド内部で使用するPrisma専用の情報。

フロントエンドには、一般的なHTTPステータスと必要最低限のメッセージを返す。

```text
Prismaのエラー
      ↓
バックエンドで判定
      ↓
HTTPステータスとJSONへ変換
      ↓
フロントエンドへ送信
```

例えば、Prismaの`P2025`は「対象データが見つからない」ことを表す。

```ts
if (error.code === "P2025") {
  res.status(404).json({
    error: "Patient not found",
  });
  return;
}
```

このコードによって、開発者が`P2025`とHTTPの`404 Not Found`をつなげている。自動的に変換されるわけではない。

Prismaのエラーを直接フロントへ返さない主な理由は次のとおり。

* フロントをPrismaに依存させない
* Prismaを知らないAPI利用者にも意味が伝わる
* データベースなどの内部情報を外部へ出しすぎない
* 将来、別のORMへ変更してもフロントのHTTP処理を維持できる

## 3. ORMとは

ORMは、プログラムからデータベースを操作するための仲介役。

PrismaはORMの一つ。

```text
Express・TypeScript
        ↓
Prisma（ORM）
        ↓
PostgreSQL
```

Prismaでは、SQLを直接書かずにTypeScriptでデータベースを操作できる。

```ts
await prisma.patient.update({
  where: {
    id,
  },
  data: result.data,
});
```

ORMは実際の開発現場でも使用される。通常のCRUDにはORMを使い、複雑な検索や集計ではSQLを併用する場合もある。

## 5. 患者更新API

患者更新時には、次のエラーを区別する。

* 部屋番号が重複している：`P2002 → 409`
* 更新対象の患者がいない：`P2025 → 404`
* その他のエラー：`500`

```ts
app.put<{ id: string }, {}, CreatePatientBody>(
  "/api/patients/:id",
  async (req, res) => {
    try {
      const result = createPatientSchema.safeParse(req.body);

      if (!result.success) {
        res.status(400).json({
          error: "Invalid patient data",
          details: result.error.flatten(),
        });
        return;
      }

      const { id } = req.params;

      const updatedPatient = await prisma.patient.update({
        where: {
          id,
        },
        data: result.data,
      });

      res.json(updatedPatient);
    } catch (error) {
      if (
        typeof error === "object" &&
        error !== null &&
        "code" in error &&
        error.code === "P2002"
      ) {
        res.status(409).json({
          error: "This room number is already in use",
        });
        return;
      }

      if (
        typeof error === "object" &&
        error !== null &&
        "code" in error &&
        error.code === "P2025"
      ) {
        res.status(404).json({
          error: "Patient not found",
        });
        return;
      }

      console.error("PUT /api/patients/:id error:", error);
      res.status(500).json({
        error: "Failed to update patient",
      });
    }
  },
);
```

## 10. フロントAPIでJSONエラーを読み取る

以前の処理では、HTTPステータスしか使用していなかった。

```ts
if (!response.ok) {
  throw new Error(`API error: ${response.status}`);
}
```

変更後は、バックエンドが返したJSONを読み取り、その`error`を使って`Error`オブジェクトを作る。

```ts
if (!response.ok) {
  const errorData: { error: string } = await response.json();
  throw new Error(errorData.error);
}
```

記録更新APIの完成形。

```ts
export const updateRecordApi = async (
  id: string,
  record: Omit<NursingRecord, "id">,
): Promise<NursingRecord> => {
  const response = await fetch(`${API_BASE}/records/${id}`, {
    method: "PUT",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(record),
  });

  if (!response.ok) {
    const errorData: { error: string } = await response.json();
    throw new Error(errorData.error);
  }

  const data: NursingRecord = await response.json();
  return data;
};
```

## 11. App.tsxでエラーメッセージを受け取る

`createRecordApi()`が投げたエラーは、`App.tsx`の`catch`で受け取る。

```ts
const addRecord = async (
  record: RecordOutput,
  patientId: string,
): Promise<NursingRecord | undefined> => {
  const recordToAdd: Omit<NursingRecord, "id"> = {
    ...record,
    patientId,
  };

  try {
    setApiError("");

    const savedRecord = await createRecordApi(recordToAdd);

    setAppData((prev) => ({
      ...prev,
      records: [...prev.records, savedRecord],
    }));

    return savedRecord;
  } catch (error) {
    console.error("看護記録追加に失敗しました", error);

    if (error instanceof Error) {
      setApiError(error.message);
    } else {
      setApiError("看護記録追加に失敗しました");
    }

    return undefined;
  }
};
```

`error instanceof Error`によって、`error`が`Error`オブジェクトか確認する。

```ts
if (error instanceof Error) {
  setApiError(error.message);
}
```

例えば、API関数が次を投げた場合、

```ts
throw new Error("Patient not found");
```

`App.tsx`では次の値を取得できる。

```ts
error.message; // "Patient not found"
```

`Error`オブジェクト以外が投げられた場合は、安全な予備メッセージを設定する。

```ts
else {
  setApiError("看護記録追加に失敗しました");
}
```

## 今日理解した処理全体

```text
Prismaでエラー発生
        ↓
バックエンドのcatchでPrismaコードを判定
        ↓
HTTPステータスと安全なJSONを返す
        ↓
フロントAPIでresponse.json()を実行
        ↓
new Error(errorData.error)を投げる
        ↓
App.tsxのcatchで受け取る
        ↓
error instanceof Errorで型を確認
        ↓
setApiError(error.message)で画面表示用に保存
```
