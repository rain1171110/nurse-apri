# 2026年8月1日 学習ログ

## 今日の学習内容

今日は、患者追加時にバックエンドで発生したエラーが、フロントの画面表示まで伝わる流れを学習した。

## バックエンドからエラーを返す

部屋番号が重複すると、Prismaが`P2002`エラーを発生させる。

```ts
if (
  typeof error === "object" &&
  error !== null &&
  "code" in error &&
  error.code === "P2002"
) {
  res.status(409).json({
    error: "This room number is already in use",
  });
  return;
}
```

`res.status(409).json()`によって、フロントへHTTPステータス`409`とJSONを返している。

```json
{
  "error": "This room number is already in use"
}
```

## patientApi.tsでエラーを受け取る

```ts
export const createPatientApi = async (
  patient: Omit<Patient, "id">,
): Promise<Patient> => {
  const response = await fetch(`${API_BASE}/patients`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(patient),
  });

  if (!response.ok) {
    const errorData: { error?: string } = await response.json();

    throw new Error(
      errorData.error ?? `API error: ${response.status}`,
    );
  }

  const data: Patient = await response.json();
  return data;
};
```

409が返ると、次の状態になる。

```ts
response.status; // 409
response.ok; // false
```

`response.ok`が`false`なので、レスポンス本文を読み取る。

```ts
const errorData: { error?: string } = await response.json();
```

`errorData`の中身は次のようになる。

```ts
{
  error: "This room number is already in use";
}
```

`{ error?: string }`は`errorData`の型であり、「省略可能な文字列型の`error`プロパティを持つオブジェクト」という意味。

```ts
type ApiErrorData = {
  error?: string;
};
```

次のコードで、取得したメッセージを持つ`Error`オブジェクトを作り、呼び出し元へ投げる。

```ts
throw new Error(
  errorData.error ?? `API error: ${response.status}`,
);
```

エラーメッセージが存在する場合は、実質的に次の処理になる。

```ts
throw new Error(
  "This room number is already in use",
);
```

`errorData.error`が存在しない場合は、`??`の右側を使用する。

```ts
throw new Error("API error: 409");
```

## App.tsxでエラーを受け取る

```tsx
const addPatient = async (
  patient: Omit<Patient, "id">,
): Promise<Patient | undefined> => {
  try {
    setApiError("");

    const savedPatient = await createPatientApi(patient);

    setAppData((prev) => ({
      ...prev,
      patients: [...prev.patients, savedPatient],
    }));

    return savedPatient;
  } catch (error) {
    console.error("患者追加に失敗しました", error);

    if (error instanceof Error) {
      setApiError(error.message);
    } else {
      setApiError("患者追加に失敗しました");
    }

    return undefined;
  }
};
```

`createPatientApi()`の中で`throw`されたErrorは、呼び出し元の`catch`に入る。

```ts
// patientApi.ts
throw new Error("This room number is already in use");

// App.tsx
catch (error) {
  // 投げられたErrorオブジェクトが入る
}
```

`error instanceof Error`は、`error`がJavaScript標準の`Error`クラスから作られたオブジェクトか確認している。

Zodのエラーかどうかを確認しているわけではない。

```ts
if (error instanceof Error) {
  setApiError(error.message);
}
```

今回は`new Error()`で作られているため、判定は`true`になる。

```ts
error.message;
// "This room number is already in use"
```

## 患者追加フォームの処理

```tsx
const handleAddPatientSubmit = async (
  data: PatientOutput,
): Promise<void> => {
  const savedPatient = await onSubmit(data);

  if (!savedPatient) {
    return;
  }

  reset();
  setShowAddForm(false);
};
```

APIに失敗すると、`addPatient()`から`undefined`が返る。

そのため、次の処理で終了する。

```tsx
if (!savedPatient) {
  return;
}
```

フォームは閉じず、入力内容も残る。

APIに成功して`Patient`が返った場合だけ、フォームをリセットして閉じる。

```tsx
reset();
setShowAddForm(false);
```

## エラーが画面へ届く流れ

```text
患者追加ボタンを押す
        ↓
App.tsxからcreatePatientApi(patient)を呼ぶ
        ↓
patientApi.tsからfetchでバックエンドへ送る
        ↓
Prismaで部屋番号の重複エラーP2002が発生
        ↓
バックエンドが409とJSONを返す
        ↓
response.json()でJSONを読み取る
        ↓
errorData.errorを取得する
        ↓
new Error(errorData.error)を作る
        ↓
throwで呼び出し元へ投げる
        ↓
App.tsxのcatch(error)が受け取る
        ↓
error instanceof Errorで確認する
        ↓
setApiError(error.message)でstateに保存する
        ↓
画面にエラーメッセージを表示する
```

## 今日理解したこと

- `res.status(409).json()`でステータスコードとJSONをフロントへ返せる
- `response.json()`でバックエンドから届いたJSONを読み取る
- `{ error?: string }`は`errorData`の型
- `?`はプロパティが存在しない場合も許可する
- `new Error(message)`でErrorオブジェクトを作る
- `throw`されたErrorは、呼び出し元の`catch`へ渡される
- `error instanceof Error`は標準のErrorオブジェクトか確認している
- `error.message`には`new Error()`へ渡した文字列が入る
- APIに失敗した場合は`undefined`を返し、患者追加フォームを閉じない
- APIに成功した場合だけ、患者をstateへ追加してフォームを閉じる
