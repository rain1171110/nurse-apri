## 1. APIエラー処理の確認

`patientApi.ts`と`recordApi.ts`では、APIから正常ではないレスポンスが返った場合に、バックエンドのエラーメッセージを取得して`Error`として投げている。

```ts
if (!response.ok) {
  const errorData: { error?: string } = await response.json();

  throw new Error(
    errorData.error ?? `API error: ${response.status}`,
  );
}
```

### 処理の流れ

```text
バックエンド
res.status(...).json({ error: "エラーメッセージ" })
    ↓
フロントエンド
response.json()
    ↓
errorData.error
    ↓
throw new Error(errorData.error)
    ↓
App.tsxのcatch
    ↓
setApiError(error.message)
    ↓
画面にエラー表示
```

患者・看護記録の追加・更新・削除について、同じ形式でエラーを受け取れるようになった。

## 3. Prismaエラー判定の共通化

これまでは、各`catch`の中で次の判定を繰り返していた。

```ts
if (
  typeof error === "object" &&
  error !== null &&
  "code" in error &&
  error.code === "P2025"
) {
  // エラー処理
}
```

重複を減らすため、Prismaエラーを判定する共通関数を作成した。

```ts
type PrismaErrorCode = "P2002" | "P2003" | "P2025";

const isPrismaError = (
  error: unknown,
  code: PrismaErrorCode,
): boolean => {
  return (
    typeof error === "object" &&
    error !== null &&
    "code" in error &&
    error.code === code
  );
};
```

各APIでは、次のように短く記述できるようになった。

```ts
if (isPrismaError(error, "P2002")) {
  res.status(409).json({
    error:
      "This room number is already in use / この部屋番号はすでに使用されています",
  });
  return;
}
```

### 使用しているPrismaエラーコード

- `P2002`：一意制約違反
- `P2003`：外部キー制約違反
- `P2025`：更新・削除対象が見つからない

## 4. `unknown`と`any`の違い

### `any`

`any`は、TypeScriptによる型確認をほぼ受けずに値を使用できる。

```ts
const showCode = (error: any) => {
  console.log(error.code);
};
```

実際には`error`が`null`などの場合でも、TypeScriptが止めてくれない可能性がある。

### `unknown`

`unknown`は、値の型を確認してから使用する必要がある。

```ts
const showCode = (error: unknown) => {
  if (
    typeof error === "object" &&
    error !== null &&
    "code" in error
  ) {
    console.log(error.code);
  }
};
```

### 今日の理解

```text
any
＝何が入っているか分からなくても、ほぼ確認せずに使用できる

unknown
＝何が入っているか分からないため、確認してから使用する
```

今回のPrismaエラー判定では、`error`の正体が確定していないため、より安全な`unknown`を使用した。

## 5. APIエラーの状態管理

`App.tsx`では、APIエラーメッセージをStateで管理している。

```tsx
const [apiError, setApiError] = useState("");
```

- `apiError`：現在のエラーメッセージ
- `setApiError`：エラーメッセージを変更する関数
- `""`：エラーがない状態

API処理を開始するときに、以前のエラーを消している。

```tsx
try {
  setApiError("");

  const savedPatient = await createPatientApi(patient);

  // 成功時の処理
}
```

エラーが発生した場合は、新しいメッセージを保存する。

```tsx
catch (error) {
  console.error("患者追加に失敗しました", error);

  if (error instanceof Error) {
    setApiError(error.message);
  } else {
    setApiError("患者追加に失敗しました");
  }

  return undefined;
}
```

## 6. MUIの`Alert`によるエラー表示

これまでの`<p>`による表示を、MUIの`Alert`へ変更した。

```tsx
{apiError && (
  <Alert severity="error" onClose={onClearApiError}>
    {apiError}
  </Alert>
)}
```

### `apiError &&`の意味

`apiError`が空文字ではない場合だけ、右側の`Alert`を表示する。

```tsx
// apiErrorが空文字の場合
apiError = "";

// Alertは表示されない
```

```tsx
// エラー文字列が入っている場合
apiError = "患者情報の追加に失敗しました";

// Alertが表示される
```

条件を明示すると、次と同じような意味になる。

```tsx
{apiError !== "" && (
  <Alert severity="error">
    {apiError}
  </Alert>
)}
```

## 7. `Alert`の各部分の役割

```tsx
<Alert severity="error" onClose={onClearApiError}>
  {apiError}
</Alert>
```

### `<Alert>`

MUIが用意しているアラート表示用コンポーネント。

### `severity="error"`

赤色のエラー用デザインとアイコンを表示する。

### `{apiError}`

Stateに保存されているエラーメッセージを表示する。

### `onClose={onClearApiError}`

Alertの閉じるボタンが押されたときに、`onClearApiError`を実行する。

MUI内部では、イメージとして次のように接続されている。

```tsx
function Alert({ onClose, children }) {
  return (
    <div>
      <span>{children}</span>
      <button onClick={onClose}>×</button>
    </div>
  );
}
```

実際のMUI内部コードはさらに複雑だが、基本的な仕組みは同じ。

### 今日の理解

```text
MUI
＝閉じるボタンの表示とクリックの検知を担当

自分のコード
＝閉じるボタンが押された後の処理を関数として渡す
```

## 8. Alertを閉じる処理の接続

`App.tsx`から、エラーを空文字にする関数を渡す。

```tsx
onClearApiError={() => setApiError("")}
```

`PatientPage.tsx`で受け取る。

```tsx
type PatientPageProps = {
  patients: Patient[];
  records: NursingRecord[];
  apiError: string;
  onClearApiError: () => void;
};
```

Alertの`onClose`へ渡す。

```tsx
<Alert
  severity="error"
  onClose={onClearApiError}
>
  {apiError}
</Alert>
```

### 全体の流れ

```text
Alertの閉じるボタンを押す
    ↓
MUIがクリックを検知
    ↓
onCloseに渡したonClearApiErrorを実行
    ↓
setApiError("")
    ↓
apiErrorが空文字になる
    ↓
apiError && の条件が成立しなくなる
    ↓
Alertが画面から消える
```
