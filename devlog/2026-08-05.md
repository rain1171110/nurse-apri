## MUIのエラー表示

```tsx
<Snackbar
  open={Boolean(apiError)}
  autoHideDuration={5000}
  onClose={onClearApiError}
  anchorOrigin={{
    vertical: "top",
    horizontal: "center",
  }}
>
  <Alert
    severity="error"
    onClose={onClearApiError}
    variant="filled"
    sx={{ width: "100%" }}
  >
    {apiError}
  </Alert>
</Snackbar>
```

### 理解したこと

```tsx
open={Boolean(apiError)}
```

`apiError`に文字列が入っていれば`true`になり、Snackbarが表示される。

```tsx
autoHideDuration={5000}
```

5秒後にSnackbarの`onClose`が呼び出される。

```tsx
const onClearApiError = (): void => {
  setApiError("");
};
```

`apiError`を空文字にすると、`Boolean(apiError)`が`false`になり、Snackbarが閉じる。

`Alert`側の`onClose`は、×ボタンを押したときに呼び出される。

## App.tsxのエラー処理共通化

以前は、各`catch`に同じ判定を書いていた。

```tsx
if (error instanceof Error) {
  setApiError(error.message);
} else {
  setApiError("患者追加に失敗しました");
}
```

共通関数を作成した。

```tsx
const getErrorMessage = (
  error: unknown,
  fallbackMessage: string,
): string => {
  if (error instanceof Error) {
    return error.message;
  } else {
    return fallbackMessage;
  }
};
```

各`catch`では、関数を呼び出すだけに変更した。

```tsx
} catch (error) {
  console.error("患者追加に失敗しました", error);
  setApiError(getErrorMessage(error, "患者追加に失敗しました"));
  return undefined;
}
```

### `error instanceof Error`の意味

```tsx
error instanceof Error
```

これは、`error`が`Error`クラスから作られたオブジェクトかを確認している。

```tsx
throw new Error("エラーメッセージ");
```

`new Error()`で作られた値なら、`error instanceof Error`は`true`になる。

確認後は、次を安全に使用できる。

```tsx
error.message
```

処理の流れ：

```text
throw new Error(...)
↓
catch(error)で受け取る
↓
error instanceof Errorで確認
↓
error.messageを返す
↓
setApiError()へ渡す
↓
Snackbarに表示する
```

## APIファイルのエラー処理共通化

患者APIと看護記録APIには、同じ処理が合計6か所あった。

```ts
if (!response.ok) {
  const errorData: { error?: string } = await response.json();
  throw new Error(errorData.error ?? `API error: ${response.status}`);
}
```

`src/api/apiError.ts`を新しく作成した。

```ts
type ApiErrorData = {
  error?: string;
};

export const throwApiError = async (
  response: Response,
): Promise<never> => {
  const errorData: ApiErrorData = await response.json();

  throw new Error(
    errorData.error ?? `API error: ${response.status}`,
  );
};
```

`Promise<never>`は、この関数が正常な値を返さず、必ずエラーを投げて終了することを表す。

### patientApi.ts

```ts
import { throwApiError } from "./apiError";
```

```ts
if (!response.ok) {
  await throwApiError(response);
}
```

### recordApi.ts

```ts
import type { NursingRecord } from "../types";
import { throwApiError } from "./apiError";

const API_BASE =
  import.meta.env.VITE_API_BASE ?? "http://localhost:3001/api";

export const createRecordApi = async (
  record: Omit<NursingRecord, "id">,
): Promise<NursingRecord> => {
  const response = await fetch(`${API_BASE}/records`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(record),
  });

  if (!response.ok) {
    await throwApiError(response);
  }

  const data: NursingRecord = await response.json();
  return data;
};

export const updateRecordApi = async (
  id: string,
  record: Omit<NursingRecord, "id">,
): Promise<NursingRecord> => {
  const response = await fetch(`${API_BASE}/records/${id}`, {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(record),
  });

  if (!response.ok) {
    await throwApiError(response);
  }

  const data: NursingRecord = await response.json();
  return data;
};

export const deleteRecordApi = async (
  id: string,
): Promise<{ id: string }> => {
  const response = await fetch(`${API_BASE}/records/${id}`, {
    method: "DELETE",
  });

  if (!response.ok) {
    await throwApiError(response);
  }

  const data: { id: string } = await response.json();
  return data;
};
```

## 今日理解したこと

- 共通処理を関数にすると、呼び出し側の重複を減らせる
- `instanceof`は、どのクラスから作られた値かを確認する
- `getErrorMessage()`は表示する文字列を選んで返す
- `setApiError()`は返された文字列をstateへ保存する
- `throwApiError()`はAPIレスポンスを読み、`Error`を投げる
- `throw`された後は、その関数の残りの処理は実行されない
- `400`・`404`・`409`には、それぞれ異なる意味がある
- 型チェック、画面確認、ビルドまで行ってからコミットする
