## 1. `Promise<never>`の理解

```ts
const throwApiError = async (
  response: Response,
): Promise<never> => {
  const errorData: { error?: string } = await response.json();

  throw new Error(
    errorData.error ?? `API error: ${response.status}`,
  );
};
```

### 学んだこと

`Promise<never>`は、この関数が正常な値を返さず、必ずエラーを投げて終了することを表す。

```ts
throw new Error(...)
```

が必ず実行されるため、この関数は正常終了しない。

`Promise<never>`を指定したことでエラーになるのではなく、もともと必ず`throw`する関数の動作を型で表している。

```text
必ずthrowする実装
    ↓
正常な戻り値が存在しない
    ↓
Promise<never>と表現できる
```

`Promise<void>`でも実行時の動作は変わらないが、意味は異なる。

```ts
Promise<void>
```

- 正常終了する可能性がある
- 正常終了しても値は返さない

```ts
Promise<never>
```

- 正常終了しない
- 必ずエラーを投げる

`Promise<never>`を明示すると、コードを読む人とTypeScriptの両方に「必ずエラーを投げる関数」という意図が伝わりやすくなる。

## 3. 患者追加時の409エラー確認

使用中の部屋番号で別の患者を追加した。

コンソールには次のエラーが表示された。

```text
患者追加に失敗しました
Error: This room number is already in use / この部屋番号はすでに使用されています
```

処理の流れは次のとおり。

```text
バックエンドが409エラーを返す
    ↓
createPatientApiがresponse.okを確認する
    ↓
throwApiErrorがErrorを投げる
    ↓
App.tsxのaddPatientにあるcatchが受け取る
    ↓
Snackbarにエラーメッセージを表示する
```

呼び出し履歴も確認できた。

```text
throwApiError
→ createPatientApi
→ addPatient
→ addPatientSubmit
→ handleAddPatientSubmit
```

また、Snackbarを閉じた後に同じ操作を繰り返し、2回目もSnackbarが表示されることを確認した。

以前発生していた「同じエラーが2回目に表示されない問題」は解消している。
