## CRUDとHTTPメソッドの復習

| CRUD   | HTTPメソッド | 操作          |
| ------ | -------- | ----------- |
| Create | `POST`   | 新しいデータを作成する |
| Read   | `GET`    | データを取得する    |
| Update | `PUT`    | 既存データを更新する  |
| Delete | `DELETE` | データを削除する    |

```text
POST   → 作る
GET    → 見る
PUT    → 直す
DELETE → 消す
```

ブラウザに表示される次のURLは、React Routerが管理する画面用URLである。

```text
http://localhost:5173/patient/:id/detail
```

患者情報を保存すると、画面の裏側で次のAPI通信が実行される。

```text
PUT http://localhost:3001/api/patients/:id
```

`PUT`はURLの一部ではなく、通信時に指定するHTTPメソッドである。実際の通信は、ブラウザの開発者ツールにあるNetworkから確認できる。

## テスト時にサーバーを起動しない設定

`index.test.ts`から`index.ts`をimportすると、`index.ts`全体が実行される。そのため、条件を付けなければテスト中も`app.listen()`が実行される。

```ts
if (process.env.NODE_ENV !== "test") {
  app.listen(PORT, () => {
    console.log(`API server running on http://localhost:${PORT}`);
  });
}
```

Vitest実行中は、次の値になる。

```ts
process.env.NODE_ENV === "test";
```

したがって、条件は`false`になり、テスト中は`app.listen()`が実行されない。

```ts
"test" !== "test";
// false
```

Supertestはポートを起動しなくても、Expressの`app`を直接テストできる。

```ts
request(app);
```

## 作成したAPI統合テスト

```ts
import { describe, expect, it } from "vitest";
import request from "supertest";
import { app } from "./index.js";

describe("POST /api/patients", () => {
  it("不正な患者データなら400を返す", async () => {
    const response = await request(app).post("/api/patients").send({
      name: "",
      room: 0,
    });

    expect(response.status).toBe(400);
    expect(response.body.error).toBe(
      "Invalid patient data / 無効な患者データ",
    );
  });
});

describe("PUT /api/patients/:id", () => {
  it("存在しない患者を更新すると404を返す", async () => {
    const response = await request(app)
      .put("/api/patients/00000000-0000-0000-0000-000000000000")
      .send({
        name: "テスト患者",
        room: 999,
      });

    expect(response.status).toBe(404);
    expect(response.body.error).toBe(
      "Patient not found / 患者が見つかりません",
    );
  });
});

describe("DELETE /api/patients/:id", () => {
  it("存在しない患者を削除すると404を返す", async () => {
    const response = await request(app).delete(
      "/api/patients/00000000-0000-0000-0000-000000000000",
    );

    expect(response.status).toBe(404);
    expect(response.body.error).toBe(
      "Patient not found / 患者が見つかりません",
    );
  });
});

describe("GET /api/patients", () => {
  it("患者一覧を取得すると200を返す", async () => {
    const response = await request(app).get("/api/patients");

    expect(response.status).toBe(200);
    expect(Array.isArray(response.body)).toBe(true);
  });
});

describe("POST /api/records", () => {
  it("不正な看護記録データなら400を返す", async () => {
    const response = await request(app)
      .post("/api/records")
      .send({});

    expect(response.status).toBe(400);
    expect(response.body.error).toBe(
      "Invalid record data / 無効な看護記録データ",
    );
  });
});

describe("DELETE /api/records/:id", () => {
  it("存在しない看護記録を削除すると404を返す", async () => {
    const response = await request(app).delete(
      "/api/records/00000000-0000-0000-0000-000000000000",
    );

    expect(response.status).toBe(404);
    expect(response.body.error).toBe(
      "Record not found / 看護記録が見つかりません",
    );
  });
});
```

## Supertestの処理

```ts
const response = await request(app)
  .post("/api/patients")
  .send({
    name: "",
    room: 0,
  });
```

それぞれの役割は次のとおり。

```text
request(app)          → テストするExpressアプリを指定
.post("/api/patients") → POSTリクエストを送る
.send({...})           → リクエスト本文を送る
await                  → APIの結果を待つ
response               → APIから返された結果
```

## expectとtoBe

```ts
expect(response.status).toBe(400);
```

`toBe()`は型だけではなく、値が完全に一致するかを確認する。

```ts
"患者が見つかりません" === "存在しない患者データ";
// false
```

両方とも`string`型だが、文字列の内容が違うため一致しない。

APIが実際に返す文字列が次の場合、

```ts
"Patient not found / 患者が見つかりません"
```

テストの期待値も完全に同じ文字列にする必要がある。

## Array.isArray

```ts
Array.isArray(response.body);
```

`Array.isArray()`は、JavaScriptにもともと用意されている機能で、値が配列か確認する。

```ts
Array.isArray([]);
// true

Array.isArray([{ name: "鈴木次郎" }]);
// true

Array.isArray({ name: "鈴木次郎" });
// false
```

今回のテストでは、患者一覧APIのレスポンスが配列になっているか確認した。

```ts
expect(Array.isArray(response.body)).toBe(true);
```

## PrismaローカルDBの接続エラー

テスト中、データベースを使う4件で次のエラーが発生した。

```text
Connection terminated unexpectedly
ECONNREFUSED
```

原因はテストコードではなく、PrismaのローカルPostgreSQLが中途半端に停止していたことだった。

```text
Prismaのnode.exe → 残っていた
51213            → 停止
51214            → 停止（メインDB）
51215            → 起動中
```

そのため、DBへ接続する処理は`500`になった。一方、ZodがDB接続前に`400`を返すテストは成功していた。

状態確認には次のコマンドを使用した。

```bash
npx prisma dev ls
```

```text
default  error
```

残っていたPrismaプロセスを終了した。

```bash
taskkill //PID 27712 //F
```

その後、PrismaのローカルDBを再起動した。

```bash
npx prisma dev start default
```

正常に復旧すると、次の3つが起動した。

```text
51213 → Prisma HTTP
51214 → メインのPostgreSQL
51215 → Shadow DB
```

最終的にテストを再実行し、6件すべて成功した。

```bash
npx vitest run server/index.test.ts
```

```text
Test Files  1 passed
Tests       6 passed
```

## 今日理解できたこと

* CRUDと`GET`・`POST`・`PUT`・`DELETE`の対応
* 画面用URLとAPI用URLの違い
* HTTPメソッドはブラウザのURL欄には表示されないこと
* Networkから実際の`PUT`通信を確認する方法
* importすると、import先のファイル全体が実行されること
* `process.env.NODE_ENV`で現在の実行環境を確認できること
* Supertestの`request()`・`.post()`・`.send()`の役割
* `toBe()`は型だけでなく値の完全一致を確認すること
* `Array.isArray()`で配列か確認できること
* ZodのバリデーションエラーはDB接続前に返されること
* `500`エラーが必ずしもテストコードの間違いとは限らないこと
* PrismaローカルDBの状態確認と再起動方法
