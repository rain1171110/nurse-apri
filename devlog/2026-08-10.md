## 2. Userモデルの追加

`prisma/schema.prisma`へ、ログインユーザーを保存するモデルを追加した。

```prisma
model User {
  id           String   @id @default(uuid())
  email        String   @unique
  passwordHash String
  createdAt    DateTime @default(now())
}
```

ポイント：

* `email`は`@unique`で重複登録を禁止する
* 生のパスワードはDBへ保存しない
* `bcryptjs`で変換した`passwordHash`だけを保存する
* `createdAt`は登録日時を自動保存する

## 4. ユーザー登録APIの作成

`server/index.ts`へ必要なimportを追加した。

```ts
import bcrypt from "bcryptjs";
import {
  createPatientSchema,
  createRecordSchema,
  registerSchema,
  type CreatePatientBody,
  type CreateRecordBody,
  type RegisterBody,
} from "./schema.js";
```

ユーザー登録APIを追加した。

```ts
app.post<{}, {}, RegisterBody>("/api/auth/register", async (req, res) => {
  try {
    const result = registerSchema.safeParse(req.body);

    if (!result.success) {
      res.status(400).json({
        error: "Invalid registration data / 無効な登録データ",
        details: result.error.flatten(),
      });
      return;
    }

    const { email, password } = result.data;

    const passwordHash = await bcrypt.hash(password, 10);

    const newUser = await prisma.user.create({
      data: {
        email,
        passwordHash,
      },
    });

    res.status(201).json({
      id: newUser.id,
      email: newUser.email,
      createdAt: newUser.createdAt,
    });
  } catch (error) {
    if (isPrismaError(error, "P2002")) {
      res.status(409).json({
        error:
          "Email is already registered / このメールアドレスは登録済みです",
      });
      return;
    }

    console.error("POST /api/auth/register", error);

    res.status(500).json({
      error: "Failed to register user / ユーザー登録に失敗しました",
    });
  }
});
```

処理の流れ：

```text
email・passwordを受信
        ↓
Zodで入力を検証
        ↓
passwordをbcryptでハッシュ化
        ↓
email・passwordHashをDBへ保存
        ↓
passwordHashを除外して201を返す
```

レスポンスへ返してよい項目：

```text
id
email
createdAt
```

返してはいけない項目：

```text
password
passwordHash
```

`passwordHash`は元のパスワードへ簡単に戻せないが、漏れると総当たり攻撃に利用される可能性がある。そのためDB内だけで扱い、ブラウザへ返さない。

## 5. エラー処理

登録APIでは次の結果を返す。

```text
不正な入力       → 400 Bad Request
登録成功         → 201 Created
メール重複       → 409 Conflict
予期しないエラー → 500 Internal Server Error
```

`email`には`@unique`があるため、同じメールアドレスを保存するとPrismaの`P2002`が発生する。

## 6. npmとnpxの違い

次のコマンドは成功した。

```bash
npx tsc --project server/tsconfig.json --noEmit
```

`npx`は、プロジェクトにインストールされている`tsc`を探して直接実行する。

一方、次のコマンドは使用できない。

```bash
npm tsc --project server/tsconfig.json --noEmit
```

`npm`には`tsc`という標準コマンドがないため、`Unknown command: "tsc"`になる。

## 7. tsconfig.jsonの役割

バックエンドでは`server/tsconfig.json`を使用する。

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["./**/*.ts"],
  "exclude": ["./generated"]
}
```

重要な設定：

* `include`：`server`以下のすべての`.ts`ファイルを検査
* `exclude`：Prismaの自動生成コードを検査対象から除外
* `strict`：厳しい型チェックを有効にする
* `noEmit`：JavaScriptを生成せず型チェックだけ行う

## 今日の理解

* パスワードはそのままDBへ保存しない
* `bcrypt.hash()`で作った`passwordHash`を保存する
* `passwordHash`もAPIレスポンスへ含めない
* `safeParse()`成功後のデータは`result.data`から取得する
* Prismaの`data`には、保存項目を1つのオブジェクトにまとめて渡す
* `@unique`の重複は`P2002`になり、APIでは`409 Conflict`を返す
* `npx tsc`は保存されたTypeScriptファイル全体を型チェックする
* 新しい技術でも完成コードのコピーだけにせず、既存コードを参考に自分で書く
