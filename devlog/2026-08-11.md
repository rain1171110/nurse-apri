## 4. PrismaとPostgreSQLの同期確認

```bash
npx prisma db push
```

結果：

```text
The database is already in sync with the Prisma schema.
```

認証に使用する`User`モデルは、すでにPostgreSQLへ反映されていた。

```prisma
model User {
  id           String   @id @default(uuid())
  email        String   @unique
  passwordHash String
  createdAt    DateTime @default(now())
}
```

### 各項目の役割

- `id`：ユーザーを識別するUUID
- `email`：ログインに使用するメールアドレス
- `@unique`：同じメールアドレスの重複登録を防止
- `passwordHash`：ハッシュ化したパスワードを保存
- `createdAt`：登録日時を自動保存

パスワードは元の文字列のままDBへ保存しない。

ログイン処理では新しいユーザーを作らないため、`bcrypt.hash()`と`prisma.user.create()`は使用しない。

## 9. メールアドレスによるユーザー検索

メールアドレスには`@unique`が付いているため、`findMany()`ではなく`findUnique()`を使用する。

```ts
const user = await prisma.user.findUnique({
  where: {
    email,
  },
});
```

### `findMany()`との違い

```text
findMany()
該当なし → []
該当あり → [ユーザー]

findUnique()
該当なし → null
該当あり → ユーザー
```

ユーザーが見つからなければ`401 Unauthorized`を返す。

```ts
if (!user) {
  res.status(401).json({
    error:
      "Invalid email or password / メールアドレスまたはパスワードが正しくありません",
  });
  return;
}
```

## 10. パスワードの比較

ログインではパスワードを新しくハッシュ化するのではなく、入力されたパスワードとDBの`passwordHash`を比較する。

```ts
const isPasswordValid = await bcrypt.compare(
  password,
  user.passwordHash,
);
```

結果：

```text
一致する   → true
一致しない → false
```

一致しない場合は`401`を返す。

```ts
if (!isPasswordValid) {
  res.status(401).json({
    error:
      "Invalid email or password / メールアドレスまたはパスワードが正しくありません",
  });
  return;
}
```

ユーザーが存在しない場合とパスワードが違う場合で、同じエラー文を使用する。

エラー文を分けると、第三者に「このメールアドレスは登録されている」と推測される可能性があるためである。

## 11. JWTとCookieの違い

役割を混同していたため整理した。

```text
jsonwebtoken
→ ログイン済みであることを示すトークンを作成・検証する

cookie-parser
→ ブラウザから送られたCookieをExpressで読み取る
```

`jsonwebtoken`は、`jwt`という名前で読み込む。

```ts
import jwt from "jsonwebtoken";
```

## 12. JWT_SECRETの作成

トークンの偽造を防ぐため、ランダムな秘密鍵を生成した。

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

生成した値を`.env`へ追加した。

```env
JWT_SECRET=生成した秘密鍵
```

秘密鍵はGitHubや学習ログへ貼らない。

`.env`が`.gitignore`へ登録されていることも確認した。

### 環境変数の型

`.env`では引用符を書かなくても文字列として読み込まれる。

```ts
process.env.JWT_SECRET
// string | undefined
```

環境変数が設定されていない可能性があるため、型には`undefined`も含まれる。

## 今日理解したこと

- 登録では`bcrypt.hash()`を使用する
- ログインでは`bcrypt.compare()`を使用する
- `findUnique()`は一意なデータを1件検索する
- 存在しないユーザーを検索すると`null`になる
- 認証失敗時は`401 Unauthorized`を返す
- メールアドレスとパスワードのエラー文を同じにすると、登録状況を推測されにくい
- JWTはトークンを作成・検証する
- Cookieは作成したトークンをブラウザとの間で受け渡す
- 環境変数は`string | undefined`になる
- 秘密鍵がない状態ではAPIサーバーを起動させないようにする
- `try`は通常処理、`catch`はDB接続失敗などの予期しない例外を扱う
