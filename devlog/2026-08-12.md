# 学習ログ：JWTログインとHttpOnly Cookieの動作確認

## 今日の学習内容

今日は、ユーザー登録からログイン、JWTを保存したCookieの確認まで行った。

### 1. CORSをCookie通信に対応

React（5173番）からExpress（3001番）へCookieを含む通信ができるように設定した。

```ts
app.use(
  cors({
    origin: "http://localhost:5173",
    credentials: true,
  }),
);
```

- `origin`：通信を許可するフロントエンドのURL
- `credentials: true`：Cookieの送受信を許可する
- 変更後はAPIサーバーの再起動が必要

患者APIへアクセスし、ステータス`200`を確認できた。

---

## 2. テストユーザーの登録

ChromeのConsoleから登録APIを呼び出した。

```js
fetch("http://" + "localhost:3001/api/auth/register", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    email: "test2@example.com",
    password: "testpass0000",
  }),
})
  .then(async (response) => {
    const data = await response.json();

    console.log("ステータス:", response.status);
    console.log("レスポンス:", data);
  })
  .catch((error) => console.error(error));
```

### 実行結果

```text
ステータス: 201
```

`201 Created`が返り、PostgreSQLの`User`テーブルへ新しいユーザーを登録できた。

保存される主な情報：

- `id`：自動生成されたユーザーID
- `email`：メールアドレス
- `passwordHash`：bcryptでハッシュ化されたパスワード
- `createdAt`：登録日時

実際のパスワードはデータベースへ保存せず、`passwordHash`として保存する。

## 3. ログインAPIの確認

登録時と同じメールアドレス・パスワードを使ってログインした。

```js
fetch("http://" + "localhost:3001/api/auth/login", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  credentials: "include",
  body: JSON.stringify({
    email: "test2@example.com",
    password: "testpass0000",
  }),
})
  .then(async (response) => {
    const data = await response.json();

    console.log("ステータス:", response.status);
    console.log("レスポンス:", data);
  })
  .catch((error) => console.error(error));
```

### 実行結果

```text
ステータス: 200
レスポンス: {
  success: true,
  message: "ログイン成功",
  user: { ... }
}
```

ログイン成功後、ChromeのApplicationタブで`token` Cookieが保存されていることを確認した。

### Cookieの確認項目

| 項目     | 確認内容         |
| -------- | ---------------- |
| Name     | `token`          |
| Value    | JWTの長い文字列  |
| HttpOnly | 有効             |
| Secure   | 開発環境では無効 |
| SameSite | `Strict`         |

## 4. `fetch()`の各設定

```js
fetch("APIのURL", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  credentials: "include",
  body: JSON.stringify({
    // APIへ送るデータ
  }),
});
```

| コード                   | 役割                                     |
| ------------------------ | ---------------------------------------- |
| `fetch()`                | APIへリクエストを送る                    |
| `method: "POST"`         | データを送信する                         |
| `Content-Type`           | JSONを送ることを伝える                   |
| `JSON.stringify()`       | JavaScriptの値をJSON文字列へ変換する     |
| `credentials: "include"` | Cookieを送受信する                       |
| `response.json()`        | JSONレスポンスをJavaScriptの値へ変換する |
| `.catch()`               | 通信自体の失敗を処理する                 |

登録APIではCookieを受け取らないため、今回は`credentials: "include"`が不要だった。

ログインAPIではJWTをCookieとして受け取るため必要になる。

## 5. HTTPステータスの整理

| ステータス | 意味                                       |
| ---------- | ------------------------------------------ |
| `200`      | ログイン成功                               |
| `201`      | ユーザー登録成功                           |
| `400`      | メール形式やパスワードの長さなどが不正     |
| `401`      | メールアドレスまたはパスワードが一致しない |
| `409`      | 同じメールアドレスがすでに登録されている   |

## 6. XSSとCookieについて

XSSは、攻撃者が用意したJavaScriptを、別の利用者のブラウザ上で実行させる攻撃。

例えば、ユーザーが入力した看護記録をHTMLとして直接表示すると危険になる可能性がある。

```js
element.innerHTML = record.content;
```

`innerHTML`は入力内容をHTMLとして解析する。

通常は、文字として表示する`textContent`を使用する。

```js
element.textContent = record.content;
```

Reactでは、次の通常表示なら入力内容が基本的に文字として扱われる。

```tsx
<p>{record.content}</p>
```

次の書き方は、入力内容をHTMLとして挿入するため慎重に扱う。

```tsx
<div dangerouslySetInnerHTML={{ __html: record.content }} />
```

今回のJWT Cookieには`httpOnly: true`を設定しているため、JavaScriptからJWTを読み取れない。

```js
document.cookie;
```

ただし、`HttpOnly`はXSSそのものを防ぐ機能ではない。XSSが起きた場合に、JWTそのものを盗まれる危険を減らす設定である。

## 7. `cookie-session`との違い

今回は`cookie-session`を追加しない。

現在使用しているもの：

- `jsonwebtoken`：JWTを作成・検証する
- `cookie-parser`：受信したCookieをExpressで読み取る
- `server/auth.ts`：JWTを検証する自作の認証ミドルウェア

今後の認証処理：

```text
ブラウザからAPIリクエスト
        ↓
Cookie内のtokenをcookie-parserが読み取る
        ↓
auth.tsの認証ミドルウェア
        ↓
jsonwebtokenでJWTを検証
        ↓
有効：next()でAPI処理へ進む
無効：401を返す
```

---

## 今日の理解

- テストユーザーは`schema.prisma`へ直接書かず、登録APIを通してPostgreSQLへ保存する
- 登録時のパスワードはbcryptでハッシュ化して保存する
- ログイン成功時にJWTを作成し、HttpOnly Cookieとしてブラウザへ送る
- Cookieを使う異なるオリジン間の通信では、CORSと`credentials`の設定が必要
- Reactの通常表示は、ユーザー入力をHTMLとして直接実行しない
- `innerHTML`は入力内容をHTMLとして解析するため、ユーザー入力には基本的に使用しない
- コードをすべて暗記するのではなく、既存コードを目的に合わせて変更し、各行の必要性を判断できるようになることが重要
