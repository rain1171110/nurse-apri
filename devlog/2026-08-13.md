### 2. 認証ミドルウェアの作成

`server/auth.ts`に`requireAuth`を作成した。

```ts
import type { Request, Response, NextFunction } from "express";
import jwt from "jsonwebtoken";

const JWT_SECRET = process.env.JWT_SECRET;

if (!JWT_SECRET) {
  throw new Error("JWT_SECRET is not defined");
}

export const requireAuth = (
  req: Request,
  res: Response,
  next: NextFunction,
) => {
  try {
    const token = req.cookies.token;

    if (!token) {
      res.status(401).json({
        error: "Authentication required / 認証が必要です",
      });
      return;
    }

    jwt.verify(token, JWT_SECRET);
    next();
  } catch (error) {
    res.status(401).json({
      error:
        "Invalid or expired token / トークンが無効または期限切れです",
    });
    return;
  }
};
```

### 処理の流れ

1. `req.cookies.token`でブラウザから送られたJWTを取得する
2. JWTがなければ`401`を返す
3. `jwt.verify()`でJWTを検証する
4. JWTが有効なら`next()`で次のAPI処理へ進む
5. JWTが不正・改ざん済み・期限切れなら`catch`で`401`を返す

### `req`・`res`・`next`の役割

- `req`：ブラウザからサーバーへ入ってきた情報を読む
- `res`：サーバーからブラウザへ結果を返す
- `next`：サーバー内の次の処理へ進む

覚え方：

```text
reqで受け取る
resで返す
nextで次へ進む
```

### 3. JWTの作成と検証の違い

ログイン成功時は、`index.ts`でJWTを作成する。

```ts
const token = jwt.sign({ userId: user.id }, JWT_SECRET, {
  expiresIn: "1h",
});
```

作成したJWTをCookieとしてブラウザへ返す。

```ts
res.cookie("token", token, {
  secure: process.env.NODE_ENV === "production",
  httpOnly: true,
  sameSite: "strict",
});
```

保護されたAPIにアクセスするときは、`auth.ts`で受け取ったJWTを検証する。

```ts
jwt.verify(token, JWT_SECRET);
```

役割の違い：

```text
jwt.sign()   → JWTを作成する
jwt.verify() → 受け取ったJWTを検証する
```

`secure`、`httpOnly`、`sameSite`はCookieの扱い方を決める設定であり、`jwt.verify()`で検証する対象ではない。

### 6. 患者・看護記録APIを認証で保護

患者情報や看護記録を扱うAPIに`requireAuth`を追加した。

```ts
app.get("/api/patients", requireAuth, async (req, res) => {
  // 患者一覧取得処理
});
```

処理順：

```text
APIへのリクエスト
    ↓
requireAuth
    ↓
JWTが有効ならnext()
    ↓
本来のAPI処理
```

認証を追加したAPI：

- `GET /api/data`
- `GET /api/patients`
- `POST /api/patients`
- `POST /api/records`
- `PUT /api/patients/:id`
- `PUT /api/records/:id`
- `DELETE /api/patients/:id`
- `DELETE /api/records/:id`

認証を付けていないAPI：

- `POST /api/auth/register`
- `POST /api/auth/login`

ユーザー登録とログインは、ログイン前に利用するため認証を付けない。

### 7. ブラウザから認証の動作確認

ログインAPIを実行した。

```js
fetch("http://localhost:3001/api/auth/login", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  credentials: "include",
  body: JSON.stringify({
    email: "test2@example.com",
    password: "testpass0000",
  }),
})
  .then(async (response) => {
    const data = await response.json();

    console.log("ステータス:", response.status);
    console.log("レスポンス:", data);
  })
  .catch((error) => console.error(error));
```

結果：

```text
ステータス: 200
レスポンス: ログイン成功
```

ログイン後、Cookieを付けて患者一覧APIへアクセスした。

```js
fetch("http://localhost:3001/api/patients", {
  method: "GET",
  credentials: "include",
})
  .then(async (response) => {
    const data = await response.json();

    console.log("ステータス:", response.status);
    console.log("レスポンス:", data);
  })
  .catch((error) => console.error(error));
```

Cookieがある場合の結果：

```text
ステータス: 200
患者一覧6件を取得
```

処理の流れ：

```text
credentials: "include"でCookieを送信
    ↓
requireAuthがCookieからJWTを取得
    ↓
jwt.verify()で検証
    ↓
next()で患者一覧APIへ進む
    ↓
患者一覧を返す
```

Cookieを削除して同じAPIへアクセスした結果：

```text
ステータス: 401
Authentication required / 認証が必要です
```

これにより、`requireAuth`が正しく動いていることを確認できた。

## テストが失敗した理由

既存のテストは、有効なJWT Cookieを送信していない。

認証追加前：

```text
テストからAPIへアクセス
    ↓
直接API処理へ進む
    ↓
200・400・404などを返す
```

認証追加後：

```text
テストからCookieなしでAPIへアクセス
    ↓
requireAuthが実行される
    ↓
JWTがないため401を返す
    ↓
本来のAPI処理まで進まない
```

APIが壊れたのではなく、既存テストが新しい認証仕様に対応していないことが原因。

## 今日理解したこと

- Cookieを受け取るときは`req.cookies`を使用する
- Cookieをブラウザへ返すときは`res.cookie()`を使用する
- `jwt.sign()`はJWTを作成する
- `jwt.verify()`はJWTを検証する
- JWTがない場合は`401`を返す
- JWTが有効なら`next()`で次の処理へ進む
- JWTが不正または期限切れの場合、`jwt.verify()`はエラーを投げる
- `try...catch`でJWTの検証エラーを処理できる
- APIに認証を追加すると、既存テストにも認証情報が必要になる
- テストの失敗は、必ずしもAPIの不具合を意味するわけではない
