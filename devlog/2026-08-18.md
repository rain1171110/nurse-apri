# 2026年8月18日 学習ログ

## 今日の目標

JWT認証を追加したことで、既存のAPIテストがすべて401になる問題に対応する。

## 発生していた問題

`requireAuth` を患者・看護記録APIへ追加した後、`server/index.test.ts` の10件がすべて失敗した。

```text
Expected: 400・404・200
Received: 401
```

テストではログインせずにAPIへリクエストしていたため、目的の処理より先に `requireAuth` で止まっていた。

## 原因

`requireAuth` は、リクエストのCookieからJWTを取得する。

```ts
const token = req.cookies.token;

if (!token) {
  res.status(401).json({
    error: "Authentication required / 認証が必要です",
  });
  return;
}
```

しかし、これまでのテストは通常の `request(app)` を使っていた。

```ts
request(app).get("/api/patients");
```

この方法ではログインCookieを保持していないため、すべて401になっていた。

## 認証処理の流れ

1. テストユーザーを登録する
2. 登録したユーザーでログインする
3. ログインAPIがJWTを作成する
4. JWTをCookieへ入れて返す
5. Supertestの`agent`がCookieを保存する
6. 各APIテストでも同じ`agent`を使う
7. `requireAuth`がCookie内のJWTを検証する
8. 認証成功後、本来テストしたい処理へ進む

## Cookieに関する役割の違い

### `res.cookie()`

ログイン成功時に、サーバーからJWT Cookieを返す。

```ts
res.cookie("token", token, {
  secure: process.env.NODE_ENV === "production",
  httpOnly: true,
  sameSite: "strict",
});
```

### `cookie-parser`

リクエストで送られてきたCookieを、サーバー側で読み取れるようにする。

```ts
const token = req.cookies.token;
```

`cookie-parser`がCookieを保存するわけではない。

### `request.agent(app)`

Supertest側でCookieを保持し、次回以降のリクエストにも付けて送る。

```ts
const agent = request.agent(app);
```

## 今日追加したテスト準備

```ts
import { beforeAll, describe, expect, it } from "vitest";
import request from "supertest";
import { app } from "./index.js";

const agent = request.agent(app);

const testUser = {
  email: `test-${Date.now()}@example.com`,
  password: "test-password",
};

beforeAll(async () => {
  await agent.post("/api/auth/register").send(testUser);

  await agent.post("/api/auth/login").send(testUser);
});
```

`Date.now()`をメールアドレスへ入れることで、テストを実行するたびに異なるメールアドレスを作成し、登録済みメールアドレスによる409エラーを避ける。

## 各テストの変更

変更前：

```ts
const response = await request(app).get("/api/patients");
```

変更後：

```ts
const response = await agent.get("/api/patients");
```

`agent`はすでに`app`を受け取っているため、次の書き方は使用しない。

```ts
request(agent).get("/api/patients");
```

正しくは次の形になる。

```ts
agent.get("/api/patients");
agent.post("/api/patients");
agent.put("/api/patients/:id");
agent.delete("/api/patients/:id");
```

## 今日理解したこと

- 認証を追加すると、既存テストにも認証対応が必要になる
- 401は目的のAPI処理より前に`requireAuth`で止まったことを表す
- JWTはテスト側で直接作らず、ログインAPIに作成してもらう
- `cookie-parser`はCookieの保存ではなく、受信したCookieの解析を担当する
- Supertestの`agent`はログインCookieを保持できる
- 登録・ログインAPIには`requireAuth`を付けない
- 患者・看護記録APIには`requireAuth`を付けて保護する
