### 1. 認証済み状態でAPIテストを実行

Supertestの`agent`を使い、テスト開始前にユーザー登録とログインを実行した。

```ts
import { beforeAll, describe, expect, it } from "vitest";
import request from "supertest";
import { app } from "./index.js";

const agent = request.agent(app);

const testUser = {
  email: `test-${Date.now()}@example.com`,
  password: "test-password",
};

beforeAll(async () => {
  const registerResponse = await agent
    .post("/api/auth/register")
    .send(testUser);

  expect(registerResponse.status).toBe(201);

  const loginResponse = await agent
    .post("/api/auth/login")
    .send(testUser);

  expect(loginResponse.status).toBe(200);
});
```

テスト結果：

```text
Test Files  1 passed (1)
Tests       10 passed (10)
```

### 2. Supertestとagentの役割を確認

```ts
const agent = request.agent(app);
```

このコードは、Expressの`app`へリクエストを送れて、Cookieを保持できるテスト用オブジェクトを作成している。

この時点では、まだAPI通信は発生していない。

実際の通信は、次のようにHTTPメソッドとAPIのパスを指定したときに行われる。

```ts
await agent.get("/api/patients");
```

それぞれの役割：

- `agent`：Cookieを保持しながらリクエストを送るオブジェクト
- `.get()`：GETメソッドでリクエストする
- `"/api/patients"`：リクエスト先のAPIパス
- `await`：レスポンスが返るまで待つ

ログイン時にサーバーから返された認証Cookieを`agent`が保存する。

```ts
await agent
  .post("/api/auth/login")
  .send(testUser);
```

その後も同じ`agent`を使用することで、保存したCookieが各リクエストへ自動的に付けられる。

```ts
await agent.get("/api/patients");
await agent.post("/api/patients");
await agent.get("/api/data");
```

Cookieによって認証を無効化しているのではなく、毎回`requireAuth`でJWTを検証し、正しいCookieがあるため認証を通過できている。

### 3. フロント側のAPI通信でCookieを送信

ブラウザからバックエンドへ認証Cookieを送るため、各`fetch()`へ次の設定を追加した。

```ts
credentials: "include",
```

アプリデータ取得API：

```ts
export const fetchAppData = async (): Promise<AppData> => {
  const response = await fetch(`${API_BASE}/data`, {
    credentials: "include",
  });

  if (!response.ok) {
    throw new Error(`API error:${response.status}`);
  }

  const data: AppData = await response.json();
  return data;
};
```

患者API：

```ts
const response = await fetch(`${API_BASE}/patients`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(patient),
  credentials: "include",
});
```

看護記録API：

```ts
const response = await fetch(`${API_BASE}/records`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(record),
  credentials: "include",
});
```

`POST`だけでなく、患者・看護記録の`PUT`と`DELETE`にも同じ設定を追加した。

### 4. テストとブラウザのCookie送信の違い

テストでは、Supertestの`agent`がCookieを保存して送信する。

```ts
const agent = request.agent(app);
```

ブラウザでは、ログイン時にCookieを保存し、`credentials: "include"`によってAPIへ送信する。

```ts
fetch(url, {
  credentials: "include",
});
```

`testUser`はテスト専用であり、実際のフロント画面へ渡されるものではない。

### 5. ログイン画面の土台を作成

`src/LoginPage.tsx`を新しく作成した。

```tsx
import type { FormEvent } from "react";

export default function LoginPage() {
  function handleSubmit(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="email">メールアドレス</label>
      <input id="email" name="email" type="email" />

      <label htmlFor="password">パスワード</label>
      <input id="password" name="password" type="password" />

      <button type="submit">ログインボタン</button>
    </form>
  );
}
```

`e.preventDefault()`によって、フォーム送信時にページが再読み込みされるのを防止している。

```ts
function handleSubmit(e: FormEvent<HTMLFormElement>) {
  e.preventDefault();
}
```

### 7. Gitの操作を復習

`git status`は現在の状態を確認するだけで、変更はステージされない。

```bash
git status
```

`git add`では、コミットへ含めるファイルを指定する必要がある。

```bash
git add server/index.test.ts src/App.tsx src/api/appDataApi.ts src/api/patientApi.ts src/api/recordApi.ts src/LoginPage.tsx
```

すべての変更をステージする場合は、次のコマンドを使用できる。

```bash
git add .
```

ただし、関係のない変更まで含めないように、先に`git status`で確認する。

基本的な流れ：

```text
ファイルを変更
  ↓
git statusで確認
  ↓
git addでコミット対象を選択
  ↓
git statusで再確認
  ↓
git commitで履歴に保存
```

今回のコミット：

```bash
git commit -m "認証Cookie対応とログイン画面の土台を追加"
```

## 今日理解したこと

- SupertestはテストコードからExpress APIへリクエストを送るための道具
- `request.agent(app)`だけではAPI通信は発生しない
- `agent.get()`や`agent.post()`を実行するとAPI通信が行われる
- 同じ`agent`を使うと、ログインで受け取ったCookieを次のリクエストにも引き継げる
- ブラウザの`fetch()`では、Cookie送信のために`credentials: "include"`が必要
- `testUser`はテスト専用であり、実際のブラウザのユーザーとは別
- `git status`は確認、`git add`はコミット対象の選択、`git commit`は履歴への保存
