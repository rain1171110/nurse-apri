## 実装したコード

### `src/api/authApi.ts`

```ts
import { throwApiError } from "./apiError";

const API_BASE =
  import.meta.env.VITE_API_BASE ?? "http://localhost:3001/api";

type LoginData = {
  email: string;
  password: string;
};

export const loginApi = async (
  receiveLogin: LoginData,
): Promise<void> => {
  const response = await fetch(`${API_BASE}/auth/login`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(receiveLogin),
    credentials: "include",
  });

  if (!response.ok) {
    await throwApiError(response);
  }
};
```

### `src/LoginPage.tsx`

```tsx
import { useState, type FormEvent } from "react";
import { useNavigate } from "react-router-dom";
import { loginApi } from "./api/authApi";

export default function LoginPage() {
  const navigate = useNavigate();
  const [apiError, setApiError] = useState("");

  async function handleSubmit(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();

    const formData = new FormData(e.currentTarget);
    const email = String(formData.get("email"));
    const password = String(formData.get("password"));

    const loginData = {
      email,
      password,
    };

    try {
      setApiError("");
      await loginApi(loginData);
      navigate("/");
    } catch (error) {
      console.error("ログインに失敗しました", error);

      if (error instanceof Error) {
        setApiError(error.message);
      } else {
        setApiError("ログインに失敗しました");
      }
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      {apiError && <p>{apiError}</p>}

      <label htmlFor="email">メールアドレス</label>
      <input id="email" name="email" type="email" />

      <label htmlFor="password">パスワード</label>
      <input id="password" name="password" type="password" />

      <button type="submit" className="btn-primary">
        ログインボタン
      </button>
    </form>
  );
}
```

## 処理の流れ

```text
ログインフォームを送信
        ↓
handleSubmitが実行される
        ↓
FormDataでemailとpasswordを取得
        ↓
loginDataにまとめる
        ↓
loginApi(loginData)を実行
        ↓
POST /api/auth/loginへ送信
        ↓
成功：JWTをCookieに保存
        ↓
navigate("/")で患者一覧へ移動
```

ログインに失敗した場合は、`loginApi`から投げられたエラーを`catch`で受け取る。

```text
ログインAPIが400または401を返す
        ↓
throwApiErrorがErrorを投げる
        ↓
LoginPageのcatchへ移動
        ↓
error.messageをapiErrorへ保存
        ↓
画面上にエラーメッセージを表示
```

## 学んだこと

### `e`と`e.currentTarget`

```ts
async function handleSubmit(e: FormEvent<HTMLFormElement>)
```

`e`は、フォームが送信されたときにReactから渡されるイベント情報。

```ts
e.currentTarget
```

`e.currentTarget`は、今回`handleSubmit`を実行した`form`要素を表す。

```ts
const formData = new FormData(e.currentTarget);
```

これにより、送信されたフォームの入力値をまとめて取得できる。

---

### `FormData.get()`と`name`の関係

```tsx
<input name="email" />
<input name="password" />
```

入力欄の`name`を指定して値を取り出す。

```ts
formData.get("email");
formData.get("password");
```

対応関係は次のとおり。

```text
name="email"    → formData.get("email")
name="password" → formData.get("password")
```

`formData.get()`は`null`を返す可能性があるため、今回は`String()`で文字列に変換した。

```ts
const email = String(formData.get("email"));
const password = String(formData.get("password"));
```

---

### API処理を別ファイルに分ける理由

`LoginPage.tsx`は、フォームの入力値の取得や画面表示を担当する。

`authApi.ts`は、バックエンドとの通信を担当する。

```text
LoginPage.tsx
入力値を取得する
        ↓
loginApi(loginData)
        ↓
authApi.ts
fetchでバックエンドへ送信する
```

`LoginPage.tsx`で再び`fetch`を書く必要はない。

---

### `navigate("/")`の意味

```ts
navigate("/");
```

ログイン成功後に患者一覧ページへ移動する。

患者カードの処理では、`map`内に`patient`が存在するため、患者IDを使用できる。

```tsx
onClick={() => navigate(`/patient/${patient.id}`)}
```

一方、ログイン画面では患者を選択していないため、`patient.id`は使用しない。

```text
/login
   ↓ ログイン成功
/
   ↓ 患者カードをクリック
/patient/:id
```

---

### 条件付きエラー表示

```tsx
{apiError && <p>{apiError}</p>}
```

`apiError`に文字列が入っているときだけ、`<p>`を表示する。

```text
apiErrorが空文字
→ 何も表示しない

apiErrorにエラー文が入っている
→ エラー文を表示する
```

---

### `error instanceof Error`

`catch`で受け取る`error`は、必ず`Error`型とは限らない。

そのため、`Error`オブジェクトであることを確認してから`message`を使用する。

```ts
if (error instanceof Error) {
  setApiError(error.message);
} else {
  setApiError("ログインに失敗しました");
}
```

---

### 400と401の違い

短すぎるパスワードなど、入力形式がログインスキーマに合わない場合は400が返る。

```text
Invalid login data / 無効なログインデータ
```

入力形式は正しいが、メールアドレスまたはパスワードが一致しない場合は401が返る。

```text
Invalid email or password
```

```text
400 Bad Request
→ 送信データの形式が不正

401 Unauthorized
→ 認証情報が正しくない、またはログインが必要
```

## 次回の学習

未ログイン状態で患者一覧を開いた場合に、自動的に`/login`へ移動させる。

現在の`throwApiError`は、エラーメッセージだけを保持しており、HTTPステータスを呼び出し元で判定できない。

次回は、`message`と`status`を持つ独自の`ApiError`クラスを作成する。

```ts
export class ApiError extends Error {
  status: number;

  constructor(message: string, status: number) {
    super(message);

    // 次回はここから
  }
}
```

次回は、受け取った`status`をクラスのプロパティへ保存する処理から再開する。

```ts
this.status = status;
```

その後、401を検出した場合に`/login`へ移動する処理を実装する。
