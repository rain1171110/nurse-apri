# 2026年8月21日 学習ログ

## 今日の目標

ログイン成功後、ページを再読み込みしなくても患者一覧を表示できるようにする。

## 発生していた問題

ログインには成功して患者一覧画面へ移動するが、患者が表示されなかった。

ブラウザを再読み込みすると、患者一覧が正常に表示された。

## 原因

ログイン前に `App.tsx` の `useEffect` が実行され、患者データの取得が401エラーになっていた。

その後、ログインに成功して次の処理を実行しても、画面が移動するだけで患者データは再取得されなかった。

```tsx
await loginApi(loginData);
navigate("/");
```

`navigate("/")` はURLを変更する処理であり、`fetchAppData()`を再実行する処理ではない。

また、次の依存配列が空だったため、`useEffect`は基本的に最初の表示時にしか実行されなかった。

```tsx
}, []);
```

## 修正した処理の流れ

```text
LoginPageでログイン成功
↓
onLoginSuccess()を実行
↓
AppのhandleLoginSuccess()を実行
↓
isLoggedInがfalseからtrueへ変化
↓
useEffectが再実行
↓
fetchAppData()で患者データを取得
↓
患者一覧を表示
```

## App.tsxでログイン状態を管理

```tsx
const [isLoggedIn, setIsLoggedIn] = useState(false);

const handleLoginSuccess = () => {
  setIsLoggedIn(true);
};
```

`isLoggedIn`は現在のログイン状態を表す。

`handleLoginSuccess`が実行されると、`isLoggedIn`が `true`へ変化する。

## LoginPageへ関数をpropsで渡す

```tsx
<Route
  path="/login"
  element={<LoginPage onLoginSuccess={handleLoginSuccess} />}
/>
```

`App.tsx`から `LoginPage.tsx`へ、ログイン成功を親へ伝える関数を渡した。

## LoginPageのprops型

```tsx
type LoginPageProps = {
  onLoginSuccess: () => void;
};
```

```tsx
export default function LoginPage({
  onLoginSuccess,
}: LoginPageProps) {
```

`LoginPage`はログイン状態そのものを変更するのではなく、ログイン成功を親へ知らせる。

## ログイン成功後に親へ通知

```tsx
try {
  setApiError("");

  await loginApi(loginData);
  onLoginSuccess();

  navigate("/");
}
```

`loginApi()`が成功した場合だけ、`onLoginSuccess()`が実行される。

関数を実行するときは、関数名の後ろに `()`が必要。

```tsx
onLoginSuccess;   // 関数を参照するだけ
onLoginSuccess(); // 関数を実行する
```

## useEffectの依存配列を変更

```tsx
useEffect(() => {
  const run = async () => {
    setLoading(true);
    setApiError("");

    try {
      const data = await fetchAppData();

      setAppData({
        patients: Array.isArray(data.patients) ? data.patients : [],
        records: Array.isArray(data.records) ? data.records : [],
      });
    } catch (error) {
      console.error(error);
      setApiError("APIから読み込めませんでした");
    } finally {
      setLoading(false);
    }
  };

  run();
}, [isLoggedIn]);
```

依存配列に `isLoggedIn`を入れたことで、ログイン状態が変化したときにも `useEffect`が実行されるようになった。

## propsへ関数を渡す2つの書き方

### 関数をその場で作る

```tsx
<LoginPage onLoginSuccess={() => setIsLoggedIn(true)} />
```

### 名前を付けた関数を渡す

```tsx
const handleLoginSuccess = () => {
  setIsLoggedIn(true);
};

<LoginPage onLoginSuccess={handleLoginSuccess} />
```

どちらも同じ動作になる。

今回は、処理の目的が分かりやすい `handleLoginSuccess`を使用した。

## setGlobalErrorsとの違い

```tsx
<NursingRecordItem onErrorsChange={setGlobalErrors} />
```

これは、子から受け取ったエラーをそのまま `setGlobalErrors`へ渡せるため、state更新関数を直接渡している。

一方、ログイン成功時は、親側で必ず `true`を設定する。

```tsx
<LoginPage onLoginSuccess={handleLoginSuccess} />
```

```tsx
const handleLoginSuccess = () => {
  setIsLoggedIn(true);
};
```

## 動作確認

- ログインAPIが成功する
- `/`へ移動する
- ページを再読み込みしなくても患者一覧が表示される
- 修正前に発生していた空の患者一覧画面が解消された

## 今日理解したこと

- `navigate()`は画面を移動するだけで、データを再取得しない
- Reactのstateは `import`で渡すものではない
- 子から親の処理を実行するときは、関数をpropsで渡せる
- 関数は `関数名()`で実行する
- `useEffect`の依存配列にstateを入れると、そのstateが変化したときに再実行される
- 親はstateを管理し、子はコールバック関数を使って親へ出来事を伝えられる
- 大文字から始まる名前はReactコンポーネントに使い、通常の関数は小文字から始める
