## 実装した内容

### 1. 画面をログイン状態によって切り替える

`isLoggedIn`を使い、ログイン状態を判定する。

```tsx
const [isLoggedIn, setIsLoggedIn] = useState(false);
```

基本的な条件分岐は次の形になる。

```tsx
isLoggedIn ? (
  <PatientList />
) : (
  <Navigate to="/login" replace />
)
```

- `isLoggedIn`が`true`：患者一覧を表示
- `isLoggedIn`が`false`：`/login`へ移動

`Navigate`を使用するため、React Routerからimportする。

```tsx
import {
  Routes,
  Route,
  Navigate,
  Outlet,
} from "react-router-dom";
```

---

### 2. 保護ルートを親Routeへまとめる

各ルートへ同じ認証判定を書くのではなく、ログインが必要なルートを親`Route`の中へまとめた。

```tsx
<Routes>
  <Route
    element={
      loading ? (
        <div>読み込み中…</div>
      ) : isLoggedIn ? (
        <Outlet />
      ) : (
        <Navigate to="/login" replace />
      )
    }
  >
    <Route
      path="/"
      element={
        <PatientList
          patients={appData.patients}
          isLoading={loading}
          onErrorsChange={setGlobalErrors}
          addPatient={addPatient}
        />
      }
    />

    <Route
      path="/patient/:id"
      element={
        <PatientPage
          patients={appData.patients}
          records={appData.records}
          updatePatient={updatePatient}
          addRecord={addRecord}
          updateRecord={updateRecord}
          deleteRecord={deleteRecord}
          deletePatient={deletePatient}
        />
      }
    >
      <Route index element={<PatientMenu />} />

      <Route
        path="detail"
        element={<PatientDetail onErrorsChange={setGlobalErrors} />}
      />

      <Route path="vitals" element={<PatientVitals />} />

      <Route
        path="records"
        element={<NursingRecordList onErrorsChange={setGlobalErrors} />}
      />

      <Route
        path="records/:recordId"
        element={<NursingRecordItem onErrorsChange={setGlobalErrors} />}
      />
    </Route>

    <Route path="/test" element={<div>テスト画面</div>} />
  </Route>

  <Route
    path="/login"
    element={<LoginPage onLoginSuccess={handleLoginSuccess} />}
  />
</Routes>
```

`/login`は保護ルートの外側に置く。

ログイン画面まで保護ルートの中へ入れると、未ログインの利用者がログイン画面を開けなくなるため。

## Outletとは

`Outlet`は、現在のURLに一致する子`Route`を表示するReact Routerのコンポーネント。

```tsx
<Route element={<Outlet />}>
  <Route path="/" element={<PatientList />} />
  <Route path="/test" element={<div>テスト画面</div>} />
</Route>
```

URLが`/`の場合、`Outlet`の場所へ`PatientList`が表示される。

URLが`/test`の場合、`Outlet`の場所へテスト画面が表示される。

```text
親Route
  ↓
Outlet
  ↓
URLに一致した子Routeを表示
```

---

## Outlet contextとの違い

### 子ルートを表示するだけ

```tsx
<Outlet />
```

### 子ルートを表示してデータも渡す

```tsx
<Outlet context={outletContext} />
```

`PatientPage`では、患者情報や操作関数を子ルートへ渡している。

```tsx
const outletContext: PatientOutletContext = {
  patient,
  patientRecords,
  updatePatient,
  addRecord,
  updateRecord,
  deleteRecord,
  deletePatient,
  usedRoomsForEdit,
};

return <Outlet context={outletContext} />;
```

子ルート側では、`useOutletContext`で受け取る。

```tsx
const {
  patient,
  updatePatient,
} = useOutletContext<PatientOutletContext>();
```

整理すると次のとおり。

```text
<Outlet />
→ 子ルートを表示する

<Outlet context={outletContext} />
→ 子ルートを表示する
→ 子ルートへ値や関数を渡す
```

`context`には次のようなものを渡せる。

- オブジェクト
- 配列
- 文字列や数値
- stateの値
- 関数
- 親がpropsとして受け取った値や関数

## 再読み込み時に/loginへ戻る原因

`isLoggedIn`の初期値は`false`になっている。

```tsx
const [isLoggedIn, setIsLoggedIn] = useState(false);
```

ページを再読み込みすると、Reactのstateは初期化される。

一方、認証Cookieはブラウザに残っている。

```text
ReactのisLoggedIn
→ falseに戻る

ブラウザの認証Cookie
→ 残っている
```

以前のコードでは、Cookieの確認が終わる前に`isLoggedIn === false`と判定され、`/login`へ移動していた。

```text
1. isLoggedInがfalseで開始
2. 画面が先に認証状態を判定
3. /loginへ移動
4. その後fetchAppDataがCookieを確認
5. ログイン済みだと判明
```

## 修正内容

`loading`を使い、認証確認が終わるまでリダイレクトを待つようにした。

```tsx
<Route
  element={
    loading ? (
      <div>読み込み中…</div>
    ) : isLoggedIn ? (
      <Outlet />
    ) : (
      <Navigate to="/login" replace />
    )
  }
>
```

処理の順番は次のとおり。

```text
loadingがtrue
→ 「読み込み中…」を表示して認証確認を待つ

loadingがfalse、isLoggedInがtrue
→ Outletで保護された画面を表示

loadingがfalse、isLoggedInがfalse
→ /loginへ移動
```

## 動作確認

次の動作を確認できた。

- 未ログインで`/`へアクセスすると`/login`へ移動する
- 未ログインで`/test`へアクセスすると`/login`へ移動する
- 未ログインで`/patient/:id`へアクセスすると`/login`へ移動する
- ログイン成功後に患者一覧が表示される
- ログイン後、患者詳細ページを再読み込みしても`/login`へ戻らない
- 認証確認中は「読み込み中…」が表示される

## 今日理解したこと

- `Route`の`element`では三項演算子を使って画面を切り替えられる
- `Navigate`は別のURLへ移動させるコンポーネント
- `replace`を付けると、現在のブラウザ履歴を置き換えられる
- 保護ルートは親`Route`へまとめられる
- `Outlet`はURLに一致した子ルートを表示する場所
- `Outlet context`を使うと、子ルートへデータや関数も渡せる
- Reactのstateは再読み込みすると初期化される
- 認証Cookieは再読み込み後もブラウザに残る
- 認証確認中と未ログイン状態を区別する必要がある
- 認証確認が終わる前にリダイレクトしてはいけない

## 現在残っている問題

現在のデータ取得用`useEffect`は、依存配列に`isLoggedIn`が入っている。

```tsx
useEffect(() => {
  const run = async () => {
    setLoading(true);
    setApiError("");

    try {
      const data = await fetchAppData();

      setIsLoggedIn(true);

      setAppData({
        patients: Array.isArray(data.patients) ? data.patients : [],
        records: Array.isArray(data.records) ? data.records : [],
      });
    } catch (error) {
      console.error(error);
      setApiError("APIから読み込めませんでした");
    } finally {
      setLoading(false);
    }
  };

  run();
}, [isLoggedIn]);
```

この中で`setIsLoggedIn(true)`を実行している。

そのため、保存済みのCookieがある状態でアプリを開くと、次のようにデータ取得が2回動く可能性がある。

```text
初回表示
→ fetchAppDataを実行
→ setIsLoggedIn(true)
→ isLoggedInがfalseからtrueへ変化
→ useEffectが再実行
→ fetchAppDataをもう一度実行
```
