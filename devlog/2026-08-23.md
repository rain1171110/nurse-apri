## 1. バックエンドのログアウトAPI

`server/index.ts`のログインAPIの下に追加した。

```ts
app.post("/api/auth/logout", (req, res) => {
  res.clearCookie("token", {
    httpOnly: true,
    secure: process.env.NODE_ENV === "production",
    sameSite: "strict",
  });

  res.status(200).json({
    message: "ログアウト成功",
  });
});
```

### 理解したこと

ログイン時は`res.cookie()`でJWTをCookieに保存する。

```ts
res.cookie("token", token, {
  httpOnly: true,
  secure: process.env.NODE_ENV === "production",
  sameSite: "strict",
});
```

ログアウト時は`res.clearCookie()`で同じ名前のCookieを削除する。

```ts
res.clearCookie("token", {
  httpOnly: true,
  secure: process.env.NODE_ENV === "production",
  sameSite: "strict",
});
```

Cookieを正しく削除するため、保存時と削除時の設定をそろえる。

今回は`express-session`を使用していないため、以下の処理は不要。

```ts
req.session.destroy();
res.clearCookie("connect.sid");
```

`nurse-apri`ではJWTを`token` Cookieに保存しているため、`token`を削除する。

ログアウトは状態を変更する処理なので、`GET`ではなく`POST`を使用する。

## 2. Expressの型指定

ログインAPIでは、次のように型を指定している。

```ts
app.post<{}, {}, LoginBody>(
  "/api/auth/login",
  async (req, res) => {
    // ログイン処理
  },
);
```

型の順番は次のとおり。

```ts
app.post<Params, ResponseBody, RequestBody>
```

`LoginBody`は、Zodスキーマから作成している。

```ts
export type LoginBody = z.infer<typeof loginSchema>;
```

これにより、`req.body`を次の型として扱える。

```ts
type LoginBody = {
  email: string;
  password: string;
};
```

ログアウトAPIはURLパラメーターもリクエスト本文も受け取らないため、型指定を省略できる。

```ts
app.post("/api/auth/logout", (req, res) => {
  // ログアウト処理
});
```

## 3. フロント側のログアウトAPI

`src/api/authApi.ts`に追加した。

```ts
export const logoutApi = async (): Promise<void> => {
  const response = await fetch(`${API_BASE}/auth/logout`, {
    method: "POST",
    credentials: "include",
  });

  if (!response.ok) {
    await throwApiError(response);
  }
};
```

ログアウトではメールアドレスやパスワードを送らないため、引数、`headers`、`body`は不要。

```ts
credentials: "include"
```

は必要。Cookieを含めてバックエンドへリクエストするため。

## 4. データ取得処理の整理

以前は、`isLoggedIn`が変わるたびに`fetchAppData()`が実行されていた。

```ts
useEffect(() => {
  // データ取得
}, [isLoggedIn]);
```

この状態でログアウトすると、`setIsLoggedIn(false)`によって再びデータ取得が実行され、認証Cookieがないため`401`になる。

そこで、データ取得処理を`loadAppData()`へ分離した。

```ts
const loadAppData = async () => {
  setLoading(true);
  setApiError("");

  try {
    const data = await fetchAppData();

    setIsLoggedIn(true);

    setAppData({
      patients: Array.isArray(data.patients) ? data.patients : [],
      records: Array.isArray(data.records) ? data.records : [],
    });
  } catch (error) {
    console.error(error);
    setApiError("APIから読み込めませんでした");
  } finally {
    setLoading(false);
  }
};
```

ログイン成功時にも同じ関数を実行する。

```ts
const handleLoginSuccess = async (): Promise<void> => {
  await loadAppData();
};
```

アプリの初回表示時にも実行する。

```ts
useEffect(() => {
  loadAppData();
}, []);
```

### 処理の役割

- 初回表示：`useEffect`から`loadAppData()`を実行
- ログイン成功：`handleLoginSuccess`から`loadAppData()`を実行
- ログアウト：`loadAppData()`を実行しない

## 5. ログアウト処理

`App.tsx`で`logoutApi`をインポートした。

```ts
import { logoutApi } from "./api/authApi";
```

ログアウト処理を追加した。

```ts
const handleLogout = async (): Promise<void> => {
  try {
    setApiError("");

    await logoutApi();

    setIsLoggedIn(false);
    setAppData({
      patients: [],
      records: [],
    });
  } catch (error) {
    console.error("ログアウトに失敗しました", error);
    setApiError(getErrorMessage(error, "ログアウトに失敗しました"));
  }
};
```

### 処理の順番

1. `logoutApi()`でバックエンドへリクエスト
2. バックエンドが`token` Cookieを削除
3. `isLoggedIn`を`false`にする
4. 患者・看護記録データを空にする
5. 保護ルートによって`/login`へ移動する

API通信に失敗した場合は`catch`へ移動するため、ログイン状態と患者データは維持される。

## 6. ログアウトボタン

`App.tsx`の`header`内に追加した。

```tsx
{isLoggedIn && (
  <button
    type="button"
    className="btn-primary"
    onClick={handleLogout}
  >
    ログアウトボタン
  </button>
)}
```

### 理解したこと

ログアウトは入力フォームではないため、`form`や`onSubmit`は不要。

```tsx
onClick={handleLogout}
```

で、クリック時にログアウト処理を実行する。

`isLoggedIn &&`によって、ログイン中だけボタンを表示する。

## 8. ログアウトAPIのテスト

テスト専用のagentを作るところまで進めた。

```ts
describe("POST /api/auth/logout", () => {
  it("ログアウト後は保護されたAPIへアクセスできない", async () => {
    const logoutAgent = request.agent(app);

    const loginResponse = await logoutAgent
      .post("/api/auth/login")
      .send(testUser);

    expect(loginResponse.status).toBe(200);

    const logoutResponse = await logoutAgent.post("/api/auth/logout");

    expect(logoutResponse.status).toBe(200);

    // 次回はここから
  });
});
```

既存の`agent`をログアウトさせると、後続テストにも影響する可能性がある。そのため、ログアウトテスト専用の`logoutAgent`を使用する。

ログアウトテストでは、最初から未ログインの状態を確認するだけでは不十分。

```text
ログイン成功（200）
    ↓
ログアウト成功（200）
    ↓
保護APIへアクセス
    ↓
認証Cookieがないため401
```

ログインとログアウトを先に実行することで、「ログアウトによってログイン状態が解除されたこと」を確認できる。
