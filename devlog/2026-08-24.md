## 1. ログアウトAPIのテスト

```ts
describe("POST /api/auth/logout", () => {
  it("ログアウト後は保護されたAPIへアクセスできない", async () => {
    const logoutAgent = request.agent(app);

    const loginResponse = await logoutAgent
      .post("/api/auth/login")
      .send(testUser);
    expect(loginResponse.status).toBe(200);

    const logoutResponse = await logoutAgent.post("/api/auth/logout");
    expect(logoutResponse.status).toBe(200);

    const protectedResponse = await logoutAgent.get("/api/data");
    expect(protectedResponse.status).toBe(401);
  });
});
```

### テストの流れ

```text
ログインAPIへPOST
↓
200を確認
↓
logoutAgentが認証Cookieを保持
↓
ログアウトAPIへPOST
↓
200を確認
↓
保護された/api/dataへGET
↓
401を確認
```

`logoutResponse.status`が`200`であることだけでは、本当にログアウトできたかまでは確認できない。

ログアウト後に保護された`/api/data`へアクセスし、`401`が返ることで、認証Cookieが使えなくなったことを確認している。

### logoutAgentを別に作る理由

```ts
const logoutAgent = request.agent(app);
```

ファイル上部の共有`agent`は、`beforeAll`でログインしてほかのテストでも使用している。

共有`agent`をログアウトさせると、保持しているCookieが削除され、後続のテストへ影響する可能性がある。

そのため、ログアウトテスト専用の`logoutAgent`を作成する。

## 2. フロント側のログアウト処理

```ts
const handleLogout = async (): Promise<void> => {
  try {
    setApiError("");

    await logoutApi();

    setIsLoggedIn(false);
    setAppData({
      patients: [],
      records: [],
    });
  } catch (error) {
    console.error("ログアウトに失敗しました", error);
    setApiError(getErrorMessage(error, "ログアウトに失敗しました"));
  }
};
```

### 各処理の役割

```ts
await logoutApi();
```

バックエンドへログアウトを依頼し、処理が完了するまで待つ。

```ts
setIsLoggedIn(false);
```

Reactのログイン状態を`false`へ変更し、ログイン画面へ切り替える。

```ts
setAppData({
  patients: [],
  records: [],
});
```

Reactのメモリ上に保持している患者情報と看護記録を空にする。

それぞれ変更するものが異なる。

| 処理 | 変更するもの |
|---|---|
| `logoutApi()` | 認証Cookie |
| `setIsLoggedIn(false)` | Reactのログイン状態 |
| `setAppData()` | Reactが保持する患者・看護記録 |

画面をログイン画面へ戻しても、`appData`は自動的には空にならない。

React Developer Toolsの`Components`タブから`App`を選択し、次のStateを確認できた。

```text
State: {
  patients: Array(6),
  records: Array(0)
}
```

ログアウト後は、`setAppData()`によって次の状態になる。

```text
State: {
  patients: Array(0),
  records: Array(0)
}
```

患者情報を扱うため、画面から隠すだけでなく、ログアウト時にReact内のデータも消すことが重要。

### logoutApiが失敗した場合

```text
await logoutApi()
↓
エラー発生
↓
setIsLoggedIn(false)は実行されない
↓
setAppData()も実行されない
↓
catchへ移動
```

`await logoutApi()`が正常終了した場合だけ、その下の処理へ進む。

## 3. logoutApiの処理

```ts
export const logoutApi = async (): Promise<void> => {
  const response = await fetch(`${API_BASE}/auth/logout`, {
    method: "POST",
    credentials: "include",
  });

  if (!response.ok) {
    await throwApiError(response);
  }
};
```

```ts
credentials: "include"
```

ブラウザに保存されている認証Cookieをリクエストに含める。

バックエンドでは、`res.clearCookie()`によって認証Cookieを削除する。

## 5. loadAppDataの処理

```ts
const loadAppData = async () => {
  setLoading(true);
  setApiError("");

  try {
    const data = await fetchAppData();

    setIsLoggedIn(true);

    setAppData({
      patients: Array.isArray(data.patients) ? data.patients : [],
      records: Array.isArray(data.records) ? data.records : [],
    });
  } catch (error) {
    console.error(error);
    setApiError("APIから読み込めませんでした");
  } finally {
    setLoading(false);
  }
};
```

### Cookieが有効な場合

```text
fetchAppData()
↓
GET /api/data
↓
requireAuthで認証成功
↓
患者・看護記録を取得
↓
setIsLoggedIn(true)
↓
appDataへ保存
```

### Cookieがない・期限切れの場合

```text
fetchAppData()
↓
GET /api/data
↓
requireAuthで認証失敗
↓
401
↓
fetchAppDataがエラーを投げる
↓
loadAppDataのcatchへ移動
```

この場合、次の処理は実行されない。

```ts
setIsLoggedIn(true);
setAppData(...);
```

### finallyの役割

```ts
finally {
  setLoading(false);
}
```

成功・失敗にかかわらず、最後に読み込み状態を終了する。

## 6. requireAuthの役割

保護されたAPIでは、データ取得処理の前に`requireAuth`が実行される。

```ts
app.get("/api/data", requireAuth, async (req, res) => {
  // 患者・看護記録を取得する処理
});
```

Expressは左から順番に処理する。

```text
GET /api/data
↓
requireAuth
↓
認証成功時だけデータ取得処理へ進む
```

`requireAuth`では主に次を確認する。

```text
token Cookieが存在するか
↓
jwt.verify()でJWTを検証
↓
改ざんされていないか
↓
有効期限が切れていないか
```

認証に成功すると、`next()`で次の処理へ進む。

```text
JWTが有効
↓
next()
↓
患者・看護記録を取得
↓
200
```

認証に失敗すると`401`を返し、データ取得処理へは進まない。

```text
Cookieなし・JWTが無効・期限切れ
↓
401
↓
患者・看護記録を取得しない
```

`requireAuth`は患者データを取得する関数ではなく、患者データ取得処理へ進んでよいか判定するミドルウェア。

## 7. fetchAppDataと401エラー

```ts
export const fetchAppData = async (): Promise<AppData> => {
  const response = await fetch(`${API_BASE}/data`, {
    credentials: "include",
  });

  if (!response.ok) {
    throw new Error(`API error:${response.status}`);
  }

  const data: AppData = await response.json();
  return data;
};
```

`method`を指定していないため、初期値の`GET`になる。

```ts
credentials: "include"
```

認証Cookieをリクエストに含める。

### response.ok

`response.ok`は、HTTPステータスが`200～299`なら`true`になる。

```text
200 → true
401 → false
500 → false
```

`fetch()`は`401`や`500`を受け取っただけでは、自動的にエラーを投げない。

そのため、自分で判定してエラーを投げる。

```ts
if (!response.ok) {
  throw new Error(`API error:${response.status}`);
}
```

`401`の場合は、次のようなエラーになる。

```ts
throw new Error("API error:401");
```

`throw`が実行されると`fetchAppData()`は途中で終了するため、次の処理は実行されない。

```ts
const data: AppData = await response.json();
return data;
```

呼び出し元の`loadAppData()`では、`catch`へ処理が移る。

```text
requireAuthが401を返す
↓
fetchが401レスポンスを受け取る
↓
response.okがfalse
↓
throw new Error("API error:401")
↓
fetchAppDataが途中終了
↓
loadAppDataのcatchへ移動
```

## 今日理解したこと

- ログアウトテストでは、ログイン状態を作ってからログアウトする
- ログアウトAPIの`200`だけでは、実際にログアウトできたとは判断できない
- ログアウト後に保護APIが`401`になることまで確認する
- 共有`agent`への影響を防ぐため、ログアウト専用の`logoutAgent`を作る
- `await`は、非同期関数が正常終了するまで後続処理を待たせる
- Cookie、ReactのログインState、患者データは別々に管理されている
- ログアウト時はReactが保持する患者データも空にする
- `requireAuth`は、保護APIへ進んでよいか判定する
- `fetch()`は`401`だけでは例外を投げない
- `response.ok`を確認し、`throw`することで呼び出し元の`catch`へつなげる
