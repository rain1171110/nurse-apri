# 2026年8月28日 学習ログ

## 今日の学習内容

今日は、ログインユーザーごとに患者と看護記録を制限する「認可」の実装を進めた。

現在はシンプルな認可として、次の設計にしている。

```text
ログインユーザーA
├── 患者A
├── 患者C
└── 患者D

ログインユーザーB
├── 患者B
└── 患者E
```

患者とログインユーザーが同一という意味ではなく、患者の`userId`にログインユーザーのIDが保存されている。

将来的には、病院や訪問看護事業所などの所属単位で患者データを共有できる設計へ拡張する。

---

## 1. スプレッド構文の確認

```ts
const newData = [...result.data];
```

`...result.data`は、中身を展開するスプレッド構文。

`[...result.data]`全体では、展開した要素を使って新しい配列を作るため、「コピーしている」という理解でよい。

オブジェクトでも同じ。

```ts
const newPatient = {
  ...result.data,
};
```

`...`自体の役割は「展開」であり、処理全体では新しい配列やオブジェクトを作成している。

---

## 2. ログインユーザーのデータだけ取得

```ts
app.get("/api/data", requireAuth, async (req, res) => {
  try {
    const patients = await prisma.patient.findMany({
      where: {
        userId: req.userId,
      },
    });

    const records = await prisma.nursingRecord.findMany({
      where: {
        patient: {
          userId: req.userId,
        },
      },
      include: {
        vitals: true,
      },
    });

    const data = {
      patients,
      records,
    };

    res.json(data);
  } catch (error) {
    console.error("GET /api/data error:", error);
    res.status(500).json({
      error: "Failed to read data / データの読み込みに失敗しました",
    });
  }
});
```

### 患者の取得

`Patient`は`userId`を直接持っているため、そのまま条件に指定できる。

```ts
where: {
  userId: req.userId,
}
```

### 看護記録の取得

`NursingRecord`は`userId`を直接持っていない。

そのため、関連する`Patient`を経由して確認する。

```ts
where: {
  patient: {
    userId: req.userId,
  },
}
```

## 3. 患者作成時にuserIdを保存

```ts
const userId = req.userId;

if (!userId) {
  res.status(401).json({
    error: "Unauthorized / 認証が必要です",
  });
  return;
}

const newPatient = await prisma.patient.create({
  data: {
    ...result.data,
    userId,
  },
});
```

```ts
userId,
```

は、次の省略記法。

```ts
userId: userId,
```

フロントエンドから`userId`を受け取るのではなく、サーバー側でログインユーザーのIDを保存する。

---

## 4. 患者更新時の認可

```ts
const updatedPatient = await prisma.patient.update({
  where: {
    id,
    userId,
  },
  data: result.data,
});
```

`id`と`userId`の両方が一致する患者だけを更新する。

```text
患者IDが一致
かつ
ログインユーザーIDが一致
```

これにより、ログイン済みでも他人の患者は更新できない。

---

## 5. 患者削除時の認可

```ts
await prisma.patient.delete({
  where: {
    id,
    userId,
  },
});
```

患者更新と同様に、患者の`id`とログインユーザーの`userId`が一致する場合だけ削除する。

---

## 6. 看護記録作成時にも認可が必要な理由

`requireAuth`が防ぐのは、ログインしていない人からの操作。

看護記録作成時の認可が防ぐのは、ログイン済みのユーザーが他人の患者に記録を追加すること。

```text
認証
→ ログインしているか

認可
→ 指定された患者に記録を作成してよいか
```

現在はユーザー単位のシンプルな認可を実装している。

将来的には、同じ病院や事業所に所属するユーザーなら同じ患者を操作できる設計へ拡張する。

---

## 7. findManyとfindFirstの違い

### findMany

条件に一致するデータをすべて取得し、配列で返す。

```ts
const patients = await prisma.patient.findMany({
  where: {
    userId,
  },
});
```

結果の例：

```ts
[患者A, 患者C, 患者D]
```

見つからなければ空の配列になる。

```ts
[]
```

### findFirst

条件に一致する最初の1件を返す。

```ts
const patient = await prisma.patient.findFirst({
  where: {
    id: recordData.patientId,
    userId,
  },
});
```

見つかれば患者オブジェクト、見つからなければ`null`になる。

今回の目的は患者一覧の取得ではなく、指定された患者1人に対して記録を作成できるか確認すること。

---

## 8. 看護記録作成時の認可

`create()`には`where`を指定できない。

そのため、記録を作成する前に`findFirst()`で患者を確認する。

```ts
const patient = await prisma.patient.findFirst({
  where: {
    id: recordData.patientId,
    userId,
  },
});

if (!patient) {
  res.status(404).json({
    error: "Patient not found / 患者が見つかりません",
  });
  return;
}
```

日本語にすると次の処理。

```text
送られてきた患者IDと
ログインユーザーIDの両方に一致する患者を探す。

見つからなければ、
その患者への記録作成を許可しない。
```

認可に成功した後で、看護記録を作成する。

```ts
const newRecord = await prisma.nursingRecord.create({
  data: {
    ...recordData,
    vitals: {
      create: vitals,
    },
  },
  include: {
    vitals: true,
  },
});
```

---

## 9. 看護記録更新時の認可

現在のコードでは、更新対象の記録が自分の患者の記録か確認できている。

```ts
const updatedRecord = await prisma.nursingRecord.update({
  where: {
    id,
    patient: {
      userId,
    },
  },
```

これは次の意味。

```text
記録IDが一致する
かつ
その記録に関連する患者のuserIdが
ログインユーザーIDと一致する
```

ただし、`recordData`には`patientId`も含まれている。

```ts
data: {
  ...recordData,
}
```

そのため、更新後の紐づけ先となる患者も、自分の患者か確認する必要がある。

## 今日理解できたこと

- スプレッド構文は値を展開し、新しい配列やオブジェクトを作るときに使う
- 認証と認可は役割が異なる
- `Patient`は`userId`を直接持っている
- `NursingRecord`は`Patient`を経由して`userId`を確認する
- `findMany()`は条件に一致する複数件を配列で返す
- `findFirst()`は指定した条件に一致する1件を探す
- `create()`には`where`を指定できない
- 記録作成前に、指定された患者を操作できるか確認する必要がある
- 患者更新・削除では、`id`と`userId`の両方を条件にする
