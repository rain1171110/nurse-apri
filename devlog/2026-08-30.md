# 2026年8月29日 学習ログ

## 今日の学習内容

看護記録を追加するときに、患者IDがフロントエンドからバックエンドへどのように渡されるのかを確認した。

また、バックエンドでデータを検証し、ログインユーザーが管理する患者か確認してから、看護記録とバイタルを保存する流れを学習した。

---

## 1. 看護記録の入力データと患者IDを渡す

`NursingRecordList.tsx`では、看護記録フォームのデータと、現在表示している患者のIDを`addRecord`へ渡している。

```ts
const handleAddRecordSubmit = async (
  data: RecordOutput,
): Promise<void> => {
  const savedRecord = await addRecord(data, patient.id);

  if (!savedRecord) {
    return;
  }

  setIsAdding(false);
  setFormData(createEmptyRecord());
};
```

引数は位置によって対応する。

```ts
addRecord(data, patient.id);
```

```text
第1引数 data        → record
第2引数 patient.id  → patientId
```

受け取る側は次のようになっている。

```ts
const addRecord = async (
  record: RecordOutput,
  patientId: string,
): Promise<NursingRecord | undefined> => {
```

`patient.id`という名前が自動的に`patientId`へ変わるわけではない。

呼び出すときの第2引数を、関数側の第2引数である`patientId`が受け取っている。

---

## 2. 記録データへ患者IDを追加する

受け取った`record`と`patientId`を、1つのオブジェクトにまとめる。

```ts
const recordToAdd: Omit<NursingRecord, "id"> = {
  ...record,
  patientId,
};
```

これは、次のような意味になる。

```ts
const recordToAdd = {
  ...record,
  patientId: patientId,
};
```

例えば、元のデータが次の内容だったとする。

```ts
record = {
  date: "2026-08-29",
  author: "岡﨑",
  content: "体調は安定しています",
};

patientId = "patient-D";
```

合体後の`recordToAdd`は次のようになる。

```ts
recordToAdd = {
  date: "2026-08-29",
  author: "岡﨑",
  content: "体調は安定しています",
  patientId: "patient-D",
};
```

---

## 3. API関数へデータを渡す

作成した`recordToAdd`を`createRecordApi`へ渡す。

```ts
const savedRecord = await createRecordApi(recordToAdd);
```

`createRecordApi`では、受け取ったデータを`record`という引数名で使用する。

```ts
export const createRecordApi = async (
  record: Omit<NursingRecord, "id">,
): Promise<NursingRecord> => {
  const response = await fetch(`${API_BASE}/records`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(record),
    credentials: "include",
  });

  if (!response.ok) {
    await throwApiError(response);
  }

  const data: NursingRecord = await response.json();
  return data;
};
```

特に重要なのは次の部分。

```ts
body: JSON.stringify(record)
```

JavaScriptオブジェクトの`record`を、通信で送れるJSON文字列に変換して、HTTPリクエストの本文へ入れている。

```ts
credentials: "include"
```

では、認証に使用するCookieも一緒に送っている。

---

## 4. バックエンドでリクエストを受け取る

送られたJSONは、Expressの`express.json()`によってJavaScriptオブジェクトへ変換される。

```ts
app.use(express.json());
```

変換されたデータは、`req.body`へ入る。

```ts
req.body = {
  patientId: "patient-D",
  date: "2026-08-29",
  author: "岡﨑",
  content: "体調は安定しています",
  vitals: {
    temperature: 36.5,
  },
};
```

---

## 5. Zodでデータを検証する

受け取った`req.body`をスキーマで検証する。

```ts
const result = recordSchema.safeParse(req.body);
```

検証に失敗した場合は、エラーを返して処理を終了する。

```ts
if (!result.success) {
  res.status(400).json({
    error: "Invalid record data / 無効な記録データ",
  });
  return;
}
```

検証に成功した場合、検証済みデータは次の場所に入る。

```ts
result.data
```

`safeParse`が記録とバイタルを合体させているわけではない。

フロントエンドからすでに一緒に送られてきたデータを、スキーマどおりか検証している。

---

## 6. 看護記録とバイタルを分ける

検証済みデータを、看護記録とバイタルに分ける。

```ts
const { vitals, ...recordData } = result.data;
```

分けた結果は、次のようになる。

```ts
vitals = {
  temperature: 36.5,
};
```

```ts
recordData = {
  patientId: "patient-D",
  date: "2026-08-29",
  author: "岡﨑",
  content: "体調は安定しています",
};
```

データを分ける理由は、`schema.prisma`で`NursingRecord`と`VitalSigns`を別のモデルとして定義しているから。

```text
recordData → NursingRecordへ保存
vitals     → VitalSignsへ保存
```

---

## 7. ログインユーザーの患者か確認する

記録を追加しようとしている患者が、現在ログインしているユーザーの患者か確認する。

```ts
const patient = await prisma.patient.findFirst({
  where: {
    id: recordData.patientId,
    userId,
  },
});
```

それぞれの条件の意味は次のとおり。

```ts
id: recordData.patientId
```

フロントエンドから送られてきた、記録を追加したい患者のID。

```ts
userId
```

Cookie内のJWTから取得した、現在ログインしているユーザーのID。

2つの条件を両方満たす患者を探している。

```text
記録を追加したい患者のID
かつ
現在ログインしているユーザーのID
```

患者が見つからなければ、他のユーザーの患者である可能性があるため、処理を終了する。

```ts
if (!patient) {
  res.status(404).json({
    error: "Patient not found / 患者が見つかりません",
  });
  return;
}
```

これは、他のユーザーが管理する患者に看護記録を追加できないようにする認可処理である。

---

## 8. 看護記録とバイタルを保存する

認可確認に成功したら、看護記録とバイタルを保存する。

```ts
const newRecord = await prisma.nursingRecord.create({
  data: {
    ...recordData,
    vitals: {
      create: vitals,
    },
  },
  include: {
    vitals: true,
  },
});
```

看護記録のデータを保存する部分。

```ts
...recordData
```

関連するバイタルを作成する部分。

```ts
vitals: {
  create: vitals,
}
```

作成後の返り値にもバイタルを含める部分。

```ts
include: {
  vitals: true,
}
```

`create`は保存の指定で、`include`は返り値に含める指定。

---

## 9. 作成したデータをフロントエンドへ返す

バックエンドから、作成した看護記録を返す。

```ts
res.status(201).json(newRecord);
```

`201`は、新しいデータの作成に成功したことを表す。

フロントエンドでは、返されたJSONを受け取る。

```ts
const data: NursingRecord = await response.json();
return data;
```

そのデータが`savedRecord`へ入る。

```ts
const savedRecord = await createRecordApi(recordToAdd);
```

最後に、画面で管理している記録一覧へ追加する。

```ts
setAppData((prev) => ({
  ...prev,
  records: [...prev.records, savedRecord],
}));
```

これにより、追加した記録が画面に表示される。

## 今日理解できたこと

- 関数の引数は、渡した位置と受け取る位置で対応する
- `data`は`record`へ、`patient.id`は`patientId`へ入る
- `record`と`patientId`を合体して`recordToAdd`を作る
- `JSON.stringify()`でデータをJSON文字列へ変換して送信する
- ExpressがJSONを変換して`req.body`へ入れる
- `safeParse()`に成功すると、検証済みデータが`result.data`へ入る
- `NursingRecord`と`VitalSigns`が別モデルなので、保存前にデータを分ける
- `patientId`と`userId`の両方を使って認可確認を行う
- Prismaで看護記録とバイタルを関連付けて保存する
- 作成した記録をフロントへ返し、画面の記録一覧へ追加する

---

## データ全体の流れ

```text
patient.id
↓
addRecord(data, patient.id)
↓
第2引数のpatientIdで受け取る
↓
recordとpatientIdをrecordToAddへまとめる
↓
createRecordApi(recordToAdd)
↓
JSON.stringify(record)
↓
POST /api/records
↓
express.json()
↓
req.body
↓
recordSchema.safeParse(req.body)
↓
result.data
↓
vitalsとrecordDataへ分ける
↓
patientIdとuserIdで認可確認
↓
NursingRecordとVitalSignsを保存
↓
201とnewRecordを返す
↓
savedRecordを画面のrecordsへ追加
```
