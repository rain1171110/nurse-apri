## 2. 昨日の復習

### SupertestでAPIへ送信するコード

```ts
const createPatientResponse = await agent
  .post("/api/patients")
  .send({
    name: "テスト患者",
    room: 999,
  });
```

それぞれの役割は次のとおり。

```ts
agent.post("/api/patients");
// POSTメソッドで /api/patients へリクエストを送る

.send({
  name: "テスト患者",
  room: 999,
});
// バックエンドへ送るデータ
```

バックエンドでは、`.send()`で送られたデータを`req.body`から受け取る。

```ts
req.body = {
  name: "テスト患者",
  room: 999,
};
```

リクエスト後、バックエンドから返されたレスポンス全体が変数に入る。

```ts
createPatientResponse;
// レスポンス全体

createPatientResponse.body;
// 返された患者データ

createPatientResponse.body.id;
// 作成された患者のID
```

### 今日の重要な区別

```text
.post("/api/patients")
→ どのAPIへ、どのHTTPメソッドで送るか

.send({...})
→ どのデータを送るか

req.body
→ バックエンドが送信データを受け取る場所

createPatientResponse
→ バックエンドから返ってきたレスポンス全体
```

## 3. 患者取得の認可テスト

```ts
describe("GET /api/patients", () => {
  it("他のユーザーの患者は取得できない", async () => {
    const otherAgent = request.agent(app);

    const testUserB = {
      email: `test-b-${Date.now()}@example.com`,
      password: "test-password",
    };

    const registerResponse = await otherAgent
      .post("/api/auth/register")
      .send(testUserB);

    expect(registerResponse.status).toBe(201);

    const loginResponse = await otherAgent
      .post("/api/auth/login")
      .send(testUserB);

    expect(loginResponse.status).toBe(200);

    const createPatientResponse = await agent
      .post("/api/patients")
      .send({
        name: "テスト患者",
        room: 999,
      });

    expect(createPatientResponse.status).toBe(201);

    const getPatientResponse =
      await otherAgent.get("/api/patients");

    expect(getPatientResponse.status).toBe(200);

    const patientIds = getPatientResponse.body.map(
      (patient: { id: string }) => patient.id,
    );

    expect(patientIds).not.toContain(
      createPatientResponse.body.id,
    );
  });
});
```

### `agent`と`otherAgent`の役割

```ts
agent;
// ユーザーAとしてログイン済み

otherAgent;
// ユーザーBとして登録・ログイン
```

このテストでは、ユーザーAが患者を作成している。

```ts
const createPatientResponse = await agent
  .post("/api/patients")
  .send({
    name: "テスト患者",
    room: 999,
  });
```

患者一覧を取得しているのはユーザーB。

```ts
const getPatientResponse =
  await otherAgent.get("/api/patients");
```

したがって、それぞれの値は次の意味になる。

```ts
patientIds;
// ユーザーBが取得できた患者IDの一覧

createPatientResponse.body.id;
// ユーザーAが作成した患者ID
```

最後に、ユーザーBの一覧にユーザーAの患者IDが含まれていないことを確認する。

```ts
expect(patientIds).not.toContain(
  createPatientResponse.body.id,
);
```

### このテストが確認していること

```text
ユーザーAが患者を作成
        ↓
ユーザーBが患者一覧を取得
        ↓
ユーザーBの一覧に
ユーザーAの患者が含まれていないことを確認
```

## 4. 看護記録更新テストの失敗

最初のテストでは、看護記録IDと患者IDの両方に、存在しないIDを指定していた。

```ts
const response = await agent
  .put("/api/records/00000000-0000-0000-0000-000000000000")
  .send({
    patientId: "00000000-0000-0000-0000-000000000000",
    date: "3000-12-19",
    author: "test author",
    vitals: {},
  });
```

この状態では、次の2つが存在しない。

```text
PUTのURLにあるID
→ 存在しない看護記録ID

.send()内のpatientId
→ 存在しない患者ID
```

バックエンドは、看護記録を更新する前に患者を確認する。

```ts
const patient = await prisma.patient.findFirst({
  where: {
    id: recordData.patientId,
    userId,
  },
});
```

患者が存在しないため、ここで処理が終了していた。

```ts
if (!patient) {
  res.status(404).json({
    error: "Patient not found / 患者が見つかりません",
  });
  return;
}
```

そのため、期待していた看護記録のエラーではなく、患者のエラーが返っていた。

```text
期待：
Record not found / 看護記録が見つかりません

実際：
Patient not found / 患者が見つかりません
```

## 5. 修正した看護記録更新テスト

看護記録が存在しない場合を正しくテストするため、先に実在する患者を作成した。

```ts
describe("PUT /api/records/:id", () => {
  it("存在しない看護記録を更新したら404を返す", async () => {
    const createPatientResponse = await agent
      .post("/api/patients")
      .send({
        name: "更新テスト用患者",
        room: 998,
      });

    expect(createPatientResponse.status).toBe(201);

    const response = await agent
      .put("/api/records/00000000-0000-0000-0000-000000000000")
      .send({
        patientId: createPatientResponse.body.id,
        date: "3000-12-19",
        author: "test author",
        vitals: {},
      });

    expect(response.status).toBe(404);
    expect(response.body.error).toBe(
      "Record not found / 看護記録が見つかりません",
    );
  });
});
```

修正後の条件は次のとおり。

```text
患者ID
→ 先に作成した、実在する患者ID

看護記録ID
→ 存在しないID
```

処理の流れは次のようになる。

```text
患者を作成
   ↓
患者作成が201か確認
   ↓
実在する患者IDを使う
   ↓
患者確認を通過
   ↓
存在しない看護記録を更新
   ↓
P2025が発生
   ↓
Record not foundの404を返す
```

この修正により、次のテストは成功した。

```text
✓ 存在しない看護記録を更新したら404を返す
```

## 7. 今日理解できたこと

- `.post()`はHTTPメソッドと送信先を指定する
- `.send()`はバックエンドへ送るデータを指定する
- `.send()`のデータはバックエンドの`req.body`に入る
- リクエスト後の変数には、レスポンス全体が入る
- `agent`と`otherAgent`は別々のCookieを保持できる
- 認可テストでは「誰が作成したか」と「誰が取得したか」を追う
- エラー処理は、コードに書かれた順番で判定される
- 看護記録の存在確認より先に患者確認で失敗すると、`Patient not found`が返る
- テストで固定値を使用すると、以前のデータと重複することがある
