## 2. 今日理解したこと

### `agent`はユーザーそのものではない

```ts
const agent = request.agent(app);
```

`agent`は特定のユーザーを表す変数ではない。

ログイン時にサーバーから受け取ったCookieを保存し、その後のリクエストでも送信できる通信オブジェクトである。

```text
agent
  └─ ログイン時に受け取ったCookieを保持する
```

---

### 同じ`agent`でユーザーAにログインする

```ts
await agent
  .post("/api/auth/login")
  .send(testUser);
```

ログインに成功すると、`agent`はユーザーAのCookieを保持する。

```text
agent
  └─ ユーザーAのCookie
      └─ ユーザーAの権限でAPIへアクセスする
```

---

### 同じ`agent`でユーザーBにログインするとどうなるか

```ts
await agent
  .post("/api/auth/login")
  .send(testUser);

await agent
  .post("/api/auth/login")
  .send(testUserB);
```

2回目のログインでユーザーBのCookieを受け取ると、同じ名前のCookieが新しい内容へ置き換わる。

そのため、両方ともユーザーAになるわけではない。

```text
1回目のログイン
agent
  └─ ユーザーAのCookie

2回目のログイン
agent
  └─ ユーザーBのCookie
```

この後に次の処理を実行すると、基本的にはユーザーBとしてリクエストが送られる。

```ts
const response = await agent.get("/api/patients");
```

つまり、同じ`agent`だけではユーザーAとユーザーBのログイン状態を同時に保持できない。

---

## 3. 2人のユーザーを再現する正しい方法

Cookieを保持する通信オブジェクトを2つ用意する。

```ts
const agent = request.agent(app);
const otherAgent = request.agent(app);
```

それぞれ別のユーザーでログインする。

```ts
await agent
  .post("/api/auth/login")
  .send(testUser);

await otherAgent
  .post("/api/auth/login")
  .send(testUserB);
```

これにより、次の状態を同時に再現できる。

```text
agent
  └─ ユーザーAのCookie
      └─ ユーザーAの権限

otherAgent
  └─ ユーザーBのCookie
      └─ ユーザーBの権限
```

## 4. なぜ認可テストでは2つの`agent`が必要なのか

認可テストでは、次のような動作を確認する。

```text
ユーザーBが患者を作成する
        ↓
ユーザーAがその患者を取得・更新しようとする
        ↓
他人の患者なので取得・更新できない
```

例えば、他ユーザーの患者を作成するときは`otherAgent`を使う。

```ts
const createPatientResponse = await otherAgent
  .post("/api/patients")
  .send({
    name: "他ユーザーの患者",
    room: 999,
  });
```

自分側の患者一覧は`agent`で取得する。

```ts
const getPatientResponse = await agent.get("/api/patients");
```

このように通信を分けることで、ユーザーAとユーザーBの権限が正しく区別されているか確認できる。

## 5. 今日の勘違いと修正

### 最初の理解

```text
agentがユーザーAなら、ユーザーBでログインしても
両方ともユーザーAの権限になるのではないか
```

### 正しい理解

```text
agentはユーザーAそのものではない。
agentは最後にログインしたユーザーのCookieを保持する。
```

したがって、同じ`agent`でユーザーBへログインすると、以降は基本的にユーザーBとして扱われる。

---

## 6. 今日の重要ポイント

- `agent`はユーザーそのものではない
- `agent`はCookieを保持する通信オブジェクト
- 誰の情報で最後にログインしたかによって、`agent`のログイン状態が決まる
- 同じ`agent`で別ユーザーにログインすると、以前のログイン状態を維持できない
- 2人のユーザーを同時に再現するには、`agent`と`otherAgent`を分ける
- 認可テストでは「自分」と「他人」のCookieを分けて保持する必要がある

## 8. 次回の開始地点

次回は、途中になっている次のテストの続きから行う。

```ts
it("他のユーザーの患者は更新できない", async () => {
  // ユーザーBが患者を作成する
  // ユーザーAがその患者を更新しようとする
  // 更新できず、404が返ることを確認する
});
```

確認する流れは次のとおり。

1. `otherAgent`で患者を作成する
2. 作成された患者の`body.id`を取得する
3. `agent`でその患者に`PUT`リクエストを送る
4. ステータスが`404`になることを確認する
5. 必要であれば、患者データが変更されていないことも確認する
