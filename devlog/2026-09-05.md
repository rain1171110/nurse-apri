## 2026-09-04：他ユーザーの患者を更新できない認可テスト

## 0. 今日の目標と成長テーマ

- 今日のテーマ：患者更新APIの認可テスト
- 目標：別のユーザーが所有する患者を更新できないことをテストする
- 強化した力：テスト・コード読解

---

## 1. 今日の作業サマリー

`otherAgent`で患者を作成し、別ユーザーとしてログインしている`agent`から、その患者を更新できないことを確認するテストを作成した。

```ts
it("他のユーザーの患者は更新できない", async () => {
  const createPatientResponse = await otherAgent
    .post("/api/patients")
    .send({
      name: "他ユーザーの患者",
      room: 998,
    });

  expect(createPatientResponse.status).toBe(201);

  const updatePatientResponse = await agent
    .put(`/api/patients/${createPatientResponse.body.id}`)
    .send({
      name: "更新しようとした患者",
      room: 998,
    });

  expect(updatePatientResponse.status).toBe(404);
});
```

---

## 2. テストの流れ

1. `otherAgent`が患者を作成する
2. バックエンドが患者IDを自動作成する
3. 作成結果が`createPatientResponse.body`に返される
4. `createPatientResponse.body.id`から患者IDを取り出す
5. 別ユーザーの`agent`が、その患者IDを指定して更新を試みる
6. 所有者の`userId`が一致しないため、`404`が返る

---

## 3. 今日理解したこと

### 患者IDはPOSTしたときに作成される

```ts
const createPatientResponse = await otherAgent
  .post("/api/patients")
  .send({
    name: "他ユーザーの患者",
    room: 998,
  });
```

このリクエストによって患者がデータベースに保存され、バックエンドで患者IDが自動作成される。

レスポンスは、イメージとして次のようになる。

```ts
createPatientResponse.body = {
  id: "自動作成された患者ID",
  name: "他ユーザーの患者",
  room: 998,
  userId: "testUserBのID",
};
```

### 作成した患者のIDを取り出す

```ts
createPatientResponse.body.id
```

- `createPatientResponse`：患者作成APIから返されたレスポンス全体
- `body`：バックエンドから返された患者データ
- `id`：作成された患者のID

### 更新する患者をURLで特定する

患者更新APIは、次の形式になっている。

```text
PUT /api/patients/:id
```

そのため、更新対象の患者IDをURLへ入れる必要がある。

```ts
.put(`/api/patients/${createPatientResponse.body.id}`)
```

実際には、次のようなURLになる。

```text
/api/patients/自動作成された患者ID
```

`${...}`はIDを作成する処理ではない。

すでに作成されているIDを、テンプレートリテラルの文字列へ埋め込むJavaScriptの書き方である。

---

## 4. 認可が働く理由

患者を作成したユーザーと、更新しようとするユーザーが異なる。

```ts
// testUserBとして患者を作成
otherAgent.post("/api/patients");

// testUserとして更新を試みる
agent.put(`/api/patients/${createPatientResponse.body.id}`);
```

バックエンドでは、患者IDだけでなく、ログインユーザーの`userId`も条件にして更新対象を探す。

```ts
where: {
  id,
  userId,
}
```

今回の結果は次のようになる。

- `id`：一致する
- `userId`：一致しない
- 更新対象：見つからない
- レスポンス：`404`

これにより、患者IDを知っている別ユーザーであっても、他人の患者を更新できない。

---

## 5. 間違えた点と修正

### 患者作成時にユーザー情報を送ろうとした

```ts
// 誤り
.send({
  user: {
    email: testUser.email,
  },
});
```

`POST /api/patients`へ送るのは患者データである。

```ts
// 正しい
.send({
  name: "他ユーザーの患者",
  room: 998,
});
```

患者の所有者は、`otherAgent`が保持するCookieからバックエンドが判断するため、リクエストでユーザー情報を指定する必要はない。

### 更新URLに患者IDを入れていなかった

```ts
// 誤り
agent.put("api/patients");
```

これでは、どの患者を更新するのか特定できない。また、先頭の`/`も不足している。

```ts
// 正しい
agent.put(`/api/patients/${createPatientResponse.body.id}`);
```
