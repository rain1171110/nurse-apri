## 3. 今日理解したこと

### 患者を作成しただけでは看護記録は存在しない

```ts
const createPatientResponse = await otherAgent.post("/api/patients");
```

この処理で作成されるのは患者だけである。

他ユーザーの看護記録を更新するテストでは、更新対象となる看護記録も`otherAgent`で作成する必要がある。

```ts
const createRecordResponse = await otherAgent.post("/api/records");
```

### 患者IDと看護記録IDは別のもの

```ts
createPatientResponse.body.id;
```

これは患者IDであり、「どの患者に看護記録を紐づけるか」を表す。

```ts
createRecordResponse.body.id;
```

これは看護記録IDであり、「どの看護記録を更新するか」を表す。

### URLと`.send()`では送られる場所が違う

```ts
.put(`/api/records/${createRecordResponse.body.id}`)
```

URLに入れた看護記録IDは、バックエンドの`req.params.id`に入る。

```ts
.send({
  patientId: createPatientResponse.body.id,
})
```

`.send()`で送った患者IDは、バックエンドの`req.body.patientId`に入る。

整理すると次のようになる。

```text
URLの看護記録ID
→ req.params.id
→ どの看護記録を更新するか

.send()のpatientId
→ req.body.patientId
→ どの患者に紐づく記録か
```

### `const { id } = req.params`の意味

バックエンドのルートが次の形になっている。

```ts
app.put("/api/records/:id", async (req, res) => {
  const { id } = req.params;
});
```

例えば、次のAPI URLへリクエストを送る。

```text
http://localhost:3001/api/records/d094341a-b5de-4d99-b162-d773b4aa015f
```

URL末尾の看護記録IDが`:id`に対応する。

```ts
req.params = {
  id: "d094341a-b5de-4d99-b162-d773b4aa015f",
};
```

次の2つは同じ意味である。

```ts
const { id } = req.params;
```

```ts
const id = req.params.id;
```

### `.send()`へ記録IDを入れるだけでは更新対象を指定できない

```ts
.send({
  id: createRecordResponse.body.id,
})
```

この`id`は`req.body.id`に入る。

しかし、現在のバックエンドは次のコードでURLからIDを取得している。

```ts
const { id } = req.params;
```

そのため、更新対象の看護記録IDはURLに入れる必要がある。

```ts
.put(`/api/records/${createRecordResponse.body.id}`)
```

技術的に`.send()`でIDを送れないわけではない。現在のバックエンドが`req.body.id`を参照する設計になっていないため、送っても更新対象の特定には使われない。

## 5. 今日つまずいた点

### `room: "uniqueRoom"`と書いた

```ts
room: "uniqueRoom",
```

引用符を付けると、変数ではなく文字列として送られる。

正しくは次の形。

```ts
room: uniqueRoom,
```

### 患者を作成しただけで更新テストを進めようとした

患者を作成しても看護記録は自動作成されない。

先に`otherAgent`で看護記録を作成し、そのレスポンスから看護記録IDを取得する必要がある。

### `/api/records`だけでPUTしようとした

```ts
.put("/api/records")
```

これでは、どの看護記録を更新するのか特定できない。

正しくは次の形。

```ts
.put(`/api/records/${createRecordResponse.body.id}`)
```

存在しないURLに送っても別の理由で`404`になる可能性があるため、正しいAPI URLに送って認可による`404`を確認することが重要。
