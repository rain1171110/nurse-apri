## 3. `put()`の役割

```ts
.put(`/api/records/${otherRecordResponse.body.id}`)
```

`put()`では、次の2つを指定している。

1. `PUT`という更新方法
2. 更新対象となるAPIのURL

例えば、看護記録IDが`record-123`の場合、実際には次のURLへリクエストする。

```http
PUT /api/records/record-123
```

バックエンドでは、次のルートがリクエストを受け取る。

```ts
app.put("/api/records/:id", requireAuth, async (req, res) => {
  const { id } = req.params;
});
```

URLの対応関係は次のとおり。

```text
/api/records/record-123
             └────────┘
                  ↓
          req.params.id
```

つまり、URLに入れて送った看護記録IDを、Expressが`req.params.id`へ格納する。

## 4. `send()`の役割

```ts
.send({
  patientId: otherPatientResponse.body.id,
  date: "2026-09-08",
  author: "更新後",
  vitals: {},
});
```

`send()`は、更新に必要な内容をリクエストの`body`に入れて送る。

バックエンドでは、次のように`req.body`から受け取る。

```ts
const result = recordSchema.safeParse(req.body);
```

または、分割代入を使って取り出すこともできる。

```ts
const { patientId, date, author, vitals } = req.body;
```

---

## 5. `put()`と`send()`の違い

| テスト側 | 役割 | バックエンドでの受け取り |
|---|---|---|
| `.put("/api/records/記録ID")` | 更新方法と更新対象を指定する | `req.params.id` |
| `.send({ ... })` | 更新内容をbodyに入れて送る | `req.body` |

一言で整理すると、次のようになる。

```text
put ＝ どのデータを更新するか
URL ＝ 更新対象
send ＝ どのような内容に更新するか
```

ただし、`put`自体が患者や看護記録を意味するわけではない。

更新対象はURLによって決まる。

```ts
.put(`/api/records/${recordId}`);   // 看護記録を更新
.put(`/api/patients/${patientId}`); // 患者を更新
```

## 6. `req.userId`について

```ts
const userId = req.userId;
```

`req.userId`に入るのは、現在リクエストを送っているログインユーザーのIDである。

```ts
req.userId = decoded.userId;
```

例えば、`agent`がユーザーAとしてログインしている場合は、ユーザーAのIDが入る。

```text
agentがリクエスト
       ↓
agentのCookieを送信
       ↓
requireAuthがJWTを検証
       ↓
req.userIdにユーザーAのIDを設定
```

看護記録の所有者は、次のつながりで確認する。

```text
看護記録 → 患者 → ユーザー
```

そのため、認可条件は次のようになる。

```ts
where: {
  id,
  patient: {
    userId,
  },
}
```

この条件では、次の2点を同時に確認している。

- 看護記録のIDが一致する
- その記録が属する患者を、現在のログインユーザーが所有している

## 7. 今日理解できたこと

### 理解できたこと

- URLに入れたIDは`req.params.id`で受け取る
- `send()`の内容は`req.body`で受け取る
- `put()`は既存データを更新するHTTPメソッド
- `put()`のURLによって、患者か看護記録かが決まる
- `agent`と`otherAgent`を分けることで、別ユーザーの認可をテストできる
- 他のユーザーの記録を更新しようとすると`404`になる

### 間違えた・注意が必要なこと

`req.userId`について、一度「看護記録を作成したユーザー」と考えてしまった。

正しくは次のとおり。

```text
req.userId
＝ 現在リクエストを送っているログインユーザーのID
```

## 8. 今日の重要ポイント

```text
.put(URL)
＝ 更新方法と更新対象を指定する

.send(データ)
＝ 更新内容をbodyに入れて送る
```

バックエンドとの対応は次のとおり。

```ts
app.put("/api/records/:id", requireAuth, async (req, res) => {
  const { id } = req.params; // URLから受け取る
  const data = req.body;     // send()から受け取る
});
```
