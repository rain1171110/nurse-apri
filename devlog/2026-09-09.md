## 2. 追加した削除認可テスト

```ts
describe("DELETE /api/records/:id", () => {
  it("他のユーザーの看護記録は削除できない", async () => {
    const uniqueRoom = createUniqueRoom();

    const createPatientResponse = await otherAgent
      .post("/api/patients")
      .send({
        name: "他ユーザの患者",
        room: uniqueRoom,
      });

    expect(createPatientResponse.status).toBe(201);

    const createRecordResponse = await otherAgent
      .post("/api/records")
      .send({
        patientId: createPatientResponse.body.id,
        date: "2026-09-05",
        author: "test author",
        vitals: {},
      });

    expect(createRecordResponse.status).toBe(201);

    const deleteResponse = await agent.delete(
      `/api/records/${createRecordResponse.body.id}`,
    );

    expect(deleteResponse.status).toBe(404);
    expect(deleteResponse.body.error).toBe(
      "Record not found / 看護記録が見つかりません",
    );
  });
});
```

### テストの流れ

```text
otherAgentで患者を作る
↓
otherAgentで看護記録を作る
↓
別ユーザーのagentが削除を要求する
↓
削除を許可せず404を返す
```

削除する記録はURLのIDで指定する。

```ts
agent.delete(`/api/records/${createRecordResponse.body.id}`);
```

削除処理では更新内容を送らないため、基本的に`.send()`は必要ない。

## 3. 病室番号の重複対策

### 変更前

```ts
const uniqueRoom = Math.floor(Math.random() * 999) + 1;
```

`describe`の中、`it`の外で実行すると、ランダム値は1回しか作られない。

```ts
describe("PUT /api/records/:id", () => {
  const uniqueRoom = Math.floor(Math.random() * 999) + 1;

  it("テスト1", async () => {
    // 同じuniqueRoomを使う
  });

  it("テスト2", async () => {
    // 同じuniqueRoomを使う
  });
});
```

その結果、複数の患者に同じ病室番号を使用して`409`になることがあった。

### 変更後

```ts
let nextRoom = 900;

const createUniqueRoom = (): number => {
  return nextRoom++;
};
```

各テスト内で実行する。

```ts
it("他のユーザーの患者は更新できない", async () => {
  const uniqueRoom = createUniqueRoom();
});
```

呼び出すたびに異なる値が返る。

```ts
createUniqueRoom(); // 900を返し、nextRoomは901になる
createUniqueRoom(); // 901を返し、nextRoomは902になる
createUniqueRoom(); // 902を返し、nextRoomは903になる
```

### `nextRoom++`の意味

```ts
return nextRoom++;
```

これは、現在の値を返してから`nextRoom`を1増やす。

おおよそ次の処理と同じ。

```ts
const room = nextRoom;
nextRoom = nextRoom + 1;
return room;
```

## 5. `git status`と`git diff`の違い

### `git status`

どのファイルが変更されたかを確認する。

```bash
git status
```

### `git diff`

変更前と変更後で、コードのどこが変わったかを確認する。

```bash
git diff
```

特定のファイルだけ確認する場合：

```bash
git diff -- server/index.test.ts
```

表示の意味：

```diff
- 変更前または削除した行
+ 変更後または追加した行
```

整理すると次のとおり。

```text
git status → 変更したファイルを確認
git diff   → 変更したコードの中身を確認
```

`git diff`では差がある部分だけを表示できるため、ファイル全体を読み直さなくても、意図しない追加や削除を確認できる。

## 6. フロント側のユーザー登録関数

`src/api/authApi.ts`へ、登録APIを呼び出す関数を追加した。

```ts
export const registerApi = async (
  receiveRegister: LoginData,
): Promise<void> => {
  const response = await fetch(`${API_BASE}/auth/register`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(receiveRegister),
    credentials: "include",
  });

  if (!response.ok) {
    await throwApiError(response);
  }
};
```

### 役割

```text
登録フォームのデータ
↓
registerApi
↓
POST /api/auth/registerへ送信
↓
バックエンドが受け取る
↓
PrismaでユーザーをDBへ保存
↓
失敗した場合はthrowApiError
```

## 7. API本体とAPIを呼ぶ関数の違い

### フロントエンド：送る側

```ts
registerApi();
```

`registerApi`は、登録APIへリクエストを送るための関数。

```ts
fetch(`${API_BASE}/auth/register`, {
  method: "POST",
});
```

### バックエンド：受け取る側

```ts
app.post("/api/auth/register", async (req, res) => {
  // ユーザー登録処理
});
```

こちらが登録API本体。

```text
registerApi()                     → APIを呼ぶ関数
POST /api/auth/register           → API
app.post("/api/auth/register", …) → APIの処理を実装する場所
```

フロントの`POST`とURLが、バックエンドの`app.post`とURLに一致することで処理がつながる。

---

## 8. `receiveRegister`とは

```ts
export const registerApi = async (
  receiveRegister: LoginData,
): Promise<void> => {
```

`receiveRegister`は、`registerApi`が受け取る引数。

将来、登録フォームから次のように渡す。

```ts
registerApi({
  email: "test@example.com",
  password: "test-password",
});
```

このとき、関数内の`receiveRegister`には次のオブジェクトが入る。

```ts
{
  email: "test@example.com",
  password: "test-password",
}
```

## 9. `JSON.stringify(receiveRegister)`の役割

```ts
body: JSON.stringify(receiveRegister),
```

JavaScriptのオブジェクトを、通信で送れるJSON文字列へ変換する。

変換前：

```ts
{
  email: "test@example.com",
  password: "test-password",
}
```

変換後：

```json
{"email":"test@example.com","password":"test-password"}
```

バックエンドでは、送信されたデータを`req.body`で受け取る。

```ts
const result = registerSchema.safeParse(req.body);
```

関係は次のとおり。

```text
フロント：receiveRegister
↓
JSON.stringifyでJSON文字列へ変換
↓
bodyとして送信
↓
バックエンド：req.bodyで受け取る
```

## 10. 今日の理解

- `registerApi`はAPI本体ではなく、APIを呼び出すフロント側の関数
- `POST /api/auth/register`が登録API
- バックエンドの`app.post("/api/auth/register", ...)`が登録処理を受け持つ
- `receiveRegister`は`registerApi`が受け取る引数
- `JSON.stringify()`でJavaScriptのオブジェクトをJSON文字列へ変換する
- `describe`の外側で作った値は、複数のテストで共有される
- `nextRoom++`は現在の値を使用した後、変数を1増やす
- `git status`は変更ファイル、`git diff`は変更内容を確認する
