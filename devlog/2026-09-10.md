## 2. 今日理解した処理の流れ

### フロントエンドから送信する

```ts
body: JSON.stringify(receiveRegister),
```

`receiveRegister`は、関数が受け取った登録情報である。

```ts
{
  email: "test@example.com",
  password: "password123",
}
```

`JSON.stringify()`によって、通信できるJSON文字列へ変換する。

```json
{
  "email": "test@example.com",
  "password": "password123"
}
```

### バックエンドで受け取る

```ts
app.use(express.json());
```

`express.json()`が、送られてきたJSON文字列をJavaScriptオブジェクトへ変換する。

```ts
req.body
```

`req.body`には、フロントエンドから送られた登録情報が入る。

### 登録情報を検査する

```ts
const result = registerSchema.safeParse(req.body);
```

- `registerSchema`：登録情報のルール
- `safeParse()`：データがルールを守っているか検査する
- `req.body`：実際に送られてきた登録情報
- `result`：検査結果

### 検査に失敗した場合

```ts
if (!result.success) {
  res.status(400).json({
    error: "Invalid registration data / 無効な登録データ",
    details: result.error.flatten(),
  });
  return;
}
```

`result.success`が`false`の場合、先頭の`!`によって条件が`true`になり、エラー処理へ入る。

```ts
if (!result.success)
```

これは次の意味になる。

> 登録情報の検査に失敗した場合

`return`によって、不正なデータのまま後続の登録処理へ進むことを防ぐ。

### 検査済みデータを取り出す

```ts
const { email, password } = result.data;
```

これは次のコードを短く書いたもの。

```ts
const email = result.data.email;
const password = result.data.password;
```

`req.body`ではなく、検査済みの`result.data`を使う。

### パスワードをハッシュ化する

```ts
const passwordHash = await bcrypt.hash(password, 10);
```

- `password`：入力されたパスワード
- `10`：ハッシュ化のコスト値
- `await`：ハッシュ化の完了を待つ
- `passwordHash`：作成されたハッシュ値

データベースには、生のパスワードを保存しない。

### ユーザーをデータベースへ保存する

```ts
const newUser = await prisma.user.create({
  data: {
    email,
    passwordHash,
  },
});
```

- `prisma.user`：`User`モデルを操作する
- `create()`：新しいユーザーを作成する
- `data`：保存するデータ
- `newUser`：保存されたユーザー情報

### 登録結果をフロントエンドへ返す

```ts
res.status(201).json({
  id: newUser.id,
  email: newUser.email,
  createdAt: newUser.createdAt,
});
```

- `201`：新しいデータの作成に成功したことを表す
- `json()`：レスポンスデータをJSON形式で返す
- `password`と`passwordHash`は返さない

## 3. 登録APIのコード

```ts
import { throwApiError } from "./apiError";

const API_BASE =
  import.meta.env.VITE_API_BASE ?? "http://localhost:3001/api";

type RegisterData = {
  email: string;
  password: string;
};

type RegisterResponse = {
  id: string;
  email: string;
  createdAt: string;
};

export const registerApi = async (
  receiveRegister: RegisterData,
): Promise<RegisterResponse> => {
  const response = await fetch(`${API_BASE}/auth/register`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(receiveRegister),
    credentials: "include",
  });

  if (!response.ok) {
    await throwApiError(response);
  }

  const data: RegisterResponse = await response.json();
  return data;
};
```

## 4. 2種類の型の違い

### バックエンドへ送るデータ

```ts
type RegisterData = {
  email: string;
  password: string;
};
```

`RegisterData`は、フロントエンドからバックエンドへ送る登録情報の型。

### バックエンドから受け取るデータ

```ts
type RegisterResponse = {
  id: string;
  email: string;
  createdAt: string;
};
```

`RegisterResponse`は、バックエンドが登録成功時に返すデータの型。

バックエンドの返り値と型を一致させる。

```ts
res.status(201).json({
  id: newUser.id,
  email: newUser.email,
  createdAt: newUser.createdAt,
});
```

パスワードが`RegisterResponse`にない理由は、バックエンドがパスワードを返していないためである。

## 5. JSONを使う理由

HTTP通信でJSONしか使えないわけではない。

登録情報のような構造化データを、項目名と値の関係を保ったまま送受信しやすいため、JSONを使用している。

```json
{
  "email": "test@example.com",
  "password": "password123"
}
```

画像・動画・PDFなどは、通常はバイナリデータや`FormData`として送信する。

JSONを使用する主な理由は次のとおり。

- 項目名と値の関係を表現できる
- 配列や入れ子のデータを表現できる
- JavaScriptオブジェクトとの変換が簡単
- 多くのプログラミング言語で扱える
- Web APIで広く使用されている

## 8. 現時点の理解度

### 理解できたこと

- JSONはHTTP通信で唯一の形式ではない
- 構造化データを送るためにJSONが適している
- フロントエンドの`body`とバックエンドの`req.body`がつながっている
- `safeParse()`は保存処理ではなく検査処理
- `result.data`は検査済みデータ
- 生のパスワードはデータベースへ保存しない
- 送信データと受信データでは必要な型が異なる
- レスポンスの型は、バックエンドが返すデータに合わせる
