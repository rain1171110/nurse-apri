## 3. 実装の要点（理解を深める）

### 1. `receiveRegister` とは

`registerApi()` が受け取る引数のことです。

```ts
await registerApi({
  email,
  password,
});
```

このデータを、`registerApi` 側では次のように受け取ります。

```ts
export const registerApi = async (
  receiveRegister: RegisterData,
): Promise<void> => {
```

この `receiveRegister` は、メールアドレスとパスワードの「箱」だと考えるとわかりやすいです。

```ts
const receiveRegister = {
  email: "register-test@example.com",
  password: "password123",
};
```

- このコードの責務（1文）:
  - サーバーに送る登録データを、APIの引数として受け取る役割を持つ
- 入力:
  - `email`, `password`
- 出力:
  - なし（`Promise<void>`）
- 型をどう絞り込んだか:
  - `RegisterData` 型で `email` と `password` の形を固定した
- null / undefined をどう安全に扱ったか:
  - 送信前にフォームの `required` で空値を避けた

### 2. `JSON.stringify()` の役割

JavaScriptのオブジェクトはそのままだと、ネットワーク越しに送れません。そこで `JSON.stringify()` で JSON 形式の文字列へ変換します。

```ts
body: JSON.stringify(receiveRegister),
```

この処理があるから、フロントから送ったデータがバックエンドの `req.body` に入ります。

```ts
const result = registerSchema.safeParse(req.body);
```

- このコードの責務（1文）:
  - 送る前のオブジェクトを、HTTPで扱える文字列に変換する
- 入力:
  - `receiveRegister` オブジェクト
- 出力:
  - JSON文字列
- 似た書き方との違い:
  - `JSON.stringify()` は「文字に変換する」
  - `safeParse()` は「その文字列が正しい形式か検証する」

### 3. `result.data` を使う理由

```ts
const result = registerSchema.safeParse(req.body);

if (!result.success) {
  return;
}

const { email, password } = result.data;
```

ここで大事なのは、`req.body` はそのまま使わないことです。

```ts
req.body; // まだ検証前のユーザー入力
result.data; // Zodで検証を通った安全なデータ
```

後続の処理では、検証済みの `result.data` を使うことで、入力の不正を減らせます。

### 4. パスワードのハッシュ化

パスワードをそのままDBに保存してはダメです。保存の前にハッシュ化します。

```ts
const passwordHash = await bcrypt.hash(password, 10);
```

保存するのは元の `password` ではなく、 `passwordHash` です。

```ts
const newUser = await prisma.user.create({
  data: {
    email,
    passwordHash,
  },
});
```

ログイン時には、入力したパスワードとDB内のハッシュ値を照合します。

```ts
const isValid = await bcrypt.compare(password, user.passwordHash);
```

- このコードの責務（1文）:
  - パスワードを安全に保管し、ログイン時に照合できるようにする
- 重要な考え方:
  - パスワードそのものは絶対に平文で持たない

### 5. 登録画面の実装

```tsx
import { useState, type FormEvent } from "react";
import { registerApi } from "./api/authApi";
import { useNavigate, Link } from "react-router-dom";

export default function RegisterPage() {
  const navigate = useNavigate();
  const [apiError, setApiError] = useState("");

  const handleSubmit = async (e: FormEvent<HTMLFormElement>) => {
    e.preventDefault();

    const formData = new FormData(e.currentTarget);
    const email = String(formData.get("email"));
    const password = String(formData.get("password"));

    const registerData = {
      email,
      password,
    };

    try {
      setApiError("");
      await registerApi(registerData);
      navigate("/login");
    } catch (error) {
      console.error("登録に失敗しました", error);

      if (error instanceof Error) {
        setApiError(error.message);
      } else {
        setApiError("登録に失敗しました");
      }
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      {apiError && <p className="text-error">{apiError}</p>}

      <label htmlFor="email">新規メールアドレス</label>
      <input id="email" name="email" type="email" required />

      <label htmlFor="password">新規パスワード</label>
      <input id="password" name="password" type="password" required />

      <button type="submit" className="btn-primary">
        登録ボタン
      </button>

      <Link to="/login" className="login-link">
        戻る
      </Link>
    </form>
  );
}
```

- このコードの責務（1文）:
  - ユーザー入力を受け取り、APIへ送信し、成功・失敗に応じて画面遷移やエラー表示を行う
- 副作用:
  - `navigate()` による画面遷移
  - `setApiError()` による画面更新
- 改善余地:
  - 入力値のバリデーションをさらに厳密化できる
  - エラーメッセージの表示位置やデザインを改善できる
