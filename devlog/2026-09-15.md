## 2. 今日理解したこと

### マッチャーとは

`expect()`の後ろに書く、「何を確認するか」を表す命令。

```ts
expect(確認したいもの).マッチャー(期待する結果);
```

例：

```ts
expect(response.status).toBe(200);

expect(loginApi).toHaveBeenCalledWith({
  email: "test@example.com",
  password: "password123",
});

expect(message).toBeInTheDocument();
```

### `toBeInTheDocument()`について

画面要素が実際にDOM内に存在することを確認するマッチャー。

```ts
expect(message).toBeInTheDocument();
```

Vitestで使うため、次のライブラリを導入した。

```bash
npm install -D @testing-library/jest-dom
```

テストファイルの先頭で読み込む。

```ts
import "@testing-library/jest-dom/vitest";
```

### `getByText()`と`findByText()`の違い

```text
getByText()
→ 今すでに表示されている要素を探す

findByText()
→ 非同期処理後に表示される要素を待って探す
```

画面遷移後の要素は次のように確認する。

```ts
const message = await screen.findByText("患者一覧");

expect(message).toBeInTheDocument();
```

### `vi.mock()`の役割

本物のAPI関数を、テスト用の偽物へ置き換える。

```ts
vi.mock("./api/authApi", () => ({
  loginApi: vi.fn(),
}));
```

これにより、実際のバックエンドへ通信せず、成功や失敗を再現できる。

```text
vi.mock()
→ 関数を偽物に置き換える

mockResolvedValue()
→ 成功を再現する

mockRejectedValue()
→ 失敗を再現する
```

### importした関数とPropsのモックの違い

`loginApi`は別ファイルからimportしているため、`vi.mock()`を使う。

```ts
import { loginApi } from "./api/authApi";

vi.mock("./api/authApi", () => ({
  loginApi: vi.fn(),
}));
```

`onLoginSuccess`はPropsとして渡す関数なので、テスト内で`vi.fn()`を作る。

```ts
const onLoginSuccess = vi.fn();

<LoginPage onLoginSuccess={onLoginSuccess} />
```

判断基準：

```text
別ファイルからimportする関数
→ vi.mock("ファイルのパス")

Propsとして渡す関数
→ vi.fn()で作成して直接渡す
```

### `path`とPropsの違い

```text
path
→ どのURLでコンポーネントを表示するか

Props
→ コンポーネントが必要とする値や関数を渡す
```

```tsx
<Route
  path="/login"
  element={<LoginPage onLoginSuccess={onLoginSuccess} />}
/>
```

- `path="/login"`：表示するURL
- `onLoginSuccess={onLoginSuccess}`：LoginPageへ渡す関数

### `loginApi`の戻り値

`loginApi`は`Promise<void>`なので、成功時には値を返さない。

```ts
vi.mocked(loginApi).mockResolvedValue(undefined);
```

```text
email・password
→ loginApiへ渡す引数

undefined
→ loginApi成功時の戻り値
```
