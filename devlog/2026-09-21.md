## 1. `vi.mock()`の理解

### モジュール全体をモックする方法

```ts
vi.mock("./api/authApi", () => ({
  loginApi: vi.fn(),
  logoutApi: vi.fn(),
  registerApi: vi.fn(),
}));
```

この書き方では、`authApi.ts`全体が次のモックに置き換わる。

- `loginApi`
- `logoutApi`
- `registerApi`

3つとも本物の`fetch()`を実行しないため、バックエンドへ通信しない。

### 一部だけをモックする方法

```ts
vi.mock("./api/authApi", async (importOriginal) => {
  const actual = await importOriginal<
    typeof import("./api/authApi")
  >();

  return {
    ...actual,
    logoutApi: vi.fn(),
  };
});
```

この書き方では、`logoutApi`だけがモックになる。

```text
loginApi    → 本物
registerApi → 本物
logoutApi   → モック
```

### `importOriginal`の役割

```ts
const actual = await importOriginal<
  typeof import("./api/authApi")
>();
```

本物のモジュールを読み込み、`actual`へ入れる。

読み込んだだけでは関数は実行されないため、その時点では通信は発生しない。ただし、本物のAPI関数がテスト中に呼ばれると、`fetch()`が実行される可能性がある。

### 今回、全モックを選んだ理由

`authApi.ts`からexportされている次の3関数は、すべて通信処理だった。

```ts
loginApi
logoutApi
registerApi
```

そのため、Appテストでは3つとも明示的にモックする方が、本物の通信を確実に防げて意図も分かりやすい。

## 2. モックに関する復習クイズ

全8問に回答し、結果は以下だった。

```text
8問中8問正解
```

理解したポイント：

- `vi.mock()`は指定したモジュール全体を置き換える
- `vi.fn()`はテスト用のモック関数を作る
- `importOriginal()`は本物のモジュールを読み込む
- 本物の関数は、読み込んだだけでは実行されない
- `...actual`で本物のexportをコピーできる
- 後ろに書いた同名プロパティが、前の値を上書きする
- `importOriginal`は一部だけモックしたい場合に向いている
- API通信を確実に防ぎたい場合は、通信関数をすべてモックする

## 4. ログアウト失敗時のテスト

### 確認する仕様

```text
ログアウトAPIが失敗する
↓
エラーメッセージを表示する
↓
ログイン状態を維持する
```

### 追加したテスト

```tsx
it("ログアウトに失敗したらエラーを表示してログイン状態を維持する", async () => {
  vi.mocked(fetchAppData).mockResolvedValue({
    patients: [],
    records: [],
  });

  vi.mocked(logoutApi).mockRejectedValue(
    new Error("ログアウトに失敗しました"),
  );

  const user = userEvent.setup();

  render(
    <MemoryRouter initialEntries={["/"]}>
      <App />
    </MemoryRouter>,
  );

  const logoutButton = await screen.findByRole("button", {
    name: "ログアウトボタン",
  });

  await user.click(logoutButton);

  expect(logoutApi).toHaveBeenCalledTimes(1);

  expect(
    await screen.findByText("ログアウトに失敗しました"),
  ).toBeInTheDocument();

  expect(
    screen.getByRole("button", {
      name: "ログアウトボタン",
    }),
  ).toBeInTheDocument();
});
```

### 重要なポイント

ログアウトに失敗すると、`App.tsx`では次の処理まで進まない。

```ts
setIsLoggedIn(false);
```

したがって、ログインボタンではなく、ログアウトボタンが残っていることを確認する。

## 5. ログイン成功時のApp統合テスト

### 確認する仕様

```text
App起動
↓
データ取得が401で失敗
↓
ログイン画面を表示
↓
ログイン情報を入力
↓
loginApiが成功
↓
Appがデータを再取得
↓
患者一覧を表示
```

### 追加したテスト

```tsx
it("未ログイン状態からログインに成功したら、患者一覧を表示する", async () => {
  vi.mocked(loginApi).mockResolvedValue(undefined);

  vi.mocked(fetchAppData)
    .mockRejectedValueOnce(new Error("API error:401"))
    .mockResolvedValueOnce({
      patients: [],
      records: [],
    });

  const user = userEvent.setup();

  render(
    <MemoryRouter initialEntries={["/"]}>
      <App />
    </MemoryRouter>,
  );

  const emailInput =
    await screen.findByLabelText("メールアドレス");

  const passwordInput =
    screen.getByLabelText("パスワード");

  await user.type(emailInput, "test@example.com");
  await user.type(passwordInput, "password123");

  const loginButton = screen.getByRole("button", {
    name: "ログインボタン",
  });

  await user.click(loginButton);

  expect(loginApi).toHaveBeenCalledTimes(1);

  expect(loginApi).toHaveBeenCalledWith({
    email: "test@example.com",
    password: "password123",
  });

  expect(
    await screen.findByText("患者一覧"),
  ).toBeInTheDocument();
});
```

## 6. `mockRejectedValueOnce`と`mockResolvedValueOnce`

```ts
vi.mocked(fetchAppData)
  .mockRejectedValueOnce(new Error("API error:401"))
  .mockResolvedValueOnce({
    patients: [],
    records: [],
  });
```

同じモック関数について、呼び出される順番ごとに異なる結果を設定している。

| 呼び出し | 結果 |
|---|---|
| 1回目 | 401エラー |
| 2回目 | データ取得成功 |

今回のテストでは、次の状態変化を再現している。

```text
1回目のfetchAppData
→ App起動時
→ 401エラー
→ 未ログイン

2回目のfetchAppData
→ ログイン成功後
→ データ取得成功
→ ログイン済み
```

### `Once`がない場合

```ts
vi.mocked(fetchAppData).mockRejectedValue(
  new Error("API error:401"),
);
```

`Once`がなければ、何回呼ばれても401エラーになる。

```text
1回目 → 401
2回目 → 401
3回目 → 401
```

そのため、ログイン後も患者一覧を表示できない。

## 7. `findBy`と`await`

次のコードでは、`await`が必要になる。

```ts
const emailInput =
  await screen.findByLabelText("メールアドレス");
```

`findByLabelText()`は非同期関数なので、`await`がない場合の戻り値は次の型になる。

```ts
Promise<HTMLElement>
```

`await`を付けると、実際の要素を取得できる。

```ts
HTMLElement
```

今回のAppは次の順番で表示が変化するため、最初の入力欄には`findByLabelText()`を使用した。

```text
読み込み中
↓
401エラー
↓
ログイン画面へ移動
↓
入力欄を表示
```
