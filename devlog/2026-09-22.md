### 間違えた問題

```ts
expect(loginApi).toHaveBeenCalledTimes(1);
```

これは、`loginApi`が何回呼ばれたかを確認する。

```ts
expect(loginApi).toHaveBeenCalledWith({
  email: "test@example.com",
  password: "password123",
});
```

これは、`loginApi`へ渡された引数を確認する。

### 整理

| コード | 役割 |
|---|---|
| `toHaveBeenCalledTimes(1)` | 呼び出し回数を検証 |
| `toHaveBeenCalledWith(...)` | 渡された引数を検証 |
| `mockResolvedValue(...)` | 成功時の動作を設定 |
| `mockRejectedValue(...)` | 失敗時の動作を設定 |

`mock...`はテスト前の動作設定、`expect...`は実行結果の検証。

## 6. package.jsonの改善

変更前：

```json
"build": "vite build"
```

この状態では、Viteのビルドしか実行されなかった。

変更後：

```json
"scripts": {
  "dev": "vite",
  "api": "tsx watch server/index.ts",
  "typecheck": "tsc -b && tsc --project server/tsconfig.json --noEmit",
  "build": "npm run typecheck && vite build",
  "lint": "eslint .",
  "preview": "vite preview",
  "test": "vitest run",
  "test:watch": "vitest",
  "db:dev": "prisma dev",
  "db:studio": "prisma studio"
}
```

これにより、次の1コマンドで型チェックと本番ビルドを実行できる。

```bash
npm run build
```

実行順序：

```text
フロントエンドの型チェック
↓
バックエンドの型チェック
↓
Viteの本番ビルド
```

`&&`は、左側のコマンドが成功した場合だけ右側を実行する。

```text
npm run typecheck 成功
→ vite buildを実行

npm run typecheck 失敗
→ vite buildは実行しない
```

### Missing scriptエラー

最初は次だけを追加していた。

```json
"build": "npm run typecheck && vite build"
```

しかし、次の`typecheck`の登録がなかった。

```json
"typecheck": "tsc -b && tsc --project server/tsconfig.json --noEmit"
```

そのため、次のエラーになった。

```text
Missing script: "typecheck"
```

これは、JavaScriptで関数を呼び出しているのに、その関数を定義していない状態に近い。

## 8. JSONは暗記すべきか

細かいコマンドを暗記する必要はない。

理解しておく内容：

```json
{
  "scripts": {
    "名前": "実行するコマンド"
  }
}
```

例えば、

```json
"test": "vitest run"
```

と登録すると、次で実行できる。

```bash
npm run test
```

優先して理解すること：

- JSONは`"キー": 値`で書く
- 項目同士を`,`で区切る
- `scripts`へコマンドを登録できる
- `npm run 名前`で登録したコマンドを実行できる
- `&&`は左側が成功した場合に右側を実行する

`tsc`などの細かいオプションは、その都度調べればよい。

## 10. テストでpropsを渡す意味

```tsx
const onSubmit = vi.fn();

render(
  <AddPatientForm
    patients={[]}
    onSubmit={onSubmit}
    showAddForm={false}
    setShowAddForm={vi.fn()}
  />,
);
```

テストには本物の親コンポーネントがないため、テスト側が親の代わりに必要なpropsを渡す。

### patients

```tsx
patients={[]}
```

今回は患者データを使わないので、空配列を渡す。

### onSubmit

```tsx
onSubmit={onSubmit}
```

本番の保存関数の代わりに、`vi.fn()`で作ったモック関数を渡す。

```ts
const onSubmit = vi.fn();
```

### showAddForm

```tsx
showAddForm={false}
```

フォームを非表示にする条件。

### setShowAddForm

```tsx
setShowAddForm={vi.fn()}
```

本番では`useState`の更新関数が渡される。

今回のテストでは実行されないが、必須propsなのでモック関数を渡す。

## 11. vi.fn()を直接渡す場合との違い

変数へ保存する方法：

```ts
const onSubmit = vi.fn();

<AddPatientForm onSubmit={onSubmit} />
```

直接渡す方法：

```tsx
<AddPatientForm onSubmit={vi.fn()} />
```

どちらもモック関数を渡している。

後から呼び出しを検証する場合は、変数へ保存する。

```ts
expect(onSubmit).toHaveBeenCalledTimes(1);
```

後から確認しない場合は、直接`vi.fn()`を渡してもよい。

## 12. 存在しない要素の確認

フォームが存在しないことを確認する場合は、`queryByRole`を使う。

```tsx
expect(
  screen.queryByRole("heading", { name: "患者を追加" }),
).not.toBeInTheDocument();
```

使い分け：

```text
getBy...   ：今存在する要素を取得。なければ即エラー
queryBy... ：存在しない要素の確認。なければnull
findBy...  ：非同期処理後に表示される要素を待つ
```
