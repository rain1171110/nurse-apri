## 復習クイズで確認したこと

- `vi.fn()` はテスト用の関数。コンポーネントに渡した**同じ関数**を `expect` で確認する。
- `toHaveBeenCalledWith(...)` は、関数に渡された引数を確認する。
- 表示されていない要素の確認には `queryByRole` を使う。
- `await user.click(...)` でクリック操作の完了を待つ。
- テストは「モックを作る → 渡す → 操作する → 結果を確認する」の順に組み立てる。

## 入力検証の仕組み

氏名と部屋番号が必須になる箇所を確認した。

```ts
name: z.string().trim().min(1, "氏名は必須です")

room: optionalNumber(/* ... */)
  .refine((value) => value !== undefined, {
    message: "部屋番号は必須です",
  })
```

氏名は空白を除いた後に1文字以上必要。部屋番号は `undefined` のままでは検証に通らない。部屋番号の重複は、既存患者から作った `usedRooms` と入力値を照合する。

フォーム送信時は、React Hook Form の `handleSubmit` が `zodResolver(schema)` を使って検証する。

```tsx
<form onSubmit={handleSubmit(handleAddPatientSubmit, onErrorsChange)}>
```

- 検証成功：`handleAddPatientSubmit(data)` が呼ばれ、その中で親から渡された `onSubmit(data)` が呼ばれる。
- 検証失敗：`handleAddPatientSubmit` には進まない。`onErrorsChange` が渡されていればエラーを渡して呼ばれ、フォームにもエラー文言が表示される。

この分岐は `handleSubmit` の内部で行われるため、このコンポーネントに検証用の `try/catch` は書かれていない。

## 追加したテスト

### 1. 氏名が空欄

部屋番号だけ入力して保存。`onSubmit` が呼ばれず、「氏名は必須です」が表示されることを確認した。

### 2. 部屋番号が空欄

氏名だけ入力して保存。`onSubmit` が呼ばれず、「部屋番号は必須です」が表示されることを確認した。

### 3. 部屋番号が重複

`patients` に部屋番号 `101` の既存患者を渡し、新しい患者にも `101` を入力した。`onSubmit` が呼ばれず、「この部屋番号は既に使用されています」が表示されることを確認した。

```tsx
patients={[{ id: "testId", name: "testName", room: 101 }]}
```

`patients` の型は `Patient[]` なので配列で渡す。`Patient` では `id`、`name`、`room` が必須で、それ以外の項目は省略できる。

## 表示と要素取得について整理したこと

実際の `PatientList` では `showAddForm` の初期値は `false`。フォームを開く操作で `true` になる。

一方、今回の `AddPatientForm` 単体テストでは、テストから直接 `showAddForm={true}` を渡している。そのため `render(...)` の直後からフォームが表示される。

```tsx
const roomInput = screen.getByLabelText("部屋番号");
await user.type(roomInput, "101");
```

`getByLabelText` は**今ある入力欄を取得**する。`findByLabelText` は**後から表示される入力欄を待つ**。どちらを使うかは「入力するかどうか」や「APIを使うかどうか」では決まらない。

## 保存成功後の処理

```tsx
const savedPatient = await onSubmit(data);

if (!savedPatient) {
  return;
}

reset();
setShowAddForm(false);
```

`onSubmit` が患者データを返したら、フォームの入力値をリセットし、親にフォームを閉じるよう依頼する。戻り値が `undefined` なら、その前に `return` する。

次のテストに向けて、保存成功を返すモックと、呼び出しを確認できる `setShowAddForm` を用意した。

```tsx
it("保存成功時にフォームを閉じる処理を呼ぶ", async () => {
  const onSubmit = vi.fn().mockResolvedValue({
    id: "testId",
    name: "testName",
    room: 101,
  });
  const setShowAddForm = vi.fn();
  const user = userEvent.setup();

  render(
    <AddPatientForm
      patients={[]}
      onSubmit={onSubmit}
      showAddForm={true}
      setShowAddForm={setShowAddForm}
    />,
  );

  // 次回：氏名と部屋番号を入力して保存する
  // 次回：setShowAddForm(false) が呼ばれたか確認する
});
```

`setShowAddForm` はこの単体テストではモックなので、呼ばれても親の状態は実際には変わらない。まず確認する対象は、**フォームを閉じるよう依頼したこと**。
