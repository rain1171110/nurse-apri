```tsx
// 保存結果が undefined の場合の設定
const onSubmit = vi.fn().mockResolvedValue(undefined);
```

## 理解したこと

`mockResolvedValue(undefined)` は、**`onSubmit` を呼ばない設定ではない**。`onSubmit` が呼ばれたときに、結果として `undefined` を返す設定。

実際の送信処理は次の形だった。

```tsx
const handleAddPatientSubmit = async (
  data: PatientOutput,
): Promise<void> => {
  const savedPatient = await onSubmit(data);

  if (!savedPatient) {
    return;
  }

  reset();
  setShowAddForm(false);
};
```

`savedPatient` が `undefined` なら `!savedPatient` は `true` になり、`return` で処理が終わる。そのため、下の `reset()` と `setShowAddForm(false)` は実行されない。患者データが返った場合は処理が続き、フォームをリセットして閉じる。

## 修正した点

既存の保存成功テストで、保存ボタンをクリックする前に `onSubmit` の呼び出しを確認していたため、一度テストが失敗した。`await user.click(saveButton)` を先に移動して解決した。

## 次回の続き

保存成功時に患者データが返ると、`if (!savedPatient) { return; }` で止まるのか、`reset()` に進むのかを確認するところから再開する。その後、保存失敗時のテストが非同期処理の完了後に判定できているか、理解度に合わせて見直す。
