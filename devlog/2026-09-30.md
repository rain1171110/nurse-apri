## 2. 今日学んだこと

### 要素の取得方法

| 方法 | 用途 | 見つからない場合 | await |
| --- | --- | --- | --- |
| getBy | 今ある要素を取得する | すぐエラー | 不要 |
| queryBy | 存在しないことを確認する際に使う | nullを返す | 不要 |
| findBy | 要素が現れるまで待つ | 制限時間内に現れなければエラー | 使用する |

```tsx
// 今ある要素を取得する
const saveButton = screen.getByRole("button", {
  name: "保存",
});

// 存在しないことを確認する
expect(
  screen.queryByRole("heading", { name: "患者を追加" }),
).not.toBeInTheDocument();

// 非同期で現れる要素を待つ
const heading = await screen.findByRole("heading", {
  name: "患者一覧",
});
```

- queryByを使うだけで「存在しない確認」になるわけではない。
- `.toBeInTheDocument()` は存在することを確認する。
- `.not.toBeInTheDocument()` は存在しないことを確認する。
- findByが待つのは、指定した要素が現れること。
- 入力欄の値が変わるまで待つ場合は、waitForで検証する。

```tsx
await waitFor(() => {
  expect(nameInput).toHaveValue("");
});
```

### 境界値テスト

部屋番号の仕様は1〜999。境界の内側と外側を確認する。

| 入力 | 期待する動作 | 確認状況 |
| --- | --- | --- |
| 0 | 保存処理を呼ばず、エラーを表示する | 今日追加 |
| 1 | 数値1を保存処理に渡す | 今日追加 |
| 999 | 数値999を保存処理に渡す | 既存テストで確認済み |
| 1000 | 保存処理を呼ばず、エラーを表示する | 今日検証を追加 |

- 0を拒否するテストだけでは、1が許可されるとは保証できない。
- 誤って「2以上」にしても、0を拒否するテストは成功してしまう。
- 999は既存の保存テストで確認しているため、同じ確認を追加する必要はない。

### 引数と戻り値

```js
function addOne(number) {
  return number + 1;
}

const result = addOne(10);
```

- 引数: 関数に渡した10
- 戻り値: 関数から返ってきた11
- result: 戻り値の11が入る変数

```js
function showNumber(number) {
  console.log(number);
}

const result = showNumber(10);
```

- console.logは表示する処理。
- returnは呼び出し元へ値を返す処理。
- この関数にはreturnがないため、resultはundefinedになる。

### モックの戻り値と検証対象

```tsx
const onSubmit = vi.fn().mockResolvedValue(undefined);

const result = await onSubmit({
  name: "testName",
  room: 1,
});
```

| 対象 | 値 |
| --- | --- |
| 渡した引数 | { name: "testName", room: 1 } |
| awaitした結果 | undefined |

```tsx
// 引数を確認する
expect(onSubmit).toHaveBeenCalledWith({
  name: "testName",
  room: 1,
});

// awaitした結果を確認する
expect(result).toBeUndefined();

// 今回は上と同じ検証
expect(result).toBe(undefined);
```

- mockResolvedValue(undefined)は、awaitした結果をundefinedにする設定。
- undefinedだから自動的にテストが失敗するわけではない。
- 実際の値や動作が、検証で期待した内容と一致すれば成功する。
- toHaveBeenCalledWithは戻り値ではなく、呼び出し時の引数を確認する。
- 今回は保存処理に値が渡ることを検証しており、保存完了を検証しているわけではない。

### 部屋番号0のテスト

```tsx
it("部屋番号が0なら保存されず、エラーを表示する", async () => {
  const onSubmit = vi.fn().mockResolvedValue(undefined);
  const onErrorsChange = vi.fn();
  const setShowAddForm = vi.fn();
  const user = userEvent.setup();

  render(
    <AddPatientForm
      patients={[]}
      onSubmit={onSubmit}
      showAddForm={true}
      setShowAddForm={setShowAddForm}
      onErrorsChange={onErrorsChange}
    />,
  );

  const nameInput = await screen.findByLabelText("氏名");
  const roomInput = await screen.findByLabelText("部屋番号");

  await user.type(nameInput, "testName");
  await user.type(roomInput, "0");

  const saveButton = screen.getByRole("button", {
    name: "保存",
  });
  await user.click(saveButton);

  expect(onSubmit).not.toHaveBeenCalled();
  expect(onErrorsChange).toHaveBeenCalled();
  expect(screen.getByText("部屋番号は1以上")).toBeInTheDocument();
});
```
