## 2. 今日の気づき

### 入力の追加と削除は別の操作

- `user.type(searchInput, " ")` は空白を追加する。
- `" "` は空白1文字、`""` は文字がない空文字列。
- 入力欄を空にするには `await user.clear(searchInput)` を使う。
- `expect` は状態を確認する処理で、入力値を変更する処理ではない。

### getByRoleとqueryByRoleの違い

| 方法 | 1個見つかった場合 | 見つからなかった場合 | 基本の用途 |
| --- | --- | --- | --- |
| getByRole | 要素を返す | エラーになる | 表示されていることの確認 |
| queryByRole | 要素を返す | nullを返す | 表示されていないことの確認 |

- `getByRole` は見つからない時点でエラーになり、後ろの `.not` まで進めない。
- `queryByRole` でも表示の確認はできるが、`getByRole` は要素がないときに詳しい検索エラーを出してくれる。
- 検索方法は、期待する状態に合わせて選ぶ。

### 操作と確認の順番が重要

1. 検索文字を入力する。
2. 検索で除外された患者がいないことを確認する。
3. 検索文字を消す。
4. 全患者が再表示されたことを確認する。

### 検索文字とReactのkey

- 現在の検索処理は、氏名または部屋番号の文字列に検索文字が含まれるかを判定する。
- `"101 田中"` は、氏名 `"田中"` にも部屋番号 `"101"` にも含まれない。
- `key={patient.id}` に使う患者IDは、重複しない値にする。

## 3. 今日追加したテスト

既存の `describe("PatientList", () => { ... })` 内に追加。

```tsx
it("検索結果が0件ならメッセージを表示する", async () => {
  const user = userEvent.setup();

  const patients = [
    { id: "patient1", name: "田中", room: 101 },
    { id: "patient2", name: "山本", room: 202 },
  ];

  render(
    <MemoryRouter>
      <PatientList
        patients={patients}
        isLoading={false}
        onErrorsChange={vi.fn()}
        addPatient={vi.fn().mockResolvedValue(undefined)}
      />
    </MemoryRouter>,
  );

  const searchInput = screen.getByLabelText("患者検索");
  await user.type(searchInput, "999号室 岡﨑");

  expect(
    screen.getByText("該当する患者がいません"),
  ).toBeInTheDocument();
});

it("検索文字を消すと全患者が再表示されるテスト", async () => {
  const user = userEvent.setup();

  const patients = [
    { id: "patient1", name: "田中", room: 101 },
    { id: "patient2", name: "山本", room: 202 },
  ];

  render(
    <MemoryRouter>
      <PatientList
        patients={patients}
        isLoading={false}
        onErrorsChange={vi.fn()}
        addPatient={vi.fn().mockResolvedValue(undefined)}
      />
    </MemoryRouter>,
  );

  const searchInput = screen.getByLabelText("患者検索");

  await user.type(searchInput, "田中");

  expect(
    screen.queryByRole("heading", { name: "202号室 山本" }),
  ).not.toBeInTheDocument();

  await user.clear(searchInput);

  expect(
    screen.getByRole("heading", { name: "101号室 田中" }),
  ).toBeInTheDocument();
  expect(
    screen.getByRole("heading", { name: "202号室 山本" }),
  ).toBeInTheDocument();
});

it("氏名の一部分でも検索できるテスト", async () => {
  const user = userEvent.setup();

  const patients = [
    { id: "patient1", name: "田中", room: 101 },
    { id: "patient3", name: "山田", room: 303 },
    { id: "patient2", name: "山本", room: 202 },
  ];

  render(
    <MemoryRouter>
      <PatientList
        patients={patients}
        isLoading={false}
        onErrorsChange={vi.fn()}
        addPatient={vi.fn().mockResolvedValue(undefined)}
      />
    </MemoryRouter>,
  );

  const searchInput = screen.getByLabelText("患者検索");
  await user.type(searchInput, "田");

  expect(
    screen.queryByRole("heading", { name: "202号室 山本" }),
  ).not.toBeInTheDocument();
  expect(
    screen.getByRole("heading", { name: "101号室 田中" }),
  ).toBeInTheDocument();
  expect(
    screen.getByRole("heading", { name: "303号室 山田" }),
  ).toBeInTheDocument();
});
```

## 4. エラーと対応

| 問題 | 原因 | 対応 |
| --- | --- | --- |
| 0件メッセージのテストが失敗 | 古い `getByText(" ")` が残っていた | 不要な確認を削除 |
| 山本の非表示確認で失敗 | `getByRole` が見つからずエラーになった | `queryByRole` に変更 |
| 検索解除の確認順が不適切 | `clear` 後に山本の非表示を確認していた | 非表示確認を `clear` 前に移動 |
| 部分一致の検証になっていなかった | 表示確認前に検索文字を消していた | 部分一致テストの `clear` を削除 |
| 患者IDが重複 | 田中・山田の両方が `patient1` | 山田を `patient3` に変更 |
