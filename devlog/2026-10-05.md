## 2. 実装したコード

既存のReact Routerのimportに、RoutesとRouteを追加する。

```tsx
import { MemoryRouter, Routes, Route } from "react-router-dom";
```

describe内に、次のテストを追加した。

```tsx
it("患者のカードをクリックすると詳細画面へ移動する", async () => {
  const user = userEvent.setup();

  const patients = [
    { id: "patient1", name: "田中", room: 101 },
    { id: "patient3", name: "山田", room: 303 },
    { id: "patient2", name: "山本", room: 202 },
  ];

  render(
    <MemoryRouter initialEntries={["/"]}>
      <Routes>
        <Route
          path="/"
          element={
            <PatientList
              patients={patients}
              isLoading={false}
              onErrorsChange={vi.fn()}
              addPatient={vi.fn().mockResolvedValue(undefined)}
            />
          }
        />
        <Route
          path="/patient/patient1"
          element={<h1>田中の詳細画面</h1>}
        />
      </Routes>
    </MemoryRouter>,
  );

  const patientHeading = screen.getByRole("heading", {
    name: "101号室 田中",
  });

  await user.click(patientHeading);

  expect(
    await screen.findByRole("heading", { name: "田中の詳細画面" }),
  ).toBeInTheDocument();
});
```

## 3. 気づき・理解したこと

### 要素の取得

- getByRoleには、headingやbuttonなどのroleを指定する。
- classNameはroleではないため、getByRoleには指定できない。
- getByRoleは、要素が見つからないと例外を投げる。
- queryByRoleは、要素が見つからないとnullを返すため、非存在の確認に使える。
- findByRoleはPromiseを返すため、awaitで要素の取得を待つ。

### 画面遷移の確認

- 一覧にもある「101号室 田中」を確認するだけでは、詳細画面への移動を証明できない。
- 移動先だけにある「田中の詳細画面」を確認することで、ルートに到達したことを検証できる。
- 今回は実際のPatientDetailではなく、テスト用の見出しを表示して遷移先を確認した。
- このテストでは、実際の詳細画面の内容やデータ取得までは確認していない。

### URLと見出しの役割

- PatientListのクリック処理が、移動先のURLを決める。
- Routeのpathが、どのURLでelementを表示するかを決める。
- findByRoleのnameは、表示された見出しを探す条件であり、移動先を決めるものではない。

田中のカードから `/patient/patient1` に移動するのに、
テスト用ルートを `/patient/patient2` にすると、URLが一致しない。
そのため「田中の詳細画面」が表示されず、テストは失敗する。
