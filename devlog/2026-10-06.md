## 3. 気づき・理解したこと

### 患者データから表示までの流れ

1. PatientListに渡した患者データにidがある。
2. カードのクリック処理がpatient.idを使って移動先のURLを作る。
3. Routeの「/patient/:id」が、そのURLに一致する。
4. useParamsがURLの「:id」に当たる部分を取り出す。
5. テスト用コンポーネントが取得したIDを見出しに表示する。
6. findByRoleが、その見出しを探して確認する。

| 処理 | 役割 |
| --- | --- |
| getByRole | クリックするDOM要素を取得する |
| user.click | 取得した要素をクリックする |
| navigate | 移動先のURLを決める |
| useParams | 移動後のURLからパラメータを取得する |
| returnのJSX | 取得したIDを画面に表示する |
| findByRole | 期待する見出しが表示されるまで待って取得する |

- getByRoleで「202号室 山本」を探しても、患者IDが返るわけではない。
- patient.idは患者データから来る。Routeが決める値ではない。
- useParamsは患者データを直接読むのではなく、移動後のURLを読む。
- JSXの「{id}」には変数の値が入る。
- 普通の文字列「"IDは{id}です"」では、{id}はそのまま文字になる。
- findByRoleのnameは、今回の見出しに表示される文字に合わせる。
- 固定パス「/patient/patient1」でも、そのパスへの遷移は確認できる。
- 動的なRouteとID表示を使うと、複数の患者の遷移を同じ仕組みで確認できる。

## 4. 詰まったところと対応

| 詰まったところ | 原因・理解 | 対応 |
| --- | --- | --- |
| Routeのpathとnavigateの書き方が混ざった | Routeは「:id」で受け取り、navigateは実際のIDを埋め込む | 役割を分けて確認した |
| h1内にPatientDetailForTest(id)を書いた | JSX内の文字として表示され、コンポーネントは動かない | `<PatientDetailForTest />`に変更した |
| 見出しのnameが患者IDになる理由が曖昧だった | URLから取得したidがJSXに入り、表示文字になる | IDを変えた確認問題で流れを追った |
| 編集前に「患者情報を編集」をクリックしようとした | その見出しは編集後に表示される | 「編集」ボタンをクリックする形に変更した |
| useOutletContextがnullになった | PatientDetailへOutletのcontextが届いていなかった | contextを渡す親Routeの内側に子Routeを配置した |
