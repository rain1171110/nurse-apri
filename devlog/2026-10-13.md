## 3. 実装の要点（理解を深める）

```tsx
function App() {
  const location = useLocation();

  // 省略

  return (
    <>
      {/* ルート定義など */}

      {isLoggedIn && location.pathname === "/" && (
        <button type="button" className="btn-primary" onClick={handleLogout}>
          ログアウトボタン
        </button>
      )}
    </>
  );
}
```

- このコードの責務（1文）: ログイン中で患者一覧画面にいるときだけログアウトボタンを表示する。
- 入力: React Routerが管理している現在のURL、`isLoggedIn`の値。
- 出力: 条件が両方成立したときにログアウトボタンを表示する。
- 副作用（ある場合）: ボタンを押すと`handleLogout`を実行する。
- 型をどう絞り込んだか: 型ガードは使っていない。`pathname`と文字列`"/"`を比較している。
- null / undefined をどう安全に扱ったか: この条件式では該当なし。
- 型で守れていること: `useLocation()`の戻り値をReact Routerの型で扱う。
- 似た書き方との違い: `window.location.pathname`を直接読むのではなく、React Routerのフックを使って現在地を扱う。
- 修正ポイント（自分がどこを変えたか）: `location`を取得し、表示条件に`location.pathname === "/"`を加えた。
- その修正で理解したこと: `main.tsx`で`BrowserRouter`が`App`を囲んでいるため、`App`内で`useLocation()`を使える。
- 改善余地（命名/分割/重複/境界条件）: 画面が増えて表示条件が複雑になった場合は、レイアウトやルート構成の整理を検討する。

## 5. つまずきから学ぶ（再発防止まで）

- つまずいた現象: `useLocation()`を`App`で使える理由と、`pathname`の扱いが分かりにくかった。

- 根本原因（思考・知識・確認不足のどれか）: Routerが提供する範囲内でフックを使うという知識の整理不足。
- 切り分け手順（次回使える手順化）:

  - 4. 対象画面と対象外画面の両方で動作確認する
- 再発防止ルール（チェック項目にする）: Routerのフックを使う前に、`main.tsx`などでRouterがコンポーネントを囲んでいるか確認する。
