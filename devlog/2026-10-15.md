- 修正前のコードの問題点: アプリコードの不具合ではなく、Git操作ミスで履歴認識が一時的に不安定になった。
- 修正後の意図: 「共通の土台からA/Bを分ける」という競合練習の条件を正しくそろえる。
- なぜその修正で直ったのか（3行で説明）:
  1. `git diff --cached --stat 06ee8b2`で土台との差分がないことを確認した。
  2. 正しいブランチ名を土台コミットから作り直した。
  3. その上でB側変更をコミットし、作業状態をcleanに戻した。
- 自分が理解した手順:
  1. まず`git status`で現在の状態を確認する
  2. 意図した土台コミットを`git log`や`git branch -avv`で確認する
  3. 必要なら土台からブランチを作り直す
  4. 変更を`add`→`commit`して最後に`git status`で確認する
- 次回同じような時にやること: 焦って操作を続けず、先に「どのコミットを土台にしたいか」を言葉で固定してから進める。

## 2. 技術判断ログ（エンジニア視点）

- 解決したかった課題: 競合練習のために、同じ行をA/Bで別内容にした2本の履歴を正しく用意する。
- 検討した選択肢:
  - 案A: Bを`06ee8b2`（共通土台）から作って変更する
  - 案B: Aの先頭`8bb35bf`からBを作って変更する
- 採用した案: 案A
- 採用理由（性能/保守性/実装コスト/安全性）: A/Bが同じ親から分岐するため、競合の発生条件を明確に再現できる。
- 採用しなかった案を捨てた理由: 案BだとBがAを含んでしまい、練習したい「独立した2変更のマージ」が崩れるため。

## 3. 実装の要点（理解を深める）

```bash
git switch -c practice/git-conflict-basics
git add conflict-practice.txt
git commit -m "test: add conflict-practice file"
git switch -c practice/conflict-a
git add conflict-practice.txt
git commit -m "test: change conflict file on branch A"
git switch -c practice/conflict-b 06ee8b2
git add conflict-practice.txt
git commit -m "test: change conflict file on branch B"
git status
```

- このコードの責務（1文）: 競合を起こす前提となる「共通土台からのA/B分岐」と「各ブランチの別変更」を履歴として作る。
- 入力: ブランチ名、土台コミットID（`06ee8b2`）、変更対象ファイル（`conflict-practice.txt`）。
- 出力: A/Bそれぞれの変更コミットが作成され、競合演習に進める状態。
- 副作用（ある場合）: ブランチ作成、コミット履歴追加、作業ツリー状態の更新。
- 型をどう絞り込んだか: 対象外（CLI操作のため）。
- null / undefined をどう安全に扱ったか: 対象外（CLI操作のため）。
- 型で守れていること: 対象外。
- 似た書き方との違い: `git switch -c ブランチ名`は現在位置から作成、`git switch -c ブランチ名 コミットID`は土台を明示して作成。
- 修正ポイント（自分がどこを変えたか）: Bブランチを誤名から正しい名前へ再作成し、土台を`06ee8b2`に固定した。
- その修正で理解したこと: 競合練習は「どこから分岐したか」が最重要で、分岐点がズレると練習結果も変わる。
- 改善余地（命名/分割/重複/境界条件）: 作成直後に`git branch -avv`で各ブランチの指すコミットを毎回確認する。

## 5. つまずきから学ぶ（再発防止まで）

- つまずいた現象: ブランチ名誤入力後、全ファイルが新規に見える状態になった。
- 直接原因: ブランチ作成時のタイポ（`pracice`）。
- 根本原因（思考・知識・確認不足のどれか）: コマンド実行後の状態確認を挟まず連続実行したこと。
- 切り分け手順（次回使える手順化）:
  - 1. `git status`で現状を固定する
  - 2. `git branch -avv`で各ブランチの指す先を確認する
  - 3. 土台コミットとの差分を比較する
  - 4. 正しいブランチ名で作り直して再確認する
- 再発防止ルール（チェック項目にする）: `switch -c`実行後は必ず1回`git status`を入れて、名前と現在地を確認する。
