## 3. 実装の要点（理解を深める）

```ts
const uniqueRoom = createUniqueRoom();

const createPatientResponse = await agent.post("/api/patients").send({
  name: "テスト患者",
  room: uniqueRoom,
});
expect(createPatientResponse.status).toBe(201);

const otherUniqueRoom = createUniqueRoom();
const createOtherPatientResponse = await otherAgent
  .post("/api/patients")
  .send({
    name: "他ユーザーの患者",
    room: otherUniqueRoom,
  });
expect(createOtherPatientResponse.status).toBe(201);

const getDataResponse = await agent.get("/api/data");
expect(getDataResponse.status).toBe(200);

const patientIds = getDataResponse.body.patients.map(
  (patient: { id: string }) => patient.id,
);
expect(patientIds).toContain(createPatientResponse.body.id);
expect(patientIds).not.toContain(createOtherPatientResponse.body.id);

const getOtherDataResponse = await otherAgent.get("/api/data");
expect(getOtherDataResponse.status).toBe(200);

const otherPatientIds = getOtherDataResponse.body.patients.map(
  (patient: { id: string }) => patient.id,
);
expect(otherPatientIds).toContain(createOtherPatientResponse.body.id);
expect(otherPatientIds).not.toContain(createPatientResponse.body.id);
```

- このコードの責務（1文）：A/Bが `GET /api/data` で自分の患者だけ取得することを確認する。
- 入力：A/Bそれぞれの認証Cookieと、各ユーザーの患者データ。
- 出力：各ユーザーに対応する患者・記録を含むAPIレスポンス。
- 副作用：テスト用DBに患者を作成する。
- 型をどう絞り込んだか：`map` の引数に `{ id: string }` を指定して患者IDを取り出す。
- null / undefined をどう安全に扱ったか：このコードでは特別な対応なし。
- 型で守れていること：`map` 内で患者に文字列の `id` がある前提を型で表している。レスポンス全体の型検証は未対応。
- 似た書き方との違い：`toContain` は含まれること、`not.toContain` は含まれないことを確認する。
- 修正ポイント：A/B別に患者を作成し、A/Bそれぞれから `/api/data` を呼ぶようにした。
- その修正で理解したこと：別のAPIの認可テストでは、`GET /api/data` のレスポンス分離を確認したことにはならない。
- 改善余地：看護記録の作成と分離確認を追加する。現在のテスト名には「看護記録」とあるが、記録はまだ検証していない。

## 5. つまずきから学ぶ（再発防止まで）

- つまずいた現象：`GET /api/data` テストを書いている途中で、`GET /api/patients` を呼んでいた。
- 直接原因：似た目的の患者APIテストをコピーし、URLとagentの違いを見落とした。
- 根本原因：テスト名・呼び出すAPI・使うユーザーの対応を整理する前にコードを書いた。
- 切り分け手順（次回使える手順化）：
  - 1. テスト名が対象にしているAPIを確認する。
  - 2. `.get(...)` や `.post(...)` のURLを確認する。
  - 3. どのユーザーのagentで呼び出しているか確認する。
  - 4. 期待するデータが含まれる／含まれないことを確認する。
- 再発防止ルール：テスト名・HTTPメソッドとURL・agent・アサーションが同じ目的を向いているか、実行前に確認する。
