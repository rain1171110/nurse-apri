## 3. 実装・技術の要点

- 重要なコードまたはコマンド：

````bash
git status
git commit -m "screenshots/patient-list.pngの変更"
git push
git push origin main
````

- 責務・目的：
- `git status`：変更・ステージ済みのファイルやブランチの状態を確認する。
- `git commit`：ステージした変更をローカルのGit履歴に記録する。
- `git push`：ローカルのコミットをGitHubへ送る。
- 入力：作業中のファイル変更、ステージ済みの変更、push先のブランチ
- 出力：Gitの状態表示、コミット記録、GitHubへの送信結果
- 副作用：コミットでローカル履歴が増え、pushでGitHub上のブランチが更新される。
- 型の絞り込み（該当する場合）：該当なし
- null／undefinedの扱い（該当する場合）：該当なし
- 型で守れていること：該当なし
- 似た書き方との違い：`add`はコミット対象として変更を選ぶ操作、`commit`は選んだ変更を履歴に記録する操作、`push`はその履歴をGitHubへ送る操作。
- 今日理解したこと：`git status`で変更ファイルを確認できる。変更を選ぶのが`add`、履歴に記録するのが`commit`、GitHubへ送るのが`push`。
- 改善余地：push後の最終的な`git status`は会話内で確認していない。
