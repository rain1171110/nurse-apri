- 責務・目的：患者作成リクエストの認証、入力検証、DB保存、エラー応答
- 入力：
  - テストの `.set("Origin", "http://localhost:5173")` が設定するOriginヘッダー
  - `.send({...})` が送信するJSON本文
  - 認証済みの `agent` が保持して送るCookie（そのテスト設定を前提として学習）
- 出力：認証失敗401、Zod検証失敗400、重複409、予期しないサーバーエラー500、作成成功201
- 副作用：成功時にPrisma経由で患者データを保存する。テストを実行していないため、実際のDB保存は確認していない
- 型の絞り込み：`result.success` の確認後は、成功分岐で `result.data` を使える
- null／undefinedの扱い：今日の主題ではない
- 型で守れていること：`app.post<{}, {}, CreatePatientBody>` の3つ目の型で、`req.body` をコンパイル時に `CreatePatientBody` として扱える。実際のHTTP本文がその型どおりであることまでは保証しない
- 似た書き方との違い：`CreatePatientBody` はコンパイル時の型指定、`safeParse(req.body)` は実行時に届いた本文を検証する処理
- 今日理解したこと：
  - Originは送信元サイトを示すヘッダー。ルートコードにはOrigin確認が含まれておらず、前段のミドルウェアで扱われると整理した
  - 許可されないOriginは403で拒否され、後続処理に進まない。許可されたOriginは後続の処理へ進む
  - CookieはJSON本文とは別に送信され、`cookie-parser` が `req.cookies` に読み込む。認証処理がJWTを検証して `req.userId` を設定する
  - `.send({...})` のJSON本文は `express.json()` によって `req.body` として扱われる
  - `requireAuth` の後、`req.userId` がなければ401を返す
  - `createPatientSchema.safeParse(req.body)` が本文を実行時に検証する。不正なら400を返して終了する
  - 検証に成功した場合、Prismaには未検証の `req.body` ではなく `result.data` を渡す
  - `data: { ...result.data, userId }` では後に指定した `userId` が優先される。保存する所有者IDは認証済みユーザーのIDになる
  - 部屋番号の一意制約違反（Prismaの `P2002`）は409、それ以外の予期しないエラーは500
  - 成功ケースは有効な本文を送り、201を確認する。失敗ケースは `name: ""` と `room: 0` を送り、400とエラーメッセージを確認する
  - 正常な処理の順は、Origin確認 → 認証 → Zod検証 → Prisma保存。JSON本文自体の解析は通常、ルート処理より前の `express.json()` が行う

```ts
// Zod検証の失敗ケース
const response = await agent
  .post("/api/patients")
  .set("Origin", "http://localhost:5173")
  .send({
    name: "",
    room: 0,
  });

expect(response.status).toBe(400);
expect(response.body.error).toBe(
  "Invalid patient data / 無効な患者データ",
);
```

```ts
// 作成成功ケース
const uniqueRoom = createUniqueRoom();

const createPatientResponse = await agent
  .post("/api/patients")
  .set("Origin", "http://localhost:5173")
  .send({
    name: "テスト患者",
    room: uniqueRoom,
  });

expect(createPatientResponse.status).toBe(201);
```

- 改善余地：テスト内の `agent` がログインしてCookieを保持する設定、Originを確認するミドルウェアの実装位置は、次回プロジェクトのコードで確認する。認証失敗・Origin拒否などのテスト実行や新規作成は、必要性を確認してから判断する
