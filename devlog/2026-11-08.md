## 2. 技術判断ログ

- 解決したかった課題：日付だけでは同日の記録をグラフ上で区別できず、複数のバイタル項目は単位と値の範囲が異なる。
- 検討した選択肢：
  - 案A：日付だけをX座標にし、同日記録は同じ位置に置く。
  - 案B：日付と時刻を含む数値をX座標にする。
- 採用した案：日時を数値化してX座標に使い、目盛り表示は月/日のみとする。
- 採用理由（性能／保守性／実装コスト／安全性など）：記録時刻の違いをX位置に反映しつつ、画面上のX軸ラベルは簡潔にできる。
- 採用しなかった案と理由：日付だけを使う方法は、同じ日の異なる時刻の記録を横方向に区別できない。
- 血圧の軸について：SBPとDBPはどちらもmmHgなので、追加時は同じ血圧用Y軸を共有する方針を確認した。まだ実装していない。

## 3. 実装・技術の要点

- 重要なコードまたはコマンド：

```tsx
const GraphData = patientRecordsWith.map((r) => ({
  recordKey: r.id,
  xDate: Date.parse(`${r.date}T${r.time || "00:00"}:00Z`),
  date: r.date,
  label: `${r.date} ${r.time || "時刻未記録"}`,
  temperature: r.vitals?.T,
  pulse: r.vitals?.P,
  respiration: r.vitals?.R,
  saturation: r.vitals?.SPO2,
}));
```

```bash
git diff -- src/PatientVitals.tsx
```

- 責務・目的：
  - `GraphData`は看護記録からグラフで使う日時・ラベル・バイタル値を取り出す。
  - `xDate`はX座標、`label`はTooltipに表示する文字列として使う。
  - `git diff -- src/PatientVitals.tsx`は対象ファイルの未ステージ差分を表示する。
- 入力：`patientRecords`内の記録。日付、時刻、`vitals.T`、`vitals.P`、`vitals.R`、`vitals.SPO2`など。
- 出力：表の行と、X座標・Y値を持つRecharts用データ。
- 副作用：`[...patientRecords]`でコピーしてからソートするため、元の配列を直接並べ替えない。
- 型の絞り込み（該当する場合）：`patientRecordsWith`では体温・脈拍・呼吸のいずれかがある記録を絞っている。
- null／undefinedの扱い（該当する場合）：`r.time || "00:00"`は時刻がない場合、グラフ内部の位置計算に00:00を使う。表示用`label`は「時刻未記録」のままにする。SPO2のみ、または今後の血圧のみ記録された行を含めるには、絞り込み条件にもSPO2・SBP・DBPを追加する必要がある。
- 型で守れていること：`vitals`がない場合はオプショナルチェーンで値を取り出す。
- 似た書き方との違い：`Date.parse(r.date)`は日付だけを数値化する。日時を組み合わせた`xDate`は、同日内の時刻差もX座標に反映する。
- 今日理解したこと：
  - `label`はTooltip表示、`xDate`はグラフ上の横位置に使われる。
  - `<XAxis dataKey="xDate" type="number" scale="time">`は数値の日時を時間軸として扱う。
  - `tickFormatter`は日時の数値を月/日の文字列に変換し、`getUTCMonth()`は0始まりなので月に1を足す。
  - `YAxis`の`yAxisId`と`Line`の`yAxisId`を一致させると、線を対応するY軸に割り当てられる。
  - `tick={{ fontSize: 10 }}`で目盛りラベルの文字サイズを指定できる。
  - `type="linear"`で記録点を直線でつなげる。
- 改善余地：
  - 時刻未記録のデータは内部座標では日付の00:00に置かれるため、表示位置の扱いを確認する。
  - 同じ日時の記録が複数ある場合、Tooltipで記録IDを識別できるようにする。
  - 画面幅が狭い場合の複数Y軸・目盛りラベルの重なりを確認する。
  - SBP・DBP・SPO2のみの記録もグラフ用配列に含めるよう、絞り込み条件を更新する。

## 5. 質問・つまずきと再発防止

- 質問したこと：
  - 日付・時刻順でない表と、グラフ上で同日に重なる点の原因。
  - `label`と`xDate`の役割。
  - グラフが曲線になる理由。
  - Y軸の目盛りラベルの文字サイズと、複数軸を配置したときの重なり。
  - 血圧を追加すると軸が足りなくならないか。
- つまずいた現象：
  - ソート処理があっても表の順序が変わらない状態があった。
  - 日付だけをX座標にしていたため、同じ日の点が重なった。
  - SPO2軸を追加した後、呼吸用の目盛りラベルが見えなくなった。
- 直接原因：
  - 表の描画にソート済み配列を使う必要がある。
  - 同日の記録に同じ日付だけのX座標を割り当てていた。
  - 左側に複数のY軸を置いてラベルが重なった。
- 根本原因（知識／確認／考え方など）：データの並べ替え、X座標、Tooltip表示、Y軸の配置がそれぞれ別の設定であることを段階的に確認する必要があった。
- 最終的に理解したこと：配列をソートしただけでは表示先は変わらず、表・グラフがその配列を参照する必要がある。X座標に使う値とTooltipに表示する文字列も別々に用意する。
- 次回の切り分け手順：
  1. 何が起きたかを言葉にする
  2. 関係する値・設定・ファイルを確認する
  3. 原因候補を絞る
  4. 修正または対応後に確認する
- 再発防止ルール：データのプロパティ名、`dataKey`、`yAxisId`を照合してから、表示を確認する。
