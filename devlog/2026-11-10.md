## 3. 実装・技術の要点

- 重要なコードまたはコマンド：

```tsx
const getRecordsAtXDate = (xDate: number) => {
  return GraphData.filter((r) => r.xDate === xDate);
};
```

- 責務・目的：引数の`xDate`と一致する`GraphData`の記録をすべて返す。
- 入力：基準となる`xDate`（数値）
- 出力：`xDate`が一致する記録オブジェクトの配列。該当がなければ空配列。
- 副作用：なし。元の`GraphData`は変更しない。
- 型の絞り込み（該当する場合）：`filter`の条件は`r.xDate === xDate`。厳密等価で一致した行だけが返る。
- null／undefinedの扱い（該当する場合）：Tooltipの`active`や`payload`がない場合は`null`を返して表示を止める。`payload?.[0]?.payload`で安全に参照し、`activePoint`がない場合も止める。
- 型で守れていること：関数の引数が`number`であること。
- 似た書き方との違い：`find`は最初に一致した1件を返すが、`filter`は一致する全件を配列で返す。
- 今日理解したこと：
  - `<LineChart data={GraphData}>`が記録ごとのオブジェクトをRechartsへ渡す。
  - Tooltipの`payload[0].payload`から、アクティブなデータに対応する元の`GraphData`オブジェクトを参照できる。
  - `activePoint.xDate`は検索対象そのものではなく、`GraphData`を絞り込む基準値として使う。
  - 同じ日時は同じ`xDate`になるので、`filter`で複数件を取得できる。
  - `itemSorter`は標準Tooltipの表示順を変える設定。`content`で独自に描画する場合、そのJSX内で表示順を作る必要がある。
  - 時刻未記録は現在`"00:00"`として`xDate`を作るため、同日の実際の00:00の記録と同じ値になる可能性がある。
- 改善余地：独自Tooltipに体温・脈拍・血圧・呼吸・SpO₂を元の順で表示し、同じ`xDate`の複数記録を識別できるか確認する。

## 5. 質問・つまずきと再発防止

- 質問したこと：
  - 狭い画面幅でY軸ラベルやTooltipが見切れるか。
  - 同じ日時の記録をTooltipでどう見分けるか。
  - `label`、`recordKey`、`payload?.[0]?.payload`、`slice(0, 8)`の意味。
  - `getRecordsAtXDate(activePoint.xDate)`でなぜ同じ日時の記録をすべて探せるのか。
- つまずいた現象：同じ日時の記録をクリックしても、最初に登録した記録しかTooltipで判定されなかった。
- 直接原因：同じ日時の記録は`xDate`が一致してグラフ上で重なり、Tooltipがアクティブな1件を基に表示していた。
- 根本原因（知識／確認／考え方など）：Tooltipの見出し整形、系列の並び順、同一座標にある複数レコードの列挙が別の処理であると整理できていなかった。
- 最終的に理解したこと：`GraphData`の各行に`label`と`recordKey`が含まれ、Tooltipのpayloadから行を参照できる。`filter`は`xDate`が一致するすべての行を返す。
- 次回の切り分け手順：
  1. 何が起きたかを言葉にする
  2. 関係する値・設定・ファイルを確認する
  3. 原因候補を絞る
  4. 修正または対応後に確認する
- 再発防止ルール：Tooltipの`labelFormatter`は見出しを整形し、`itemSorter`は系列値を並べ替える。複数記録をまとめて表示するには独自`content`で描画する。
