### App.tsxで確認したこと

- 重要なコードまたはコマンド：

患者情報と看護記録をまとめてstateに保持している。

```tsx
const [appData, setAppData] = useState<AppData>({
  patients: [],
  records: [],
});
```

APIで患者の保存に成功した後、返された患者を画面側の配列へ追加している。

```tsx
const savedPatient = await createPatientApi(patient);

setAppData((prev) => ({
  ...prev,
  patients: [...prev.patients, savedPatient],
}));
```

読み込み中・ログイン済み・未ログインで表示先を分けている。

```tsx
loading ? (
  <div>読み込み中…</div>
) : isLoggedIn ? (
  <Outlet />
) : (
  <Navigate to="/login" replace />
)
```

- 責務・目的：
  - アプリ全体で使用する患者情報・看護記録を管理する。
  - 起動時とログイン成功時にAPIからデータを読み込む。
  - 患者・看護記録の追加、更新、削除をAPIへ依頼し、成功後にstateへ反映する。
  - ログイン状態に応じて画面を切り替える。
  - APIエラーをSnackbarとAlertで表示する。
  - 開発時のみ入力検証エラーを表示する。

- 入力：
  - APIから取得した患者情報・看護記録。
  - 各画面から渡される追加・更新・削除の対象データ。
  - 現在のURLとログイン状態。

- 出力：
  - 患者一覧、患者詳細、バイタル、看護記録などの画面。
  - 子コンポーネントへ渡すデータと操作用関数。
  - APIエラーの通知。

- 副作用：
  - APIとの通信。
  - Reactのstate更新。
  - エラーのコンソール出力。
  - 開発用エラー表示を消すタイマーの設定・解除。

- 型の絞り込み（該当する場合）：
  - `error instanceof Error`で、エラーがErrorオブジェクトか確認してから`message`を参照する。
  - `Array.isArray`で、取得したpatientsとrecordsが配列か確認している。

- null／undefinedの扱い（該当する場合）：
  - タイマーの参照は、初期値を`null`にしている。
  - 患者・看護記録の追加や更新は、失敗時に`undefined`を返す。
  - 削除は、成功時に`true`、失敗時に`false`を返す。

- 型で守れていること：
  - `AppData`で保持するデータの形を指定している。
  - `Omit<Patient, "id">`により、患者追加関数の入力型からidを除いている。
  - `Promise<Patient | undefined>`などで、非同期処理の成功時と失敗時の戻り値を表現している。
  - 型チェック自体は今日実行していない。

- 似た書き方との違い：
  - 追加では配列の展開構文、更新では`map`、削除では`filter`を使って、新しい配列を作成している。
  - `setAppData((prev) => ...)`では、更新前のstateを受け取り、その内容を基に次のstateを作成している。

  - 患者削除時には、画面側のstateから該当患者の看護記録も除いている。
  - 未ログインの場合は、保護対象の画面からログイン画面へ移動する。
  - ログアウト成功後はログイン状態を解除し、患者・看護記録を空にする。
