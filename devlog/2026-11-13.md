### Tooltip内で空白項目を非表示化
- 修正箇所：`PatientVitals.tsx` 行104～119
- 起きていた症状：値がない項目（体温のみの記録でも脈拍・呼吸・SPO2枠が表示される）
- 原因：条件なしですべての項目を表示していた
- どう修正したか：各項目を `{value &&}` で条件付きレンダリング

  ```jsx
  {r.temperature && <div>体温: {formatValue(r.temperature, "℃")}</div>}
  ```
- 修正後の変化：値がある項目だけ表示されるようになった
- なぜ直ったのか：`&&` 演算子で、値がないときは後ろの要素がレンダリングされない
- 次に同じ問題が起きたときの確認手順：各項目の条件式を確認

## 3. 技術的な判断

### 同じ時刻に複数の記録がある場合の表示方法

- 解決したかった課題：「2026-11-13 10:30 に記録A と記録B がある場合、どちらをクリックしても記録A だけ表示される」
- 検討した案：
  - **案A**：クリック時に複数の記録をリスト表示
  - **案B**：系列ごとにTooltipを分ける（体温をクリック→その記録の体温のみ）
  - **案C**：グラフは全体推移だけで、詳細はテーブル表示（現在のテーブルで複数行表示）

- 選んだ案と理由：**案C（グラフは全体推移のみ）**
  - 理由：Rechartsの設計上、同じxDateに複数の記録があるとき、クリック時の判定ができない。グラフは推移を見るだけに割り切った方が、シンプルで使いやすい
  
- 選ばなかった案と理由：
  - 案A：複雑になる割に、UIがわかりにくくなる
  - 案B：Rechartsの仕組みで実装不可。`payload` は「同じ座標のすべての線のデータ」を返すため、どの記録の線をクリックしたか区別できない

## 4. コードと理解したこと

### Rechartsの `payload` 構造
```javascript
// クリック時の payload の構造
payload = [
  {
    stroke: 'red',
    dataKey: 'temperature',
    name: '体温',
    payload: {
      recordKey: 'a4b40ca0-...',  // 記録ID
      xDate: 1794026400000,       // グラフの時刻
      temperature: 38,
      pulse: 50,
      // ...
    }
  },
  { ... }, // 他の5つのLine（脈拍、呼吸、SPO2、SBP、DBP）
]
```

- このコードの役割：Recharts の Tooltip がクリックされたときに渡されるデータ構造
- 入力と出力：
  - 入力：グラフ上のクリック座標
  - 出力：その座標に対応するすべての Line のデータ（6つ）
- 重要な処理の流れ：
  1. `payload[0].payload.xDate` で座標の時刻を取得
  2. `getRecordsAtXDate(xDate)` で、その時刻のすべての記録を取得
  3. 複数の記録がある場合、すべてが `records` 配列に入る
  4. しかし、`payload` には常に最初の記録のデータだけが入っているので、区別できない
- 理解したこと：
  - `payload` は6要素の配列（グラフの6つのLine分）
  - 各要素の `payload.recordKey` は**同じ時刻のすべての記録で同じ値**
  - つまり、「どの記録の線をクリックしたか」の判定はRechartsでは不可能
- 次に確認したいこと：Rechartsのカスタマイズオプション（onClick コールバックなど）

## 6. つまずきと学び

### 複数記録の判定ができない問題
- つまずいたこと：「同じ時刻に2つの記録がある場合、2番目の記録の線をクリックしても1番目の記録だけ表示される」
- 原因：Rechartsの設計。`payload` は同じxDateに複数の記録があっても、最初の記録のデータだけを含む
- どう切り分けたか：
  1. コンソールで `payload.length` を確認 → 6要素（Line数）
  2. `payload.map(p => p.payload.recordKey)` で recordKey を確認 → すべて同じ値
  3. `records` 配列の長さを確認 → 2個（記録数）
  4. だが `filtered` 結果は1個 → 実は1つの記録しか取得できていない
- 次回試すこと：Recharts の onClick コールバックを使う（Tooltip ではなく）
- 再発防止のための確認項目：ライブラリのドキュメントを最初に確認
- 次回も使える考え方：コンソールでデータ構造を小分けにして確認する（「全体 → 要素1つ → 配列の内容」の順）

### Tooltip は仕様上の限界がある
- 学び：UI/UX を決めるときに「ライブラリの仕組み」も考慮する必要がある
- この場合、グラフの目的が「全体推移の把握」なら、詳細はテーブルに任せた方がシンプル
