### 解説メモ（会話からそのまま転記）

#### 質問・テーマ

#### 解説（原文のまま）

別のAIからの解説：
```
クッキーはユーザー固有 ← ユーザーAのブラウザに保存されるのは、ユーザーAのトークン
トークンにはユーザーIDが入っている ← 偽造しない限り、本人のIDしか取出されない
DB検索時に where: { userId } で制限 ← そのユーザーのID条件に合うデータだけを返す
```

**実装コード確認結果：**

1. **ログイン時のトークン発行（server/index.ts）**
```typescript
app.post("/api/auth/login", async (req, res) => {
  // ... メール・パスワード検証 ...
  
  const token = jwt.sign({ userId: user.id }, JWT_SECRET, {
    expiresIn: "1h",
  });
  
  res.cookie("token", token, {
    httpOnly: true,
    secure: process.env.NODE_ENV === "production",
    sameSite: process.env.NODE_ENV === "production" ? "none" : "strict",
  });
  
  res.json({
    success: true,
    message: "ログイン成功",
    user: { id: user.id, email: user.email },
  });
});
```

2. **データ取得時のリクエスト（src/api/appDataApi.ts）**
```typescript
export const fetchAppData = async (): Promise<AppData> => {
  const response = await fetch(`${API_BASE}/data`, { 
    credentials: "include"
  });
  if (!response.ok) {
    throw new Error(`API error:${response.status}`);
  }
  const data: AppData = await response.json();
  return data;
};
```

3. **サーバー側の認証チェック（server/auth.ts）**
```typescript
export const requireAuth = (
  req: Request,
  res: Response,
  next: NextFunction,
) => {
  try {
    const token = req.cookies.token;
    if (!token) {
      res.status(401).json({
        error: "Authentication required / 認証が必要です",
      });
      return;
    }
    const decoded = jwt.verify(token, JWT_SECRET);
    if (typeof decoded === "string" || typeof decoded.userId !== "string") {
      res.status(401).json({
        error: "Invalid token payload / トークン内容が無効です",
      });
      return;
    }
    const userId = decoded.userId;
    req.userId = userId
    next();
  } catch (error) {
    res.status(401).json({
      error: "Invalid or expired token / トークンが無効または期限切れです",
    });
    return;
  }
};
```

4. **cookieParser ミドルウェア（server/index.ts）**
```typescript
app.use(cookieParser());
```

### 自分の理解

#### このコードの役割
- ユーザーがログインしたときに、トークンをブラウザに送って保存させること
- その後のリクエストで、ブラウザが自動的にそのトークンをつけて送信させること
- サーバーがトークンを検証して、ユーザーIDを確認すること
- そのユーザーIDで、そのユーザーの患者データだけをフィルタして返すこと

#### 入力と出力
- 入力：メール、パスワード
- 出力：ブラウザに保存されるトークン、その後の患者データ

#### 重要な処理の流れ

**Step 1：ログイン時**
```
ブラウザ（ユーザーAがメール・パスワード入力）
    ↓
サーバーの /api/auth/login へ POST
    ↓
サーバーが jwt.sign() でトークン生成（userId を含める）
    ↓
res.cookie() で「トークンを保存しろ」と指示
    ↓
ブラウザが自動でトークンを自分のメモリに保存
```

**Step 2：データ取得時**
```
ブラウザの fetchAppData() で /api/data へリクエスト
    ↓
credentials: "include" があるので、保存してあるトークンを自動で付加
    ↓
サーバーが「Cookie: token=xxx」というヘッダーで受け取る
    ↓
cookieParser() が Cookie ヘッダーを解析
    ↓
req.cookies.token でアクセス可能になる
    ↓
requireAuth で jwt.verify() でトークン検証
    ↓
userId を取出して req.userId に設定
    ↓
その後のエンドポイント（/api/data）で req.userId を使う
    ↓
that userId で where を絞る
    ↓
そのユーザーのデータだけ取得して返す
```

#### 理解したこと

**今日、確実に理解できたこと：**

1. **クッキーはブラウザに保存される**
   - ❌ 間違い：サーバーにも保存される
   - ✅ 正解：ブラウザのメモリに保存される（サーバーは保存しない）
   - 理由：`res.cookie()` はブラウザへの指示書であって、サーバーは一度渡したら終わり

2. **credentials: "include" の意味**
   - ブラウザに対して「このリクエストを送るときに、保存してあるクッキーをつけろ」という指示
   - つけ方：HTTPリクエストヘッダーの `Cookie:` という行に、トークンを追加する
   - 具体例：
     ```
     GET /api/data HTTP/1.1
     Host: localhost:3001
     Cookie: token=eyJhbGc...
     ```

3. **cookieParser() ミドルウェアの役割**
   - リクエストが来たときに、ヘッダーの `Cookie: token=xxx` を解析して、JavaScript のオブジェクトに変換する
   - 処理：
     ```
     リクエスト → Cookie ヘッダー（文字列） 
              ↓ (cookieParser が解析)
            req.cookies オブジェクト
              ↓
            req.cookies.token でアクセス可能
     ```

4. **jwt.verify() の検証**
   - JWT_SECRET キーを使ってトークンが本物か確認
   - 偽造されてたら、catch で例外が発生して 401 エラー
   - 本物なら、tokenDecode.userId でユーザーIDを取出

5. **複数層の安全装置**
   - クッキー自体が該当ドメイン限定
   - トークン署名で偽造検知
   - DB検索時に where: { userId } で制限
   - 更新・削除時に id + userId 両方で確認

## 6. つまずきと学び

#### つまずいたこと
1. **クッキーの保存場所について混乱**
   - 最初の理解：サーバーにも保存される
   - 正しい理解：ブラウザのメモリにだけ保存される

2. **credentials: "include" の仕組みが曖昧**
   - 「どうやってクッキーが送信されるのか」という具体的なメカニズムが理解できていなかった
   - HTTPリクエストヘッダーの `Cookie:` 行という形式を知らなかった

3. **往復回数の理解**
   - 最初：「1往復」と答えた
   - 実際：「1往復でトークン受信 + 以降全てのリクエストにトークンが付く」

- クッキーやHTTPリクエストの仕組みを、実装コードで見たことがなかった
- 別のAIからの高度な説明を、基礎知識なしで受け取ろうとしていた
- ネットワーク通信の詳細（リクエストヘッダーなど）をイメージできていなかった

3. 身近な例え（図書館の会員カード）を使ってイメージする
