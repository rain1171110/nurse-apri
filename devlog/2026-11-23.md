## 2. セキュリティ復習まとめ（A～E）

### 【全体像：セキュリティの3層防御 + レート制限】

```
【第1層：UI層】
患者一覧には、ログインユーザーの患者だけ表示

【第2層：API層（複合条件）】
where: { id, userId } 両方チェック
→ 他のユーザーのデータは 404

【第3層：認証層（トークン検証）】
クッキーなし → トークンなし → エラー 401

【第4層：レート制限（ブルートフォース攻撃防止）】
15分に5回まで
6回目は Status 429 エラー
```

### 【A. トークンが別物】

全ユーザーのトークンが違う理由：各トークンに「誰のトークンか」が入っているから

```
ユーザーA のトークン ≠ ユーザーB のトークン
  ↑ 中に userId が入ってる
```

### 【B. req.userId の流れ】

トークン → jwt.verify() → userId 抽出 → req に追加 → DELETE で使用

```
ミドルウェアが req という箱に userId を詰める
  ↓
ルートが req から userId を取り出して使う
```

### 【C. 複合条件による防止】

```
where: { id, userId }  ← 2つの条件を両方チェック
  ↓
「自分の患者だけ」という制限が実装される
```

### 【D. Status 401 vs 404】

```
401 = 認証がない（requireAuth で止まった）
404 = 認証はあるけどデータがない（DELETE ルートで検索失敗）
```

### 【E. レート制限】

```
15分に5回まで
  ↓
6回目は Status 429 エラー
  ↓
ブルートフォース攻撃を防止
```

## 3. バイタルグラフの仕組み学習

### 【全体の流れ】

```
【第1段階：データを取得】
patient と patientRecords を router から受け取る

【第2段階：グラフ用にデータを加工】
日付順にソート
体温・脈拍・呼吸などのデータを抽出
グラフで表示できる形に変換

【第3段階：グラフを描画】
recharts ライブラリの LineChart を使用
5本の折れ線グラフを表示

【第4段階：ユーザーが操作】
グラフをクリック → Tooltip（詳細情報）が表示
テーブルでも記録を表示
```

### 【PatientPage でのデータ処理】

**ファイル：src/PatientPage.tsx**

```typescript
// 患者を探す
const patient = patients.find((p) => String(p.id) === id);

// その患者の記録を探す
const patientRecords = records.filter((r) => String(r.patientId) === id);

// context オブジェクトを作る
const outletContext: PatientOutletContext = {
  patient,
  patientRecords,  ← ここでグラフに必要なデータが入る
  updatePatient,
  addRecord,
  updateRecord,
  deleteRecord,
  deletePatient,
  usedRoomsForEdit,
};

// 子コンポーネントに渡す
return <Outlet context={outletContext} />;
```

**データの流れ：**

```
App.tsx か main.tsx
  ↓
全患者データ patients、全記録データ records
  ↓
<PatientPage patients={patients} records={records} />
  ↓
URL から患者ID を取得
  ↓
「この患者と、この患者の記録」を抽出
  ↓
context オブジェクトに詰める
  ↓
<Outlet context={outletContext} />
  ↓
子コンポーネント（PatientVitals など）が受け取る
  ↓
const { patient, patientRecords } = useOutletContext()
```

### 【Outlet と context とは】

```
【Outlet】
React Router の機能
親コンポーネント（PatientPage）が
子コンポーネント（PatientMenu, PatientDetail, PatientVitals）を表示する場所

【context】
親から子へ「データを渡す仕組み」
props ではなく context で渡すことで「途中のコンポーネント」を経由しない

【図解】
PatientPage（親）
  ↓ <Outlet context={outletContext} />
  ├→ PatientMenu（子1） ← useOutletContext で受け取る
  ├→ PatientDetail（子2） ← useOutletContext で受け取る
  └→ PatientVitals（子3） ← useOutletContext で受け取る
     └→ const { patient, patientRecords } = useOutletContext()
```

### 【患者データの中身】

```typescript
patient = {
  id: "p123",
  room: 101,
  name: "田中太郎",
  ...
}
```

### 【記録データの中身】

## 4. 重要な理解ポイント

### 「Outlet と context」の新しい概念

```
【従来の props で渡す方法】
App
  ↓ patients={patients}
PatientPage
  ↓ patients={patients}
PatientMenu
  ↓ 患者データが使える

【Outlet と context で渡す方法】
App
  ↓ patients={patients}
PatientPage
  ↓ <Outlet context={{patients, ...}} />
  ├→ PatientMenu ← context から直接受け取る
  ├→ PatientDetail ← context から直接受け取る
  └→ PatientVitals ← context から直接受け取る
```

**利点：**
```
props だと「中間のコンポーネント」も prop を通す必要がある
context だと「必要なコンポーネント」だけ受け取れる
  ↓
「Prop Drilling」（prop の通し回し）を減らせる
```

### PatientPage での重要な処理

```
【患者を検索】
const patient = patients.find((p) => String(p.id) === id);
  ↓
「全患者の中から、この ID の患者を探す」

【患者の記録を検索】
const patientRecords = records.filter((r) => String(r.patientId) === id);
  ↓
「全記録の中から、この患者の記録だけ抽出」
```

**つまり、PatientPage は「患者と記録をフィルタリングして、子に渡す」という役割** ✅

## 6. つまずきと学び

### つまずいたこと

1. **「PatientPage に vitals が出てこない」という疑問**
   - vitals は PatientVitals.tsx の中で使われている
   - PatientPage には vitals そのものは出てこない
   - でも patient と patientRecords（vitals を含む）は PatientPage で処理されていた

### 原因

- PatientPage でデータをどう処理しているか、見ていなかった
- Outlet と context の関係が不明確だった

### どう解決したか

1. **実コードを見た**
   - PatientPage.tsx を確認
   - `patient` と `patientRecords` がフィルタリングされていることに気付いた

2. **データの流れを図で理解**
   - App.tsx → PatientPage → Outlet → PatientVitals
   - PatientPage で「患者と記録を抽出」→ Outlet で「context に詰める」→ PatientVitals で「受け取る」

3. **Outlet と context の役割を分離**
   - Outlet = 「子コンポーネントを表示する場所」
   - context = 「親から子へデータを渡す仕組み」

### 再発防止のための確認項目

- 「このコンポーネントにデータが出ていないのに、他のコンポーネントで使われている」という場合は、「親コンポーネント」を確認する
- React Router の Outlet は「親が子を表示する場所」という理解
- context は「props ではなく別の方法でデータを渡す」という理解
