### 【4-2】データに patientId を追加

```typescript
const recordToAdd: Omit<NursingRecord, "id"> = {
  ...record,
  patientId,
};
```

**Before（record）：**
```typescript
{
  date: "2026-11-26",
  time: "08:30",
  author: "看護師 A",
  vitals: { T: 36.5, P: 72, ... },
  content: "患者さんは安定している"
}
```

**After（recordToAdd）：**
```typescript
{
  date: "2026-11-26",
  time: "08:30",
  author: "看護師 A",
  patientId: "patient123",  // ← 追加される
  vitals: { T: 36.5, P: 72, ... },
  content: "患者さんは安定している"
}
```

**重要：`Omit<NursingRecord, "id">`**

```
NursingRecord = { id, date, time, author, ... }
Omit<NursingRecord, "id"> = { date, time, author, ... }  ← id を除く
```

**なぜ id を除くのか？**
- 新規作成だから id はまだ存在しない
- バックエンド（データベース）が自動的に id を生成する

### 【4-3】try-catch で API 通信

```typescript
try {
  setApiError("");  // ← 【重要】前のエラーをクリア
  const savedRecord = await createRecordApi(recordToAdd);
  
  setAppData((prev) => ({
    ...prev,
    records: [...prev.records, savedRecord],
  }));
  
  return savedRecord;  // ✅ 成功時
  
} catch (error) {
  console.error("看護記録追加に失敗しました", error);
  setApiError(getErrorMessage(error, "看護記録追加に失敗しました"));
  return undefined;  // ❌ 失敗時
}
```

---

### 【4-4】setApiError("");の役割

**ユーザーの操作：**

```
【1回目】API がエラー
  ↓
画面に「失敗しました」と表示

【2回目】もう一度試す
  ↓
setApiError("") で前のエラーをクリア  ← 重要！
  ↓
API 通信を新しく開始
```

**もし setApiError("") がなかったら：**

```
成功した新しい記録が表示される
でも、前のエラーメッセージ「失敗しました」もまだ表示されている
  ↓
「あれ？成功したのに、エラーメッセージが表示されてる？」 😕
```

**「古いエラーが混ざらないようにする」という親切な設計**

---

### 【4-5】setAppData で React の state を更新

```typescript
setAppData((prev) => ({
  ...prev,
  records: [...prev.records, savedRecord],
}));
```

**処理の流れ：**

```
prev = { patients: [...], records: [記録1, 記録2, 記録3] }
  ↓
{
  ...prev,                    // { patients: [...], records: [...] } をコピー
  records: [                  // その中の records を上書き
    ...prev.records,          // [記録1, 記録2, 記録3] をコピー
    savedRecord               // 新しい記録を追加
  ],
}
  ↓
{ patients: [...], records: [記録1, 記録2, 記録3, 新しい記録] }
```

**特徴：**
- 前の patients は変わらない
- records だけに新しい記録を追加
- 古い記録はそのまま保ったまま

### 【5-2】API_BASE の確認

```typescript
const API_BASE = import.meta.env.VITE_API_BASE ?? "http://localhost:3001/api";
```

**意味：**
- 環境変数 `VITE_API_BASE` があれば、それを使う
- なければ `http://localhost:3001/api` をデフォルトとして使う

**つまり：** バックエンド API の基本 URL

---

### 【5-3】fetch で POST リクエストを送信

```typescript
const response = await fetch(`${API_BASE}/records`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(record),
  credentials: "include",
});
```

**各要素を詳しく：**

| 要素 | 意味 |
|------|------|
| `fetch(...)` | ネットワークリクエストを送る関数 |
| `` `${API_BASE}/records` `` | URL：`http://localhost:3001/api/records` |
| `method: "POST"` | HTTP メソッド。新しいデータを作成 |
| `headers: { ... }` | 「JSON 形式のデータを送ります」と宣言 |
| `body: JSON.stringify(record)` | 【送る】データを JSON 文字列に変換 |
| `credentials: "include"` | クッキーを含める（JWT 認証用） |

---

### 【5-5】レスポンスのエラーチェック

```typescript
if (!response.ok) {
  await throwApiError(response);
}
```

**response.ok とは？**

| ステータスコード | response.ok | 意味 |
|------------------|------------|------|
| 201 Created | true | ✅ 成功 |
| 200 OK | true | ✅ 成功 |
| 400 Bad Request | false | ❌ 入力値が不正 |
| 401 Unauthorized | false | ❌ 認証が必要 |
| 404 Not Found | false | ❌ リソースがない |
| 500 Internal Server Error | false | ❌ サーバーエラー |

**つまり：**
```typescript
if (!response.ok) {
  // ステータスコードが 200 番台じゃない（失敗）
  await throwApiError(response);  // エラーを投げる
}
```

---

### 【5-6】レスポンスボディを取得・パース

```typescript
const data: NursingRecord = await response.json();
return data;
```

**何が起きるか？**

```
response = {
  status: 201,
  body: JSON 形式のデータ（バイナリ）
}

await response.json()
  ↓
JSON をパース（JavaScript オブジェクトに変換）
  ↓
data = {
  id: "record456",
  date: "2026-11-26",
  ...
}

return data
  ↓
App.tsx の addRecord に返す
```


## 🔄 JSON の送受信（重要）

### 送る側（Step 5）

```typescript
body: JSON.stringify(record)
       ↓
     「record を JSON 形式に変換してサーバーへ送信」
```

**つまり：** フロント → サーバー に JSON テキストを送る

### 受け取る側（Step 5）

```typescript
const data: NursingRecord = await response.json();
                                   ↓
                            「返ってきた JSON をパースして JavaScript オブジェクトに変換」
```

**つまり：** サーバー → フロント から JSON テキストを受け取ってパースする

**ネットワーク上で流れているのは JSON（テキスト形式）**
- 送る側：JavaScript オブジェクト → JSON 文字列
- 受け取る側：JSON 文字列 → JavaScript オブジェクト
